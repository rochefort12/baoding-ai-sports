## 入口与布局

同一个 plus-ui 工程：平台用户由 C 端“我要办赛”到 `/portal/organization` 的申请/进度；服务端兑换有效组织会话后进入 `/org-desk/home`。普通平台身份直接访问组织任务先回申请页，匿名访问组织任务先到平台登录；安全任务地址在兑换组织会话后恢复。管理员 `/login` 默认 `/index`，未重画平台组织审批页面。

`BusinessFrame` 用于办赛场景；原 Layout 仅在 `/org-desk/` 且非超级管理员场景选择 B 布局。原侧栏、顶栏及平台页面保留。顶部页面标签复用 RuoYi 的 tagsView 状态与增删更新能力，呈现使用专用 B 端标签栏；赛事内部任务标签单独由路由 query 驱动，可刷新和前进/后退。组织切换通过现有服务端组织入场，不以原租户下拉或前端角色开关替代。

样式集中 `plus-ui/src/assets/styles/business.scss`，约束在 `.business-app` 或专用弹窗类。表格/表单/抽屉/上传/确认复用 Element Plus，未全局替换若依主题，未新增依赖。电脑和手机分别适配侧栏、任务滚动和表单。

## 后端新增查询

- `GET /sports/b/desk/context`：组织模块按当前管理主体、有效组织授权与会话租户核对，返回组织编号/名称及 organize/payment 状态。平台身份不能直接调用，无有效准入拒绝。
- `GET /sports/b/fees/obligations/{id}/records`：资金模块核对组织、payment 用途和会话租户，通过义务→报名→项目→赛事验证归属，再返回真实收款/分配和关联退款 DTO。冲正不删除事实，不返回数据库实体、验证码、文件材料或完整证据 JSON。

没有模型或迁移变更，沿用 PostgreSQL 的资金事实，不用 Redis 或页面声明冒充实收。服务端写操作/事务规则保持原接口，界面限制不是授权替代。

## 本轮未关闭的业务缺口

真实普通组织账号仍需逐项进行申请、发布、审核、到账、撤回/退款、报到/录分/授奖和重复操作验收，不能用模拟截图或管理员代替。

资金当前写接口按原义务核对整笔金额，退款按原待办登记整笔原款，尚不支持完整补款、分次退款金额/实际时间/接收人及受控更正；界面明确整笔退款，不提供虚假的分次结案。本轮新增查询不等于上述写能力已补齐。报名版本对比/更细的审核材料查询、目录删除及其他旧清单要求继续按既有待办核对；本轮没有以页面重排关闭 21 项功能、17 项缺口或七类普通角色验收。

真实短信、验证码验签、生产参数与运营责任仍按原清单。当前资金身份沿用既有服务端准入及 grant 机制，未新增工作人员授权管理平台。
