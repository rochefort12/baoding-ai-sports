## 2. 共用界面状态

| 状态 | 呈现与下一步 | 校验边界 |
| --- | --- | --- |
| 首次加载/刷新 | 骨架或加载提示，关键按钮等待最新状态 | 不拿上一组织/上一对象旧数据可操作 |
| 无数据 | 区分无赛事、无报名、无结果、无证明、无消息；仅给合法入口 | 查询失败不能显示为空列表 |
| 查询失败 | 说明暂未获取结果，保留必要编辑内容，允许重新加载 | 不宣称业务失败或自动创建新对象 |
| 未登录/会话失效 | 提示登录，保留安全的目标位置；重新进入后再校验 | 重置/关闭已撤销会话不继续操作 |
| 无权限/对象不可见 | 显示无法访问及可返回位置，不透露私人对象内容 | 非本组织、无本人关系或用途授权不足由服务端拒绝 |
| 操作中 | 防重复点击，显示正在处理 | 仍需服务端事务、幂等及并发保护 |
| 请求超时/结果未知 | 明确“结果待核对”，查询本次请求事实后再决定是否重试 | 不把未知写成功/失败；旧提交重试不得复活撤回记录 |
| 时间/名额已变化 | 刷新对象，显示已截止、已开赛、满额等实际原因 | 服务端北京时间及占用为准，不以浏览器时钟抢窗口 |
| 配置/确认版本冲突 | 指出变更范围，保留草稿，补填并重新确认后提交 | 不是无提示覆盖新值或套用旧确认 |
| 部分导入失败 | 行级原因、成功事实与待修正项分别反馈 | 不把部分成功写全量成功；重试不重复新增事实 |

## 3. S01 账号与档案

| 业务状态 | 主操作/反馈 | 禁止或限制 |
| --- | --- | --- |
| 未注册/未登录 | C00 公共首页可浏览，办理个人任务时进入独立 C03；C04 恢复密码 | 不展示假登录身份；无监护/孩子切换；注册不代办别人的档案 |
| 登录成功 | 无原任务到 C00；有安全原任务返回并重验；必要档案缺项再 C05 | 不统一强制建档、不自动报名/占位/确认/付款 |
| 短信待发送/已发送/过期/已用/限频 | 用途明确，提示实际发送结果及可重试条件 | 注册与重置验证码不可混用；人机校验成功不等于短信发出 |
| 重置成功 | 密码已更新，保留安全原任务回 C03 登录 | 撤销平台及关联组织会话，不保留旧会话继续办赛 |
| 档案未完善/字段错误 | C05 定位缺项；出生日期必填且不得未来 | 绑定验证手机号只读；一期不换号 |
| 档案已保存/提交快照已有 | 当前资料已更新，正式报名仍保留原提交依据 | 不倒灌旧名单/答案；不新增敏感资料历史回滚页 |
| 账号已关闭 | 拒绝登录/访问旧会话，按必要渠道处理 | 不自动撤回报名或把新同号账号当旧账号 |

## 4. S02 组织申请

| 状态 | 申请人反馈 | 平台动作/边界 |
| --- | --- | --- |
| 未申请/草稿 | C16 进入 B16，草稿允许缺项保存；正式提交需组织名称、联系人、联系方式并核对 | 不要求已有参赛档案 |
| 已提交待审 | B17 展示冻结版本、进度，直接返回 B16 仍不能编辑 | P01/P02 超级管理员审批；普通组织不可代审批 |
| 被拒绝 | B17 展示理由，B16 修改保存仍保持拒绝；再提交新增版本，旧版本只读 | 不把被拒版本覆盖为从未提交 |
| 已批准 | B17 展示组织及进入获授权 B02 工作台入口，保留历史记录 | 真实事务开户结果；certified 只是办赛准入，无逐场发布审批 |
| 审批结果未知/版本变化 | B17 先查询结果或刷新当前版本；未知提交不得引导新建第二份 | 不分多次 UI 操作模拟建组织/租户/权限成功 |

## 5. S03 赛事三轴、时间与项目

发布轴：draft/published/offline。举办轴：normal/cancelled。时间阶段由服务端北京时间计算：pre_registration/registration/registration_closed/ongoing/finished。不得用单个“进行中/结束”覆盖取消事实。

| 场景 | C 端表达 | B 端动作与限制 |
| --- | --- | --- |
| 草稿且开赛前 | 公共接口不可见 | 编辑/授权预览；满足公开信息才首次发布 |
| 正常公开，报名前 | 时间、费用及报名开始提示 | 配置在各自锁定规则允许内维护 |
| 正常公开，报名中 | 条件齐全可报名；满额/无有效费用配置解释原因 | 名额按整单，人数另列；容量不得低于实际占用 |
| 报名截止，尚未开赛 | 停止新提交；已有有效提交仍可付款、等待审核 | 已有提交可开赛前通过；长期未付人工拒绝，无自动清退 |
| 正常进行中 | 停止新提交/普通付款/新增通过；待审明确未取得资格 | 保留合法现场执行；禁止下架；不可首次发布 |
| 正常结束 | 不新报名/通过/正常报到/建场次 | 允许已有场次结果整理、有依据证明及资金收尾；不能改结束时间复活 |
| 曾发布后下架，未结束未取消 | 不再公开发现；本人关联记录仍可按授权查看 | 重新校验后可恢复，包括进行中；也可取消；不重开报名、不改旧义务 |
| 任一发布状态下取消 | 突出取消与本人历史/收尾路径；不绕过公开可见性 | 禁止新报名、通过、报到、场次、录分/确认、新证明；真实资金/通知收尾继续 |
| 项目无正式提交历史 | 仅展示当前有效可办项目 | 可按权限删除；删除前重验历史 |
| 项目有正式提交历史 | 旧提交有固定项目/费用依据 | 不直接删除，即使全撤回；不新增单项目取消流程 |
| 已有正式报名后赛事编辑 | 当前公开信息与旧承诺可辨 | 仅不改含义的一般更正；重大变更取消另建，不迁移名单/款项 |

B02/B03 统计把历史报名、人数、历史占用和当前有效执行分开，取消赛事不计入有效执行，不引入未定义“营收”总值。

## 6. S04 字段与收款图

| 对象状态 | 可做动作/反馈 | 限制 |
| --- | --- | --- |
| 组织定义未选用 | B15 编辑/删除文本、数字、日期、单选枚举定义 | 只本组织，不新增平台通用扩展目录 |
| 定义已被选用/正式使用 | 查看引用，合法维护或停用 | 已选不直接删除；正式使用不改类型/单位/枚举含义 |
| 定义停用 | 禁止新选择，保留已有配置/历史 | 不清空旧答案或破坏当时含义 |
| 赛事首个正式提交前 | B14 统一配置必填/顺序/说明；C06/C09 保存草稿 | 无项目级覆盖，无规则引擎；实质变化保留值并要求相关成员补填/重确认 |
| 仅字段排序变化 | 按新顺序显示 | 不无故要求所有成员重确认 |
| 赛事已有首个正式提交 | 配置锁定，展示依据 | 全撤回仍不解锁；快照保留值/标签/类型/单位/枚举含义 |
| 成员未填/错误/确认过期 | 本人定位填值、按当前版本确认 | 队长看完成情况、不代敏感确认；不复制其他赛事答案 |
| 收款图待核对/有效/缺失 | 授权承办方核对收款主体与图可用后启用 | 只 JPG/PNG/WebP ≤5 MB，校验真实类型/组织/用途；二维码收费无有效图不开放 |
| 收款图被引用/未引用 | 被引用保护；未引用满 7 天复查引用后清理 | 不覆盖/删除已引用图，变更新文件引用不得规避重大变更限制 |

一期不提供报名材料或付款截图上传。组织申请的既有附件按该业务已有规则处理，不扩展成新的通用材料平台。

## 7. S05 提交、邀请与占位

| 状态 | 用户/组织看到什么 | 主操作与限制 |
| --- | --- | --- |
| 草稿、待成员填写/确认 | 当前名单、完成情况、字段缺项 | 编辑/邀请/本人填写；不占名额、不预付款 |
| 邀请无效/过期/不匹配 | 不可办理原因 | 不泄露他人答案；不默认更换身份后自动接受 |
| 全部当前确认有效 | 可正式提交及费用依据 | 最终仍校验人数、真实值、窗口、名额与当前版本 |
| 正式提交成功 | 本次版本、冻结名单/字段/费率、资格分支和资金下一步 | 占一个整单名额；个人/双打/团体人数不能当容量单位 |
| 已提交/已通过 | 有效占位、当前资格及资金各自状态 | 原个人提交人/当前代表队伍队长可办合法整单事项，不能局部退员 |
| 被拒绝/已合法撤回 | 原版本历史、释放名额、旧资金收尾 | 可依法重新准备/提交，当前资料重确认、独立义务；不沿用旧款/旧名额 |
| 已通过申请撤回 | 显示整单影响和实际阻碍 | 截止前且全单无人报到、无场次，授权正确；提交时重验 |
| 赛事取消 | 历史状态加取消标识，名额停用 | 不伪造拒绝/删除占用；真实资金收尾不恢复资格 |

未通过报名的撤回边界沿服务端已确认业务校验；本矩阵不把“已通过”的特别限制擅自扩展为所有草稿/未通过状态的新规则。

## 8. S06 资格与审核

| 条件组合 | C07 主反馈 | B07/B08 允许动作 |
| --- | --- | --- |
| 免费、需要审核、有效提交 | 待承办方审核 | 开赛前合法人工通过/拒绝；不制造付款任务 |
| 收费、需要审核、未足额 | 待实际到账/补款；付款声明单独列 | 不通过；核对声明，payment 登记真实资金 |
| 收费、需要审核、足额 | 资金条件满足，仍待审核 | organize 重验后人工通过；到账不是自动通过 |
| 免费、无需审核、有效提交 | 自动通过，已取得资格 | 首次提交锁配置，不跳过资格/人数/名额等检查 |
| 收费、无需审核、足额到账 | 条件允许时自动通过 | 重验有效申请、规则和开赛前窗口；失效不通过但保留实收 |
| 待审遇开赛 | 审核窗口已结束，未取得资格 | 不新增通过；可人工拒绝及资金收尾，无自动批量拒绝 |
| 拒绝/撤回/取消后有实收 | 无当前有效资格，资金按原依据处理 | 实收不可复活申请，不能借修改资金重新通过 |
| 已通过后冲正致不足 | 资格历史保留，另示付款异常/执行限制 | 按 S07/S09 人工分支，不删资格/报到/结果事实 |

## 9. S07 资金状态与事实

| 状态 | C 端呈现/动作 | B09 呈现/动作 |
| --- | --- | --- |
| 无有效收费版本 | 本项目暂不可报名 | 配置有效版本，不把缺配置写免费 |
| 明确免费版本 | 0 元、不需付款 | 不生成虚假实收；审核分支独立 |
| 已正式提交收费义务 | 冻结金额、整单计费、主体/方式/联系/退改依据；可平台外付款 | 本次独立义务，不跨报名抵扣 |
| 用户已声明付款 | 已声明、待承办方核对；仅提交人/当前队长可办理 | 不当作实收；付款人称呼/时间/备注仅授权可见，无截图入口 |
| 未实收/部分实收/足额/多收 | 授权范围内显示应付、进度及待办 | 记录真实人、金额、发生时间；少付补款，多付人工处理 |
| 净有效实收计算 | 付款条件是否满足与审核分别显示 | 未冲正真实收款合计减有效实际退款；足额与本次应付比较 |
| 普通付款窗口关闭 | 开赛/拒绝/撤回/取消后不继续普通付款；截止本身不关既有有效申请付款 | 真实迟到/误付款仍登记；原已通过冲正补款走本单人工区域 |
| 误金额/未真到账 | 原进度可能变化，显示需核对 | 冲正旧事实+新增正确事实，不覆盖删除；非金额备注更正授权留痕 |
| 已退款后拟冲正 | 显示待核对异常 | 不造成累计退款超有效实收，先受控核对修复 |
| 待退款/办理中 | 显示原政策、处理状态、实际退款进度 | 实际平台外办理后录金额/时间/原付款人接收；变更接收人核验授权依据 |
| 部分实际退款 | 已实际退多少，仍办理中 | 计划未完成不结案，累计不得超有效实收；幂等/并发校验 |
| 已退款/无需退款 | 分别显示真实完成或无需依据 | 无需退款需原政策/原因，不以取消点击产生退款事实 |

实际收款、退款、资格与付款声明是独立事实。收款记录不预填第一名选手、应付金额或当前时间为真实事实；输入帮助可以提示核对，但最终确认必须对应实际发生。

## 10. S08 队伍关系

| 状态 | 反馈/允许动作 | 边界 |
| --- | --- | --- |
| 未加入/申请或邀请待处理 | C10/C11 展示本人的合法建队/加入/确认入口 | 待处理不算有效队员 |
| 当前队员 | 查看当前关系及权限允许信息 | 不默认拥有队长操作/他人证明权限 |
| 当前队长 | 管理关系、代表队伍报名/付款声明/合法撤回 | 不替成员敏感字段确认；不改变冻结名单/退款接收人 |
| 已退出/历史成员 | C12 历史关系与时间 | 不当当前队员；退队不自动退赛，本人必要报名历史按授权保留 |
| 转让/职责变化 | 刷新当前队长及可办动作 | 旧会话动作重验；注销前队长/唯一管理员需先解决职责阻碍 |

## 11. S09 报到、结果与证明

| 状态/组合 | 呈现/动作 | 限制与优先级 |
| --- | --- | --- |
| 已通过、允许现场、未报到 | B10 可授权报到 | 一赛事一人一次，名单用正式快照，不自助报到 |
| 已报到 | 显示真实人/时间及重复操作结果 | 重复请求不重复事实，不用人工删记录解除资金问题 |
| 冲正不足、无人报到且无场次 | 提示暂停新报到，去 B09 核对/补款 | 足额仅解除付款限制，不恢复取消等失效条件 |
| 冲正不足、已有报到或场次 | 显示需人工协调 | 不自动清除报到/对阵、改判或撤销证明；场次关联优先走人工分支 |
| 免费/其他有效款仍足额 | 继续按正常执行条件办理 | 不因一笔冲正一律拦截 |
| 场次草稿结果 | B11 编辑/核对/导入反馈 | C15 不显示未确认结果；结束仅已有场次收尾 |
| 场次正式结果 | C15 本人相关对阵/比分摘要/胜负 | 非参与者不可查私人结果；确认后不普通编辑覆盖，后续纠错另行实施 |
| 无正式结果/无证明 | 区分两种空态 | 非获奖者仍可能有正式赛果 |
| 有合法授奖依据 | B12 关联正式结果或承办方确认排名、人/时间后生成本人证明 | 不自动排名发奖，不宣称外部官方等级；证明仅本人和授权赛事人员 |
| 赛事取消 | 全部相关历史加取消标识 | 禁止新报到/场次/保存及确认结果/新证明，即使结束原允许收尾也停止 |

## 12. S10 通知

| 状态 | C14/B13 表达 | 允许动作/边界 |
| --- | --- | --- |
| 取消已提交、待异步投递 | 已取消；渠道尚待处理 | 固定取消时相关账号去重，包含待确认、有效报名及未结资金，不只队长 |
| 站内信未读/已读 | 持久状态、必要取消信息、业务入口 | 本人查阅；已读不是退款或强制接受取消 |
| 登录成功 | 无原任务到 C00；有安全原任务返回并重验；必要档案缺项再 C05 | 不统一强制建档、不自动报名/占位/确认/付款 |
| 短信待发送/发送中/待回执 | 如实显示待核对渠道状态 | 当前已验证号码，内容不含证件/健康/他人款项 |
| 明确发送成功/失败 | 与站内信已读分别展示 | 成功回执不代表本人读到；失败不回滚取消 |
| 暂时失败 | 授权查看原因及有限重试 | 业务去重，不无限重发 |
| 超时未知 | 待查询/等回执 | 不盲目再次发，不承诺外部绝对一次送达 |
| 无发送条件/确定错误 | 明确缺手机号/模板等实际原因，运营跟进 | 不改用紧急联系人/第三方付款号码；修正条件再处理 |
| 业务链接已不可公开/无权 | 本人合法记录仍可按授权进入；否则解释不可访问 | 切换账号或组织后重验，不以消息链接绕过权限 |

## 13. S11 身份/组织切换

## 14. S12 平台核验与受理

| 状态 | P05/P06 呈现与处理 | 边界 |
| --- | --- | --- |
| 基础资料变更摘要 | 操作者、时间、变更字段和结果 | 用途授权，不保存展示完整敏感前后值/版本回滚 |
| 注销受理、待核验 | 显示必要受理信息及核验结论 | 实际平台渠道承接，无新常规审批，无通用材料上传系统 |
| 注销有硬阻碍 | 明确有效提交/通过报名、未结资金、队长/唯一组织管理人等待办 | 先处理或移交，不自动撤回、直接改库或掩盖未结资金 |
| 符合约束已关闭 | 账号/关联会话撤销、手机解绑、关系结束的真实结果 | 保留必要历史并限制访问，关闭不等于全部删除 |
| 同号新账号/同证件已有身份 | 核验必要证据，处理一人一个当前账号关联 | 不继承旧角色；短信/姓名/生日/金额不足以证明原本人 |

| 分类清理/恢复 | 仅展示必要处理结果和限制 | 具体期限待上线落实，不宣称永久保存全部资料；恢复重施关闭/删除/访问限制 |

## 16. 首轮线框检查清单

1. C02 有免费、收费、缺有效配置、满额、截止、取消各场景，不只一个正常页。
2. C06 有本人字段缺项、成员待确认、配置变更和提交结果未知；草稿无付款按钮。
3. C07/C08 同屏区分资格、声明、净有效实收、退款及下一步；四种审核/费用分支分别可解释。
4. B07/B08/B09 有待实收、待审核、窗口结束、部分退款、冲正不足及取消资金收尾；审核权限不自动显示资金写入。
5. B03/B05 展示三轴状态及首次发布/恢复/下架/取消差异；结束收尾与取消禁止不冲突。
6. B14/B15 显示字段引用、配置锁定与本人重确认原因，不产生项目级字段分支。
7. B10–B12 体现已有执行的资金异常、草稿/正式结果和授奖依据；C13/C15 有各自空态与私人边界。
8. C14/B13 已读/短信回执/退款独立；P06 不把人工受理改成常规审批，顶栏可识别身份/组织。

本表为后续线框、视觉稿、组件实现及普通角色验证的共同输入；本轮仅执行文档检查，未执行 UI、接口、数据库或真实短信/资金验收。

办赛服务的会话失效/无本人版本/进度查询失败沿共用状态处理：不泄露申请内容，不把失败当作无申请；B16/B17 本地模拟不证明服务端授权或真实审核通过。材料在线上传按最新文件边界后置，不阻止无附件准入申请。

本轮已核对文档任务与 HTML 覆盖：定义保留不等于原型已画；逐项缺口及共享 B 端布局见 [UI 覆盖与一致性检查](UI覆盖与一致性检查.md)。
