# Cursor：C 端平台登录、落点与导航实施提示词

请在当前 AISports 项目实施以下正式前端改版。先读取 AGENTS.md、docs/README.md、最新交接记录、ADR-005、ADR-011、ADR-012，以及 docs/05-ui/登录与导航设计决定.md、C端-Page-Map.md、User-Journey.md、UI覆盖与一致性检查.md。最新业务代码 / 交接优先于地图中的历史实现快照。所有终端命令用 PowerShell 7，保留其他会话的未提交修改。

## 目标及可参考原型

参考 docs/05-ui/prototype/index.html、auth.js、consumer.js、styles.css 与 previews/auth/。这是虚构 HTML 原型，只用于布局和任务连续性；不要复制其模拟认证、验证码、sessionStorage 会话布尔值或虚构档案到生产逻辑。C 端延续 AI运动、莲池绿 / 暖橙、保定城市站及通用运动平台；B 端复用 RuoYi / Element Plus，超级管理员维持原生后台。

1. 站点未登录打开 `/` → 公开 `/portal/home`（C00）。平台账号普通登录成功 → C00；不再统一跳 `/portal/identity`。来自报名、邀请、入队、个人记录或办赛申请的合法目标优先返回。登录 / 注册不占位、提交报名、代确认、付款或授予办赛准入。
2. C 端新增独立 `/portal/login`、`/portal/register`、`/portal/forgot`，位于后台 Layout 之外、复用 C 端品牌布局。原生 `/login` 留给平台管理员用户名登录；该页没有预填管理员账号或密码。平台用户（参赛者 / 队长 / 办赛负责人）使用统一手机号登录，不另建一种账号。
3. C 登录框初始空白，标注手机号 / 密码；去掉租户下拉、五个社交按钮、rememberMe、语言切换、RuoYi 页脚，保留真实启用的验证码、注册、忘记密码和返回首页。C 页面不以手机号 / 用户名形态自动切认证策略。不新增短信登录或社交登录。必要开源许可证与源代码声明保留。
4. 注册标题“注册”。使用现有平台注册接口，成功回 C 登录并保留验证后的原目标，不自动登录、不携带密码。忘记密码成功回 C 登录，清理本地认证状态并遵循后端撤销平台及关联组织会话的现有规则，保留目标。显示真实验证码用途、错误、过期、限频、发送中 / 重试，未知手机号恢复提示保持一致，禁止把演示验证码或模拟成功当真。
5. 从公开赛事点报名时保留 eventId、unitId 和原任务；完成认证后返回同场同项目。需要本人档案的报名 / 入队操作才引导 C05，保存后回原任务并重新校验；本人姓名、出生日期、性别、已验证手机号按当前规则，选填字段不强制。浏览 / 账号管理 / 办赛申请不要求先建档。原任务已不可办理时解释原因，不静默创建新单或跳到无关赛事。
6. C12 承载为 C11 队伍详情内“加入/退出记录”标签，不新增一级导航或独立页面；C10 保留现有本人历史关系摘要 / 按队伍的本人历史投影。退出后只能查本人的已结束关系，不能恢复完整队伍权限。当前有效成员、历史成员、申请 / 邀请分开。完整 C10/C11/C12 本轮先记录承载，随队伍页面设计实施；不要把当前说明弹窗标为已完成历史页。

## 必须沿用的认证及授权契约

先阅读 plus-ui/src/router/index.ts、permission.ts、views/login.vue、register.vue、forgot.vue、views/portal/identity.vue、team.vue、api/login.ts、api/types.ts、store/modules/user.ts、utils/request.ts 及当前后端 PlatformAuthStrategy / 平台账号接口实现，避免照搬旧登录中的 username 分支与本地明文密码记忆。

- 平台登录调用现有 `POST /auth/login`，认证策略 `grantType=platform`，内部平台租户按现有契约使用（当前为 900001），clientId 沿实际客户端配置；技术租户不让普通用户选择。字段按 LoginData 与后端策略映射（当前 username 承载手机号），不要凭视觉字段名更改请求 DTO。
- 管理员 `/login` 使用原有 password 策略、管理员租户 / 用户名契约；不能因移除 C 端租户下拉破坏后台登录。删除预填凭据及明文密码持久化；如保留管理员记忆偏好，最多非敏感用户名，密码不缓存。
- 注册、恢复沿 api/login.ts 现有 `/auth/participant/captcha-config`、`sms-code`、`register`、`reset-sms-code`、`reset-password`。验证码用途严格隔离；加密头、isToken=false、repeatSubmit 等沿现有约定。密码格式按当前前后端校验（目前 5—20 位及禁止字符），不要独自改后端安全规则。
- 平台 token、clientid、技术租户、组织授权交换和后台菜单 / 按钮权限仍按 ADR-005。组织映射 sys_user 不能独立通过密码 / 手机号 / 社交登录。访客 C16 登录后可回 B16/B17，申请不要求参赛档案；批准还要有效组织授权才能进入 B02，禁止静态前端放行。
- user info / 菜单加载与会话过期按现有 store / 请求拦截器执行，不仅用 token 存在就显示“林一”或业务资料。首页访客显示登录 / 注册，登录后显示真实账号概要及消息入口，无姓名时用已有 displayName 安全兜底。
- returnTo / redirect 使用集中式允许路由检查与参数白名单，仅站内合法业务页面；外域、协议相对地址、脚本、编码绕过、路径穿越、平台账号越权后台目标 → C00。不持久化密码、验证码、手机号、材料、任意查询参数；邀请凭据不写日志 / 证据。返回前服务端重验对象授权及状态，不信任前端检查。

## 路由兼容与实现范围

`permission.ts` 当前 participantLanding 默认 `/portal/identity`，未登录保护统一发 `/login`；改为按平台 / 后台上下文分别处理。逐个添加 C 公共首页和账号页匿名白名单，不放开整个 `/portal/*`，个人记录、本人档案、邀请资料和组织页面保持真实认证及授权。旧 `/register`、`/forgot` 做兼容跳转并保留安全目标；修复旧 `/forgot` 不在匿名白名单的问题。处理已登录进入认证页、直接深链、刷新、浏览器前进后退及无效目标，不出现重定向循环。站点根 C00 默认入口与管理员 `/index` 落点区分，复用原生 TagsView / Layout 的 B 端页面不能被 C 首页替代。

所有共用正式样式放 plus-ui/src/assets/styles/，复用现有请求、表单和身份组件，保持 C 端 390/375/320px 可用。不修改模型 / DDL，不造新认证 API，不开启未来场馆 / 本地生活交易，不画完整超级管理员页面。当前 MinIO / 收款码 / 办赛附件已有更新，勿按旧地图把现有能力禁用或覆盖；资金、准入和审核语义仍以 ADR-011 为准。

## 验证与交付

请实际执行变更相称的类型检查 / 构建与普通平台账号、管理员两类路径验证，至少覆盖：

- 新访客根首页无假账号；登录空字段 / 失败 / 验证码过期 / 限频；普通登录 C00。
- 单打 / 双打等选择后登录保持赛事与项目；注册 / 恢复往返保留任务；缺档案补齐后继续，不自动正式提交。
- 公开赛事取消 / 下架 / 截止、邀请失效 / 身份不符、无组织准入时返回原任务给真实原因，保持服务端授权。
- 管理员用户名登录及管理深链；平台用户不会进入管理员默认页或取得越权菜单；未准入办赛无需参赛档案且不能进入组织运营。
- 恶意或多重编码 redirect、刷新 / 返回、会话失效、320px 布局；密码 / 验证码不落浏览器持久存储、URL、日志、截图或提交。

真实短信 / 验证码服务端验签若仍被外部配置阻塞，保留明确未验证记录，不关闭相关一期缺口。HTML 原型测试仅模拟，不代替普通角色真实 API 验收。结束更新 docs/01-development/交接记录.md、一期未完成事项.md 和受影响 UI 文档，分别写已实现、实际验证、未执行 / 外部阻塞。提供可复查页面路径与结果，不把设计已定当功能已完成。若现有契约缺少实现这些 UI 所需的数据或权限，先完成无依赖部分，说明具体缺口；仅对会改变业务权利的选择向用户确认。
