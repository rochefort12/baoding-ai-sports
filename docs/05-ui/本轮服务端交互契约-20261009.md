# 服务端交互契约（2026-10-09）

供Cursor接续本轮界面修改，依据[ADR-023](../03-architecture/ADR-023-助手身份传递与报名草稿删除.md)。运行生效与测试结果见最新交接，不以本文代替验收。

## 独立主视觉

POST /sports/b/events/{eventId}/promotion/visual，原consent/style/audience/keywords保持。无需先有文案；返回原PromotionView，即使saved=false也可返回visualFileId、visualStyle、imageAvailable。saved仅表示完整文案存在，不应作为主视觉预览或按钮的唯一条件。图片走既有组织保护的媒体读取，不能拼公共存储地址或泄露凭据。

主视觉成功不自动生成文案；后续文案生成保留图片。失败保留已有材料。相同请求仍复用，换风格不自动付费调用。既有同意/生成中防重/迟到回复保护保留。

## 报名草稿删除

新增DELETE /sports/c/registrations/{registrationId}，成功为R<Void>。服务端仅允许当前可办理者删除从未提交的draft，并删除成员字段值与邀请；正式历史不能物理删除。无须请求体，不提供管理员跨用户入口。

界面可初步按status=draft、canManage=true、submittedAt为空、requestKeyConsumed=false、无已知付款义务展示“删除草稿”。最终以服务端校验为准，不能根据状态为draft就默认撤回历史也可删。确认提示应说明草稿及其成员邀请将移除；删除失败展示业务原因，成功刷新本人报名与收到邀请列表。不要以撤回接口代替删除。

## 其他

本人报名查询账号长编号、主视觉保存的平台所有者、审核付款提示约束已经在服务端修正。无需在界面添加账号输入、转换为Number、绕过权限或自行判断付款成功。当前Cursor界面范围继续按用户提供提示词执行，避免重复编辑模型/业务代码。

## 2026-10-12 奖项、材料及队伍报名契约

- POST /sports/b/competition/awards 可选 awardKind=placing/special 与 basisMatchIds；明确最终名次不再以换名称创建另一项，既有名次从赛后收尾修改。专项依据限制在本报名场次。
- GET /sports/proof-review/events/{eventId} 默认待复核，includeVerified=true 包含当前已签发；每个逻辑奖项返回代表 id/version、names、unit_name、award_kind、people_count、history_count、basis_text、basis_results、basis_fingerprint。新 id 与 version 必须来自同一实际行。
- honor.resolve 的重新签发增加 basisFingerprint；读取的赛果依据变化、失效或撤销则拒绝，不可用任意其他赛果替代。仍要求责任人 UI 的动作确认和组织权限。
- GET /sports/c/proofs 默认当前有效；history=true 加本人历史。ProofCard 的 status/current/reason 供区分当前、暂停、撤销或替代。历史不能通过旧详情 URL 或图片导出伪装为有效。
- 赛事材料保存/编辑仍使用原 Markdown，现有模板、生成或已保存内容默认进入阅读预览，共用 MarkdownIt 与 DOMPurify，正文、标题、列表、表格、引用和代码块统一排版，不执行原文 HTML 或脚本。
- POST /sports/c/registrations 增加可选 memberAccountIds:string[]。teamId 与名单必须一起使用；服务端按当前队长、可用成员、人数、事务及幂等核对。名单一次带入，其他成员为待本人确认并发送站内邀请。重复请求返回当前状态，不恢复后来移除的成员或覆盖非空名单。
- EntryCard.members.selfMember 回显当前登录者，队长不参赛时不要请求其本人参赛字段/声明。创建与正式提交都展示完整名单；本人确认权、资金、容量及提交快照保持服务端权威。

详见 ADR-039/040 与[本轮验证](../04-verification/奖项材料与队伍报名修复验证-20261012.md)。

## 2026-10-12 赛事项目报到契约

POST /sports/b/competition/events/{eventId}/check-ins 提供 unitId、personId、requestKey，响应 CheckInCard 增加 unitId。未传项目的旧调用仅在人员只有唯一已通过项目时兼容，多个项目须明确选择。请求摘要包含项目，相同键不能更换项目。服务端复核本项目冻结名单、当前收款和赛事状态。

GET /sports/b/competition/events/{eventId}/eligible 的 EligiblePerson 增加 unitId、legacyEventCheckin。checkedIn 只表示本项目有效报到；legacyEventCheckin 表示存在项目未知的旧赛事级到场，不可把它展示为全部项目已报到。筛选与请求采用行内编号，不使用项目名称或旧选择状态。手机以完整参赛人卡片展示状态和报到操作，重复点击有办理中状态。旧核查、撤回和成长边界见 ADR-041。
