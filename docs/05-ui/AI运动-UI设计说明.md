# AI运动 · 平台版 UI 设计说明

日期：2026-10-07。版本：V0.2。品牌名称“AI运动”为用户暂定；配色、标识和布局为第一版设计建议，尚未经用户视觉评审。交付为本地 HTML 交互原型，不是 Figma 文件，也不是已接入业务的 Vue 页面。

## 1. 已收到的设计要求

- B 端简洁、方便、直观，操作不复杂；正式接入必须复用已有 RuoYi-Vue-Plus / plus-ui 前端、权限与组件。
- C 端独立入口和界面，优先适配手机，同时兼顾电脑；复用同一前端工程不影响入口和视觉独立，不另建身份体系。
- 用户补充：通用赛事与体育服务平台，羽毛球仅一期试点；考虑场馆运营、本地运动生活撮合及体育信息流。保定元素要增强，运动保持主主题。
- 品牌暂定“AI运动”，暂无正式 Logo、颜色和指定参考产品。用户授权结合保定、AI、参赛者及运营管理任务自由提出方向。

业务仍以 [ADR-011](../03-architecture/ADR-011-一期业务收口与交付边界.md)为准，页面任务见 [Page Map](README.md)、[User Journey](User-Journey.md)和[状态矩阵](页面状态矩阵.md)。代码修复顺序以最新交接/一期清单为准；本设计原型不改变该顺序、不关闭业务待办。

## 2. 平台版方向：保定城市站，通用运动生活

保定的地方感从古莲花池的绿色意象提取，不画政府徽章或假借官方背书。古莲花池与保定的联系参考[河北省文物局资料](https://wenwu.hebei.gov.cn/system/2023/09/27/030253938.shtml)。采用池水/植物的深绿色、浅灰白底与少量暖橙；这是设计推导，不是城市官方色或已注册品牌色。

首版首页绑定羽毛球的呈现已被用户纠正。平台首页现在以原创运动者、跑道和多种球类意象为主，辅以低对比古城/亭檐/莲池概念线稿；标题“在古城，找到运动的每一种可能”及保定城市站加强本地感。羽毛球插画保留在具体赛事卡/详情，不代表整个品牌。AI 字母以简单几何 A、向上的转角和运动点作为临时标识；不增加智能助手、算法推荐或 AI 审核功能。标识不是正式商标交付，名称与图形仍可调整。

交互参考[微信官方 WeUI](https://github.com/Tencent/weui/blob/master/README_cn.md)的移动端表单、按钮、反馈等基础组织方式；B 端对照[Element Plus 官方组件](https://element-plus.org/zh-CN/component/overview)及项目既有框架。选这些参考是为了贴近国内用户常见操作、方便复用，不声称存在“公认最佳产品”排名，也未复制第三方界面、图片或品牌图形。

## 3. 色彩、排版和组件

| 用途 | 第一版值/原则 | 使用范围 |
| --- | --- | --- |
| 品牌/主操作 | 莲池深绿 #155E52 | 主要按钮、选中导航、强调金额 |
| 深色导航 | #193C34 | B 端侧栏；C 端保持明亮 |
| 活力点缀 | 暖橙 #CF4E25 | 插画、等待关注，避免整屏强色 |
| 页面背景 | #F5F7F4 | 浅灰白，减少视觉疲劳 |
| 正文/次要文字 | #21332E / #66756F | 状态和字段优先保证可读性 |
| 成功/警告/错误 | 绿/橙/红，辅以文字与图标 | 不能只凭颜色区分状态 |
| 中文字体 | 系统微软雅黑/苹方等 | 不依赖海外字体 CDN |
| 基础尺寸 | 正文 14px，次要 12px；C 端关键按钮至少 42px 高 | 手机点按与后台密度分别考虑 |
| 圆角 | C 端卡片 13–16px；B 端卡片 10px、按钮 6px | 品牌统一，消费界面与工作界面各有密度 |

全站采用共享样式。原型用 prototype/styles.css；正式接入按项目规范迁到 plus-ui/src/assets/styles/，映射 Element Plus 主题和框架变量，不在各页面复制样式。

## 4. 两端结构和本轮完成度

| 端/页面 | 本轮交付 | 边界 |
| --- | --- | --- |
| C00 平台首页 | 保定城市站、通用运动主视觉、赛事/个人快捷入口、未来服务次级预告 | 不把试点运动当品牌；无多城市切换或假未来服务操作 |
| C01 赛事发现 | 跨运动项目与状态筛选、统一卡片、无结果/未开放状态 | 当前只有羽毛球试点；其他运动不生成可报名假赛事，目录样例不是开放排期 |
| F 系列服务预告 | C端场馆/运动生活，B端场馆/内容生活服务空间 | 仅方向介绍和返回，不新增一期可执行业务、权限或承诺 |
| C02 赛事详情 | 时间地点、责任组织、项目/整单费、审核/退改、联系区域；手机底部报名入口 | 图/联系/退改时限都是占位示例，不能直接作为批准规则上线 |
| C06 分步报名 | 本人填值确认→核对规则→模拟正式提交 | 基础档案只读示例；成员已自行确认是虚构场景，真实邀请与版本链未接入 |
| C07/C08 报名与资金 | 本人列表/详情、资格/声明/实收/退款分别展示、模拟声明、撤回/重提 | 无真实收款码、支付、退款或业务写入 |
| C09/C10/C11/C14/我的区域 | 邀请待确认概念片段、队伍/个人入口、取消站内消息片段 | 队伍授权链、完整档案/证明/结果/办赛申请等未完成详细设计；入口点击明确说明范围 |
| B01/B02/B03/B05 | 赛事列表、概览、固定赛事工作区、预览/下架/恢复/取消 | 新建编辑页只是后续入口，首次发布未模拟；不调整已有后端 |
| B07/B08/B09 | 列表查询、报名抽屉、独立审核与资金操作、收款/补款、冲正、部分退款 | payment/organize 仅界面权限演示，不是真实权限控制 |
| B06/B14/B15 | 项目费用只读、锁定字段、独立提交前配置场景、目录与新增表单预览 | 未模拟真实费率/文件上传、完整字段定义保存及成员配置版本验证 |
| B13 | 取消后站内/短信/已读分开展示及结果模拟 | 不发送短信；列表只是收件片段，不保证完整接收人数 |
| B10–B12、P01/P02/P05/P06 | 未生成详细原型 | 已在 Page Map 及矩阵中明确，不用入口占位冒充完成 |

B 端先区分平台工作台与业务空间，未来场馆/内容生活服务只做规划预览；当前赛事空间仍以“选择赛事后在同一工作区连续办理”为主，报名详情里集中资金操作；没有独立全套财务菜单或业务大屏。表格首要展示对象、资格、资金、声明与下一步，低频操作进入抽屉，减少切页。

C 端主导航为首页、赛事、我的参赛、我的。报名、队伍与个人结果入口进入“我的参赛”分区；体育资讯与生活服务放在次级规划预告，不增加空的资讯主导航。平台结构见[平台级 UI 信息架构](平台级UI信息架构.md)。信息发现与任务办理分开；手机采用底部导航，赛事详情另有固定报名栏，重要操作无需翻到长说明末尾。公共不可见与本人记录访问分开，取消不伪造原报名拒绝或实退款。

## 5. 打开与评审

推荐通过项目 PowerShell 7 入口启动：

```powershell
./scripts/Start-UiPrototype.ps1
```

本机地址：C 端 [http://127.0.0.1:5188/](http://127.0.0.1:5188/)，B 端 [http://127.0.0.1:5188/business.html](http://127.0.0.1:5188/business.html)。服务只监听本机且只提供原型静态文件；端口占用可传 -Port 调整。退出该终端服务后地址失效，重开入口即可。未发布公网。

也可直接打开 [C端 HTML](prototype/index.html)或 [B端 HTML](prototype/business.html)；浏览器 file 地址的本地存储共享策略不一致，跨端演示建议用上述本地服务。无 CDN、外部字体、远程图片或在线依赖。

建议评审顺序：

1. 看 C 端首页/详情的品牌方向、信息是否好找及手机排版。
2. 选择单打，完成本人确认、核对、提交及付款声明；观察尚未到账/通过。
3. 进入 B 端名单找到该报名，登记模拟实收，再人工审核；比较两种权限。
4. 通过底部“原型演示场景”看免费/收费 × 人工/无需审核四分支；场景切换重置虚构数据，不是解锁真实配置。
5. 模拟取消，查看本人消息、资金收尾与部分退款；比较报名截止、进行中、结束。
6. 在“参赛字段”查看锁定状态；用提交前独立场景检查可编辑布局。

演示数据存本地浏览器，重置仅清本原型的数据键，不清其他站点/业务数据。跨端共享方便评审；正式身份切换必须清理旧授权/缓存/异步响应，本原型未接入真实会话机制。承办方预览参数只用于演示，正式产品不可凭该参数绕授权。

## 7. 仍待评审与正式接入

用户首先评审平台定位是否清楚、保定元素是否适度、次级预告是否有价值，再评审配色、两端密度与报名/资金办理，再调整组件细节。本期其他页面的详细设计与正式 Vue 接入按原清单继续；不能把本轮局部原型标为全站完成。

本轮不改变业务权利；若用户选择方向，仅确认视觉与交互基线。真实渠道、供应商、保留期限、收费/退改参数和部署责任仍按原交付条件确定，不复用原型示例作为真实配置。

## 2026-10-07：补齐我要办赛与本人审核查看

首版“我要办赛”只有说明弹窗，属于已定义任务的原型遗漏。本轮新增 B16/B17（organizer.html）：申请表、草稿、核对提交、冻结待审、拒绝理由与修改重提、只读历史版本、已准入入口及查询未知/失败/失效状态。首页与我的均接入，现有组织工作台可回看记录；准入前不展示组织操作菜单。复用共享颜色、表单、卡片、表格；正式页面继续复用 RuoYi 布局与 Element Plus 组件，平台账号准入前路由不要求组织租户会话。

管理员沿 RuoYi，申请审核 P01/P02 视觉页按用户本轮要求暂不生成。用户所称资质审核查看沿已确认的办赛准入，未扩展为证照验真或官方认证；申请附件上传按当前文件边界后置，原型不收取文件。所有审核结果仅从明确标记的原型状态选择器载入，申请人没有审批操作。

办赛申请验证：草稿恢复、必填/核对、提交冻结、待审阻止编辑、拒绝保存不重提、下一版提交、旧版只读、无本人版本、通过跳转、申请人无审批动作、未知结果/查询失败/失效及移动布局；本地模拟与真实业务验收分开。
