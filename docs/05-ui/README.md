3. 现有前端路由、业务页面、API 和管理菜单迁移，作为代码现状依据。文件存在不等于运行可达或已验收。
4. [业务母版](../99-raw_materials/保定体育综合服务平台_全域业务母版_V1.0.md)第 17 章页面行为包及相关业务章节，作为来源；已调整/后置部分不直接恢复为 M1 功能。

## 3. 两种独立标记

每条页面记录同时写设计状态与代码现状，两者不能互相替代。当前一期任务已确认，表中“局部待定/候选”仅保留解释历史标记，不重新将已确认任务视为业务未决；承载形式与布局仍待设计评审。

| 设计状态 | 含义 |
| --- | --- |
| 确定 | 页面任务有明确业务依据；本地图建议的导航、拆分、标签页和展示形式仍待 UI 评审 |
| 局部待定 | 页面任务确定，但内部某项流程、字段、入口位置或展示范围仍待业务决定 |
| 候选 | 独立成页或一期实施尚未决定；不作为必交页面、不默认出现在正式导航 |

代码现状使用「已有页面」「已有局部功能」「待开发」「旧页面/菜单停用」。已有页面的最终改版仍需实施和普通角色验收。新增逻辑页面 ID 不等于新增路由；详情、编辑和记录可以在同一路由内用子视图、标签页、抽屉或弹窗实现。

## 5. 页面设计共用边界

- 资格审核、应付义务、用户付款声明、实际到账、退款、报到和结果分别展示；不使用一个「完成」标签替代全部状态。
- 赛事发布状态、举办状态、时间阶段独立，时间以北京时间解释，窗口边界由服务端判断。
- 队伍当前成员与历史成员分开；退队不等于退赛，当前档案不覆盖提交时名单快照。
- 公共页面不返回私人身份、健康、付款明细和证明；敏感后台摘要只给用途匹配的授权人员。
- 名额单位是整单报名，人员统计另列；付款人可与参赛者不同。
- 关键页设计加载、空数据、失败、无权限、会话过期、对象不可见、时间截止、版本冲突和重复操作反馈；超时后先核对原事实，不引导重复报名或重复记账。
- Web/H5 共用业务结果。C 端导航和 B 端表格密度可以分别适配屏幕；现有框架布局不是最终视觉方案。
- 共用样式落在 plus-ui/src/assets/styles/，不复制多份页面样式。地图不承诺新的页面后端数据已存在。

## 6. 未决事项与更新方式

业务待办、决定及缺陷继续归[一期未完成事项](../01-development/一期未完成事项.md)，这里仅记对页面的影响，不复制一份缺陷清单。后续更新以稳定页面 ID 追踪，可调整名称/承载形式；页内区域升级成独立路由需在地图标明理由。

优先评审顺序建议：B/C 总导航 → C02 赛事详情与 C06/C07 报名 → B03 赛事工作区与 B08/B09 审核/资金 → 队伍 → 报到录分 → 平台必要核验与受理。该顺序是设计建议，不改变已确认一期范围。

模型/旅程/矩阵轮已完成文档检查。本轮 HTML 原型真实运行隔离浏览器并保存截图，含办赛申请补齐的新版 112 项本地模拟交互/布局检查通过，保存 32 张登记截图；未执行真实接口、数据库或普通角色业务验收，未修改验收状态。
