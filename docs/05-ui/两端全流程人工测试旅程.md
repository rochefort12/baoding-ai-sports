# 两端全流程人工测试：从空数据开始走一场比赛

版本 V2.0，日期 2026-10-07。状态：待执行操作指南。此版替代 V1.0，原 T 编号不再沿用，旧问题记录须注明版本。

## 怎么使用

从第一步往下走，每段明确写出**现在用谁、打开哪里、做什么、应该看到什么**，不用记字母代号。

**申请组织 → 管理员审批 → 创建并发布免费赛事 → 参赛者浏览报名 → 负责人审核 → 现场比赛 → 查看赛果和证明。**

主线结束再走收费、双打、队伍、撤回、取消与时间边界等分支；各分支先创建所需数据。异常检查紧跟对应操作，第一次可先走正常操作，第二遍再测异常。

依据：[ADR-011](../03-architecture/ADR-011-一期业务收口与交付边界.md)。覆盖一期赛事与必要审批，不含未来场馆/生活、自动排赛、平台代收和完整申诉。本文不替代 TC01—TC80 的完整验收。

### 从什么状态开始

最新交接显示：本机没有组织、人员档案、赛事和报名，保留一个试用平台账号及框架基础账号。**一个试用账号不够完成多人比赛**，需要时会指引注册其他账号。不再次清库，不删除基础账号/租户；旧未引用对象存储文件不当本轮上传证据。

只需认中文角色：

- **组织负责人**：用保留试用平台账号申请组织，通过后同账号进办赛，可兼任审核/现场。
- **平台管理员**：已有管理账号，只做原生后台审批及必要授权准备。
- **参赛者小李、参赛者小王**：后面注册的两个独立账号，中文备注便于阅读，不要求真实档案姓名叫小李/小王。
- **收款人员**：收费时才需要，有资金权限；负责人合法获授时可兼任。
- 其他参赛者、第二组织人员在相应分支才准备。

不同账号用独立浏览器会话，或退出再登录。普通标签通常共用身份，每次切换看顶栏确认。凭据用已有安全渠道，不写本文。

真实短信/验证码仍有待接入：注册阻塞就记录，先用试用账号测办赛；没有更多合法账号则暂停多人报名。不用管理员冒充参赛者，不改库造账号或绕过验证。

入口：[首页](http://127.0.0.1:5173/portal/home)、[平台登录](http://127.0.0.1:5173/portal/login)、[我要办赛](http://127.0.0.1:5173/portal/organization)、[管理员登录](http://127.0.0.1:5173/login)。地址变化替换主机/端口。

每步记通过、问题、已知缺口、外部阻塞或未测。问题记“第几步、使用谁、赛事名、实际表现”，截图遮盖私人资料，序号仅方便定位。

## 第一步：负责人申请办赛

**现在用组织负责人的平台账号。** 没有组织，不能先直接进组织工作台。

| 顺序 | 在哪里做什么 | 应该看到什么 |
| --- | --- | --- |
| 1.1 | 平台登录，用保留试用账号 | 无原任务回首页，显示本人而非示例账号 |
| 1.2 | 点击我要办赛 | B 共享布局/顶部标签，无参赛档案前置，不选技术租户 |
| 1.3 | 组织名“交互测试运动社”，填必填/合法附件，存草稿并刷新 | 草稿附件回显，保存不是正式提交 |
| 1.4 | 正式提交，再看进度 | 待审/版本明确，不改已提交版本，尚不能进组织 |

**异常检查：** 缺必填、非法附件定位错误，上传失败不假成功；待审直接开组织地址不泄露数据；重复提交不重复申请。

## 第二步：管理员审批，建立组织

**切换平台管理员，打开管理员登录。** 不在平台手机号页填管理用户名。

| 顺序 | 使用谁／做什么 | 应该看到什么 |
| --- | --- | --- |
| 2.1 | 管理员登录，组织申请审核找刚才申请 | 原生若依界面，申请可查 |
| 2.2 | 管理员先拒绝一次，写原因 | 拒绝记录保留，不删除申请 |
| 2.3 | 回负责人进度，按原因修改重提 | 原因可看，旧版本只读、新版本可分 |
| 2.4 | 管理员通过新版本 | 建组织及准入，不逐场审批 |
| 2.5 | 回负责人刷新，点进入组织 | 服务端授权入场，顶栏办赛身份/组织正确 |

**异常检查：** 被拒不能入场，历史版本不能编辑；准入不宣称官方验真。后续用普通负责人，不用管理员代办。

## 第三步：创建第一场免费赛

**现在用负责人，办赛身份。** 免费主线不依赖真实资金条件。

| 顺序 | 在哪里做什么 | 应该看到什么 |
| --- | --- | --- |
| 3.1 | 赛事管理→新建 | 空列表可以创建 |
| 3.2 | 名称“交互测试·免费单打赛”，填地点、联系人、规程/须知/声明 | 责任组织正确，公开联系与私人注册号区分 |
| 3.3 | 当前可报名，截止未来、开赛晚于截止、结束晚于开赛，保存草稿 | 回显，尚不公开 |
| 3.4 | 点赛事名称/工作区 | 保持标题/任务标签，返回列表可找 |
| 3.5 | 项目与费用建单打，人数1、整单容量至少4，设有效免费零金额配置 | 人数/整单区分；无配置不默认免费；需 payment 而无权时记录准备不足，通过既有受控授权准备 |
| 3.6 | 保持人工审核；当前方式开关在赛事表格报名审核列 | 方式设置不是审核某笔报名 |
| 3.7 | 列表编辑或概览对应操作核对保存 | 现入口分散，集中方案未实施，难找记体验意见 |

当天比赛为报名审核留足时间并等待服务器现场窗口；分多日测则日期往后设。正式报名后不靠改期赶测试。

**异常检查：** 非法时间/缺必填拒绝；无提交项目目标可删，请另建临时项目测删除，不删主线。

## 第四步：字段、图片、预览和发布

**仍用负责人，配置在首次正式报名之前完成。**

| 顺序 | 做什么 | 应该看到什么 |
| --- | --- | --- |
| 4.1 | 组织字段目录建文本/数字/日期/单选测试字段 | 本组织目录，用非敏感内容，不收无必要健康信息 |
| 4.2 | 在工作区“报名设置”选用报名信息字段，设必填/选填、排序/说明 | 全赛事统一，不是只给某项目 |
| 4.3 | 无图预览，再传合法宣传图/说明图预览 | 默认封面可用，有图替换；共用 C 页面，可切换电脑详情、手机详情和首页卡片，预览无报名写入 |
| 4.4 | 公开与发布或概览操作首次发布，确认联系人公开 | 成功公开，不需平台再逐场审批 |

**异常检查：** 草稿预览不公开；非法实际格式、超5MB拒绝，发布缺项说明原因；收款码不在介绍公开。目录删除现缺口，停用不能冒充删除。

**使用参赛者小李，从刚才报名登录继续。**

| --- | --- | --- |
| 6.1 | 注册、合法验证，再回登录 | 标题注册，原任务保留，注册不是报名；短信阻塞记录，不用原型码 |

## 第七步：审核小李，再让小王报名

| 顺序 | 使用谁／做什么 | 应该看到什么 |
| --- | --- | --- |

| 7.2 | 负责人通过，回概览 | 有效资格，待审减少，重复审核不重复事实 |
| 7.3 | 小李刷新 | 通过，不是仅提交成功 |

## 第八步：现场比赛、结果和证明

前置：两人通过且服务器允许现场操作。时间未到先做后面独立分支再回来，不改服务器时间。

| 顺序 | 使用谁／做什么 | 应该看到什么 |
| --- | --- | --- |
| 8.1 | 负责人报到任务给两人报到 | 一赛事一人一次，无参赛自助入口 |
| 8.2 | 场次录分选同项目两单手工建场 | 对阵正确，不自动排赛 |
| 8.3 | 保存双方草稿，小李看我的赛果 | 办赛可回看，C 不公开草稿 |
| 8.4 | 负责人确认，两人刷新 | 正式对阵/比分摘要/胜负，仅本人相关 |
| 8.5 | 负责人给小李测试称号，关联正式结果或实际排名依据 | 确认人时间留存，不自动发奖/宣称官方等级 |
| 8.6 | 小李看证明、小王看赛果和空证明 | 本人私人证明；无证明不等于没参赛 |

**异常检查：** 重复报到不新建、待审/拒绝不能报到；相同重复确认不造事实，不同内容不能覆盖正式结果。访客/小王不能读小李证明，队长不能看全员；无结果又无依据不能授奖。

**免费人工主线完成。** 后续先建专用数据，避免撤回/取消破坏已比赛赛事。

## 第九步：另一场收费赛，走付款和审核

**先负责人新建“交互测试·收费单打赛”**，不要改已有正式报名的免费赛价格。重复第三/四步，设人工审核、单打、足够容量，明确整单金额、收款主体/方式/联系、退改政策。二维码方式须有效收款图，首次发布开赛前完成。

没有受控真实收退款条件可看指引/校验，资金写入标未测；不能为了点完按钮登记未发生款项。平台只登记，不自动扣款退款。

| 顺序 | 使用谁／做什么 | 应该看到什么 |
| --- | --- | --- |
| 9.1 | 小李从公开详情正式报名 | 提交后即能按冻结说明付款，不等审核；资格待审/声明未声明/资金待付款分开 |
| 9.2 | 小李按指引真实付款，需要时点击“我已付款，通知承办方”；收款人员尚不登记实收 | 声明待核对，不冒充到账，不能据此通过；无付款截图上传要求 |
| 9.3 | 负责人试审核通过 | 足额实收前拒绝/禁用，不以声明代收款 |
| 9.4 | 平台外确有整笔付款，收款人员核对后在报名详情登记实际付款人、金额、北京时间、备注 | 流水真实可查，付款人可为第三人；文字行留白清晰，点击左侧可收起详情；不默认首位成员/当前时间为事实 |
| 9.5 | 负责人重新查询并人工通过，小李刷新 | 实收与资格分别更新；到账本身不替人工审核 |
| 9.6 | 双方离开再回，查看流水/义务 | 持久一致，不只是前端改标签 |

**异常检查：** 金额空/非正数、付款人/实际时间缺失拒绝；取消弹窗不写。重复登记先查原结果，不重复分配。少付仍待补，多付按原款收尾。足额后改为“补记其他实际收款”，金额为空，缺原因或取消二次确认不写入。相同付款人/金额/实际时间应提示核对；同一笔不要重登。必要补款、分次退款按真实事实测试，不虚构款项。

| 12.3 | 小李代表队伍选本次小李/小王名单，各人确认正式提交 | 长期成员不自动全参赛，冻结名单独立 |
| 12.4 | 小王退队，回本人历史，再看旧报名 | 退队不退赛，资格/金额/名单保留；不再看完整队伍详情 |
| 12.5 | 小李转让给仍在队第三位参赛者，双方刷新 | 新旧权限更新，原付款人不因转让变化 |
| 12.6 | 新队长看加入退出记录，小王看本人历史 | 当前/历史区分、结束原因可查；完整时间 DTO 现缺口，别伪造时间 |

**异常检查：** 另用非目标账号打开入队链接，应拒绝且不泄露成员资料。勾选短信后，当前未接通应明确未送达并保留有效邀请；同一邀请不重复生成站内信或无界申请短信。历史邀请可复制链接，不宣称补发成功。重复申请/审批/接受不重复成员；撤申请/拒邀/撤邀后再接受无效。普通成员不能转让/移除他人/解散；队长直接退出有责任限制。解散测试另建专用队伍，旧报名/资金义务应保留，规则阻止时解释原因。赛后新入队者不继承旧成绩/私人证明。

## 第十三步：专用赛事撤回、重新报名、退款与冲正

**先负责人新建“交互测试·撤回收尾赛”**，人工审核、收费（无资金条件先免费测撤回），截止/开始留足时间，发布。小李提交，有资金条件才真实付款并登记，再负责人通过。不要用已报到或关联比赛的主线报名来测合法撤回。

| 顺序 | 使用谁／做什么 | 应该看到什么 |
| --- | --- | --- |
| 13.1 | 小李截止前、全单无人报到无场次，先取消撤回窗，再真正确认 | 取消窗不写；真正整单撤回释放名额，保留历史，不自动退款 |
| 13.2 | 小李用当前资料重新本人确认并提交 | 重新竞争名额/审核、新冻结依据与独立付款义务，旧款不抵新款 |
| 13.3 | 收款人员回原报名看旧款、退款待办 | 新旧义务/流水分开，没退不显示已退款 |
| 13.4 | 确有整笔原款实退才登记整笔已退款；依原政策真实无需退才写原因结案 | 只登记真实事实；计划未完成不结案；系统不会帮你自动退款 |
| 13.5 | 另一个专用真实误确认且满足合法条件的记录，收款人员冲正 | 原记录标冲正不删除；有效实收变化，全单无人报到不足则暂停新报到 |

**异常检查：** 成员/截止后/有报到或场次撤回拒绝，不局部退一个人。旧请求不复活撤回单，精确重放属专项。缺原因无需退款不结案。分次收款/退款按实际金额与时间登记，累计退款不能超过原有效收款；接收人变更须核验依据，已退款原款不能直接撤销错误到账，受控更正仍待专项。已有报到/场次发生资金问题不自动删历史/改判撤证，人工协调。

## 第十四步：新建取消赛，检查两端通知与历史

**先负责人新建“交互测试·取消通知赛”**，在未来窗口，足够名额，免费或有受控资金条件的收费，并发布。小李提交/通过，小王留待确认或已提交；如要测未结资金接收范围，须实际准备该关系，不凭空假设。取消前留截图和编号。

| 顺序 | 使用谁／做什么 | 应该看到什么 |
| --- | --- | --- |
| 14.1 | 负责人先关闭取消窗，再输入原因真取消 | 关闭不写，真正取消不可恢复，不批量伪造拒绝 |
| 14.2 | 访客看详情，小李/小王看本人单 | 原因和取消标记明确，无新报名/普通付款误导，历史保留 |
| 14.3 | 负责人回审核/报到/场次/证明 | 新通过/现场/结果/证明禁止，历史与资金收尾区分 |
| 14.4 | 小李/小王各自我的消息，点跳转、标已读刷新 | 通知本人，同账号去重；持久已读不等于退款/短信回执 |
| 14.5 | 负责人取消通知查渠道、失败原因，明确失败时重试 | 站内信/短信分开；真短信未通应失败/阻塞，不假送达；失败不回滚取消 |
| 14.6 | 确有迟到/误付款时收款人员合法登记收尾 | 不恢复资格/名额，不删历史资金 |

**异常检查：** 重复取消/已读/重试不重复事实或无界发送。未知发送如实待确认；短信取账号当前验证号，不取备注付款人/紧急联系人。要查取消后的赛果证明，需先在另一专用赛事完成第八步再取消，已有私人历史可看标取消，新结果/证明不可建。

## 第十五步：最后一名额、截止、开赛和结束

这些用专用短窗口，别改已正式报名赛事时间。等待真实服务器时间；需要多次等待可隔天继续。

| 顺序 | 按实际顺序准备并操作 | 应该看到什么 |
| --- | --- | --- |
| 15.1 | 负责人新建免费“交互测试·最后名额赛”，容量1发布；两人存草稿 | 草稿/预览不占位 |
| 15.2 | 两人独立会话尽量同时正式提交 | 最多一单成功，另一个满额；人工近同时不代表高并发验收 |
| 15.3 | 合法撤回或拒绝占位者，另一个重提；负责人试降容量 | 释放可重新竞争、不预留；容量不低于占用 |
| 15.4 | 负责人新建“交互测试·短窗口赛”：当前可报名、截止较近、开赛稍后；先发布，两人截止前提交留待审 | 数据必须在截止前准备，不能等结束再造前置状态 |
| 15.5 | 到截止后开赛前，负责人审核；收费条件具备时核对既有有效单付款 | 无新报名；已有单仍可付款/审核，不自动批拒 |
| 15.6 | 留另一单待审到开赛，尝试通过/普通付款 | 不新增通过，普通付款关闭；实际迟到款仍人工收尾，不恢复资格 |
| 15.7 | 另建开赛前已发布再下架的专用赛事，等进行中恢复 | 满足条件可恢复，但不重开报名；无发布历史不能开赛后首次发布，开赛后不能普通下架 |
| 15.8 | 另建短时“交互测试·结束收尾赛”，结束前按主线通过/建场/存草稿，等结束再处理 | 不新报到/建场/通过；允许已有场次结果整理及有依据证明；现 UI 停止分支可能藏入口，记已知实现问题 |

**异常检查：** 结束/取消不能改时间复活；首次正式提交后全部撤回仍锁方式/字段、不能删历史项目。正式报名后改期/换实际场地/人数/费用承诺不能普通编辑解决，需取消另建，不迁名单款项。

## 本轮更新后的专项复测

1. 在同一赛事新建或改名为已存在项目，必须提示重名且不新增；已有正式历史不能改类型/人数或移除。
2. 单打从详情点报名进入草稿，不出现邀请；填本人资料后直接正式提交，应保存当前值，不能代别人确认。
3. 收费提交后看到付款指引和清晰进度；付款通知可选，通知不变成报名成功。
4. 在有真实条件时登记两笔实际到账，例如 40 元再 60 元对应 100 元应付：第一笔通过置灰，足额后才可通过。不要为了点按钮伪造到账。
5. 已拒绝后实际迟到收款照实登记：资格不恢复，逐笔原款可退款收尾。实际退款分两笔，第一次不自动结案；合计超原款拒绝。接收人改变须核验并记录依据。
6. 两个项目分别有获准人员时，切报到项目只显示该项目名单；赛果一方选择胜/负/平自动补另一方，详情与本人正式赛果可查看每局比分。
7. 办赛 Logo 留在 B 端；“返回运动平台”恢复平台身份，再点“办赛工作台”直接进入组织。手机打开侧栏后点外部关闭。

以上为用户继续人工复测的步骤，不表示已真实执行资金或所有普通角色验收。
