# AI运动 · 平台级 UI 信息架构

日期：2026-10-07。版本：V0.2。状态：按用户最新定位生成的平台版原型；品牌视觉、布局及预告形式待评审，未来业务规则/权限尚未定义。

## 1. 定位与范围

AI运动是可扩展的体育服务平台，赛事运营是当前首先落地的业务空间，羽毛球只是一期试点项目。后续还要容纳多种运动与赛制、场馆运营、本地运动生活撮合、体育信息与内容。

用户最新决定优先于首版“羽毛球赛事服务”的首页呈现。当前实际业务仍遵循 [ADR-011](../03-architecture/ADR-011-一期业务收口与交付边界.md)：一期可执行链路仅羽毛球试点，未来服务入口预告不代表新增本期实现承诺。变更记录见 [ADR-012](../03-architecture/ADR-012-UI入口与原型交付.md)补充节。

## 2. 三层结构

| 层级 | C 端 | B 端 | 扩展约束 |
| --- | --- | --- | --- |
| 平台层 | 城市、品牌、通用首页、身份与个人运动记录 | 平台工作台、当前组织、获授权业务空间 | 不绑定某一种运动，不将赛事资格审核等同于所有业务的办理状态 |
| 服务层 | 赛事；后续场馆服务、运动生活/体育信息 | 赛事运营；后续场馆运营、内容与生活服务 | 未来服务按业务独立授权，不因赛事权限自动获得场馆/内容权限 |
| 业务任务层 | 具体赛事发现/详情/报名/资金/赛果；未来服务自己的任务 | 当前赛事配置/名单/资金/执行；未来空间自己的管理任务 | 当前案例仍按羽毛球规则执行，不用单打/双打/比分套全部未来服务 |

赛事、场馆、生活服务和资讯共用平台入口，不合并成一个泛化订单/付款/状态流程。页面和组件可以复用，事实语义、责任主体与权限由各业务规则决定。

## 3. C 端导航与未来入口判断

一级导航采用「首页、赛事、我的参赛、我的」。

- **首页 C00**：运动平台品牌与保定城市站、近期赛事、个人任务快捷入口；场馆/运动生活放在较低的次级服务区。
- **赛事 C01**：统一目录。按运动项目与状态发现赛事，具体赛制与参赛方式由赛事卡和详情说明；目前只有羽毛球能进入试点办理。
- **我的参赛**：聚合本人已有参与关系，本轮以 C07 报名为主，联到队伍及正式赛果/私人证明；后续其他服务记录有对应分区，不挤入一个报名列表。
- **我的**：基础身份与账号、本人消息、必要组织入口，沿现有授权；不建立“运动者”和“运营者”两套账号。

选择次级预告的原因：既能看出平台的长期方向，又避免手机主导航被多个无法办理的栏目占满。体育信息放在“运动生活”愿景中，当前没有内容供给时不创建一屏虚构推荐流或单独资讯主导航。不是已有用户研究结论，仍需结合用户视觉/操作反馈调整。

原型未来入口用 F 编号追踪：F-C01 场馆服务预告、F-C02 运动生活预告、F-B01 场馆运营空间预告、F-B02 内容与生活服务空间预告。F 编号仅为设计追踪，不加入一期可办理页面或权限菜单计数。

## 4. 当前、尚未开放与未知状态

| 状态 | 界面呈现 | 行为 |
| --- | --- | --- |
| 当前试点可体验 | 赛事卡/项目显示羽毛球，保留已确认报名办理 | 原型仍只模拟，不表示真实普通角色业务已验收 |
| 其他运动尚未开放 | 赛事筛选可发现项目方向，显示“本项目尚未开放报名” | 可返回当前可参与项目，无虚构赛事/报名按钮/上线日期 |
| 未来服务规划 | 首页次级入口明确“后续规划”；详情解释方向、尚未开放与返回路径 | 无预约/交易/匹配/内容发布操作，不提供假订阅或收集个人信息 |
| 查询无数据/失败 | 无符合条件和查询失败独立 | 不把未来业务混成加载失败，也不把失败冒充暂未开放 |
| 未获业务授权 | 正式业务空间只按用途授权开放 | 原型规划预览可查看方向，不继承赛事权限或操作能力 |

其他运动的展示样例（跑步、篮球、足球、网球）不是已正式批准的运动目录、开放顺序或实现排期。

## 5. 通用赛事的共用与变化区域

| 区域 | 可共用 | 必须按运动/赛制变化 |
| --- | --- | --- |
| 赛事发现卡 | 名称、运动项目、赛事/活动类型、日期、地点、责任方、开放状态、公开费用依据 | 赛事能力是否已开放，不能凭目录名称宣称可运营 |
| 赛事详情 | 公开责任、时间地点、规则来源、参赛单元、收费/退改、下一步 | 单打/双打/球队/接力/计时组别等名称与人数；材料及专项条件按未来确认规则 |
| 报名办理 | 本人/代表关系、字段确认、冻结依据、窗口/资格/资金分别反馈 | 单人/多成员名单、主替补/分阶段等未来规则，不在当前原型假实现 |
| 执行与结果 | 当前场次/对象、草稿与正式、确认与来源、本人授权 | 对抗比分、时间/距离/试次、裁判评分、晋级/排名等结果结构，不写死为 A/B 胜负 |
| 后台工作区 | 选定赛事上下文、按任务办配置/报名/资金/执行、角色权限 | 可适用工具和字段由能力配置控制；未开放工具不以空壳冒充可用 |

来源参考[业务母版](../99-raw_materials/保定体育综合服务平台_全域业务母版_V1.0.md)第 01、02.4、03、17 章；母版范围不能覆盖 ADR-011 当前一期边界。未来专业规则和流程未确定时，不靠 AI 猜参数构造通用实现。

## 6. 保定元素的强弱分配

用户要求“加强保定，但不要盖住运动”。因此采用以下层级：

1. **明显的城市识别**：页头“保定·城市站”、首页“保定·身边的运动生活”，赛事位置和工作台城市标识。
2. **运动主视觉**：跑道、运动者与多种球类意象占主要面积；主标题强调运动的多种可能，不绑定羽毛球。
3. **城市背景**：亭檐、古城建筑和莲池线稿作为低对比背景，暖灰砖色点缀。不使用政府徽章、景点大照片或观光导航。
4. **本地文案**：“在古城，找到运动的每一种可能”“古城有来处，运动有新意”“熟悉的城市，新的运动相遇”。城市线稿为原创概念插画，不是精确地标复原或官方授权标识。

品牌仍是 AI运动，保定是当前城市站。以后扩展服务或城市时，城市选择区域、文案与背景可替换，赛事/个人任务导航不用重做。当前没有多城市数据或切换操作，只解释保定城市站。

## 7. 原型及实施边界

C 端 [首页](prototype/index.html#home)、赛事 #events、场馆 #future/venues、运动生活 #future/life。B 端 [工作台](prototype/business.html)保留赛事任务，侧栏提供两类后续业务空间的规划预览。

当前 35 个既有 C/B/P 页面编号保留，新增 C00 平台首页视图，补齐 B16/B17 后合计 38 个现行设计逻辑页面。F 系列预告不算现行可办理业务页面。HTML 中新增 platform.js 管理平台发现与预告，共用样式保持一份，正式接入依旧迁入当前 RuoYi 前端。

本轮没有改变当前账号、名额、收费、审核、结果的规则或数据，没有开放其他运动、场馆商业预约、本地撮合或资讯发布业务。后续能力仍按原里程碑/另行业务确认，不因“敬请期待”成为一期必交。细分运营用户模型和未来真实旅程在业务边界确定后再补，不伪造角色权限或用户访谈。

## 8. 办赛服务补齐

首页“我要办赛”、我的 C16 及组织工作台“申请与准入记录”接入 [B 端办赛服务](prototype/organizer.html#apply)。准入前是平台账号侧 B16/B17，不是假定已获得组织管理会话；申请、进度和版本详情有独立页面状态。已准入身份切换直接进入 B02，未准入只能申请/查询。平台超级管理员沿 RuoYi，仅追加 P01/P02 业务审核，本轮不生成其视觉原型。

B16/B17 与赛事运营共用 B 端框架；顶部页面标签用于任务导航，准入前赛事入口受限，任务标签按作用域显示。地图/旅程保留与原型覆盖分开，见 [覆盖检查](UI覆盖与一致性检查.md)。

## 9. 登录入口与 C12 承载

C00 同时是访客入口与无原任务平台登录落点；原任务优先，报名缺档案再引导完善。平台手机号认证页独立于管理员原生 /login，不增加账号体系。注册、恢复保留安全原任务并回登录。C12 固定 C11 历史标签，C10 保留本人历史投影，退出人员不得通过历史恢复完整队伍授权；随队伍页面一起绘制。详见[登录与导航决定](登录与导航设计决定.md)，正式路由改版仍待实施。
