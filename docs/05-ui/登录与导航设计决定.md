# 平台账号入口、登录落点与队伍历史承载

日期：2026-10-07。范围：UI 设计决定与独立 HTML 原型。正式 Vue 登录、路由和后端授权未在本轮修改。依据 ADR-005、ADR-011 及用户提出的七个问题；本文件细化体验，不增加账号类型或业务权限。

## 1. 七个问题的决定

| 问题 | 本轮设计决定 | 正式代码现状 / 实施条件 |
| --- | --- | --- |
| 1 登录后第一屏 | 无原任务的普通平台登录 → C00 通用首页；已有原任务 → 回该任务。本人档案 C05 位于“我的”，不是统一登录落点 | `permission.ts` 的 participantLanding 仍指向本人档案，正式实施须更改；本轮仅原型已改 |
| 2 未登录首页及报名返回 | 未登录打开站点也进 C00，可浏览 C01/C02。点报名才登录；保留 eventId、unitId 和原任务。登录后继续同场同项目填写，缺必要档案则 C05 补齐后返回；重新核验窗口、身份、名额、配置 | 不自动创建报名、占位、提交本人确认、付款或获得资格；原型只有一场固定虚构赛事 |
| 3 C12 | 主承载固定为 C11 队伍详情内“加入/退出记录”标签，不新建一级栏目或独立页面；随 C10/C11 一起画。C10 保留“本人历史关系”摘要及按队伍筛选的本人记录投影 | 已退出人员不能借历史入口重新查看完整队伍详情。当前 `team.vue` 已有本人历史关系列表，保留；当前/历史成员分开，具体字段按现有契约和授权，不臆造全队历史查询 |
| 4 共用 /login | 界面分开：运动者、队长、办赛负责人共用平台手机号入口；平台管理员使用原生 /login 用户名入口。仍是一个 plus-ui 工程及已有认证服务 | 不新增独立参赛者账户，不允许组织映射用户单独密码登录；平台账号进入组织仍由服务端授权换取组织会话 |
| 5 登录页元素 | C 端移除租户下拉、五个社交登录、记住密码开关、语言切换和若依版权页脚。保留按服务端配置实际启用的安全验证码、注册和忘记密码。页脚使用 AI运动、保定城市站 | 不新增短信登录、微信登录或其他社交登录；保留仓库必要许可证/来源声明，不把 UI 页脚调整解释为删除授权声明。管理员页继续若依原生布局及实际配置 |
| 6 输入框 | C 端手机号 / 密码均为空，占位“请输入手机号”“请输入密码”。管理员在 /login 输入用户名，不在同一框内猜测手机号或用户名认证类型 | 所有入口不得预填管理员凭据；密码、验证码和 token 不用于持久化草稿，不复用现有 rememberMe 的明文密码缓存 |
| 7 注册后返回 | 标题“注册”，说明同一平台账号可以参赛、加入队伍、申请办赛。注册成功 → C03 登录，保留安全原目标；不自动登录。密码恢复成功也回登录并保留目标 | 恢复密码继续现有撤销平台及关联组织会话规则。手机号证明不等于实名、赛事资格或办赛准入 |

这些均可按现有业务与用户独立 C 端要求决定，无需增加待确认业务问题。实际短信供应商及验证码验签的外部条件继续按最新清单处理，不用模拟结果关闭这些缺口。

2026-10-09：登录图形验证码按已有 `captcha.enable=false` 关闭。参赛者 `/portal/login` 和管理员 `/login` 都随 `/auth/code` 的 `captchaEnabled` 显示；关闭时去掉必填校验，服务端密码登录和平台登录也不再校验图形码。短信验证码、密码校验和登录失败锁定保持。该开关同时让发短信前的图形码不再生成，阿里云人机验证配置未改。

## 2. 原任务与安全返回

1. 无原任务、目标为空或非法 → C00。登录页“注册 / 忘记密码 / 返回登录”全链路保留相同目标。
2. 仅接受经过路由白名单验证的站内业务目标；拒绝外部地址、协议相对地址、脚本、路径穿越、管理后台地址等。只保存恢复所需的赛事、项目、邀请 / 队伍对象标识；不把 token、密码、手机号、材料或任意查询参数复制到目标。
3. 返回前重新获取登录者和目标的服务端授权 / 最新业务状态。原赛事取消、下架、截止、满额、邀请失效、账号不匹配等应给原任务的明确反馈，不能以登录成功绕过校验；下架不阻止按授权查看本人既有报名。
4. 报名 / 入队的本人档案前置仅在这些操作要求时出现；普通浏览、账号管理和办赛申请不被档案强制阻断。选填字段不得变为统一必填。
5. 会话失效保留安全任务并重新登录。登录返回不是自动重放敏感写操作，任何提交 / 撤回 / 资金确认继续由本人明确操作。

## 3. 目标路由与 HTML 承载

| 逻辑页面 | 正式 Vue 目标（待实现） | 本轮 HTML 原型 |
| --- | --- | --- |
| C00 | `/portal/home`；站点 `/` 的公开默认入口指向这里 | `index.html#home`，访客与已登录不同顶栏 |
| C03 登录 | `/portal/login`，独立于后台 Layout | `index.html#login?returnTo=…` |
| C03 注册 | `/portal/register` | `index.html#signup?returnTo=…`；`#register` 仍表示赛事报名，不混用 |
| C04 恢复 | `/portal/forgot` | `index.html#forgot?returnTo=…` |
| C05 前置 | 复用 `/portal/identity`，按任务返回 | `index.html#identity?returnTo=…` 仅展示固定虚构档案和前置返回，不替代完整编辑设计 |
| 平台管理登录 | `/login`；无原管理任务默认 `/index` | `#admin-entry` 只说明原生入口，不模拟管理员登录 |
| C12 | C11 `teams/:id` 历史标签；C10 本人历史投影 | 本轮只定承载，未画历史标签 / 完整队伍界面 |

`/portal` 现有受保护业务路由不能整体加入匿名白名单，只逐个开放上述公共页面。旧 `/register`、`/forgot` 可作为兼容别名跳转新平台入口，并传递经验证的目标；已知旧 `/forgot` 当前未在匿名白名单中，实施时一并修复。旧 `/login?redirect=…` 的参赛者深链需迁移 / 导流到平台入口；管理员合法后台深链仍由后台入口处理，禁止平台入口把任意管理页当普通返回目标。

## 4. 演示与验证边界

原型 `auth.js` 在 sessionStorage 只存登录、档案场景、新账号三个布尔标记；不存输入手机号、密码、验证码、身份材料或真实令牌，不调用真实 API。可用虚构号码 `13900000000`、任意符合现有格式的虚构密码体验；安全验证为明确标注的模拟按钮，短信验证码演示值 `123456`，没有发送短信。注册和恢复使用独立页面流程；正式验证码必须沿既有服务端用途隔离与限频规则，不能照搬本地演示码。

原型覆盖：公开首页、匿名保护、普通登录 / 任务返回、同场同项目报名恢复、注册 / 恢复上下文、缺档案前置、密码显隐、基本错误 / 过期 / 频率提示、短信重试倒计时、退出登录、非法返回目标过滤、办赛入口返回及移动布局。C05 完整编辑、C10/C11/C12、真实会话撤销、授权及接口状态仍未由此验收。

正式实施提示词见 [Cursor 前端登录与导航实施提示词](Cursor-前端登录与导航实施提示词.md)。浏览器实际检查及证据以本轮 `prototype/previews/verification.json` 和交接记录为准，不把模拟通过当业务验收。

本轮实际验证（2026-10-07）：原有 112 项回归加 43 项账号 / 返回 / 响应式检查，合计 155 项通过、0 浏览器脚本异常。登记 41 张截图（本轮新增 auth/ 下 9 张）；其中 review-before/ 四张为已保留的历史基线，未冒充本轮重拍。新认证页移动首屏已检查注册 / 恢复入口可见并移除固定底栏。项目静态规范检查通过，13 份 UI / ADR 文档链接和 38 个现行逻辑页面覆盖核对通过。
