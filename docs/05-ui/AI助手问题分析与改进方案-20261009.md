# AI助手问题分析与改进方案

日期：2026-10-09。状态：依据用户十项反馈形成的待评审方案，未实施、不表示新业务规则已批准。遵循ADR-011与ADR-019；不扩展为完整Agent平台。证据为当前源码静态阅读，未复现用户具体会话或核对其赛事数据与运行包。

接续：用户随后授权开始修改，已实施范围见[ADR-020](../03-architecture/ADR-020-AI助手目标分流与草稿就绪反馈.md)与交接最新记录。下文保留提案当时边界，不将所有提议自动标为实现或真实验收完成。

## 判断

核心是现有会话编排、业务上下文与校验反馈需要局部架构调整，叠加提示词、UI与宣传设计问题。当前没有证据支持先做模型权重微调，也不需要更换模块化单体或另建多Agent平台。

已核实：BusinessAssistant.send通过包含“办赛”等关键词的正则直接开启文字创建任务；现有任务讨论优先于运营咨询。“这个办赛还欠缺哪些信息吗”可被当作新规程。正确进入运营咨询时原代码会传选中eventId，不能概括为整个助手完全没有赛事上下文。kernel.SYSTEM明确要求回答或修改后不要逐项点名未填内容，与用户需要下一步引导冲突。discuss请求仅含任务、草稿、历史和消息，没有当前日期/时区；validateStored主要检查结构和枚举，未与最终创建校验对齐。ConsumerAssistant使用文本插值。BusinessAssistant把草稿组件排在全部对话后，outside监听没有对放大模式排除。具体突然关闭原因仍需复现。posterSheet固定绘制两个圆圈与信息框，宣传不调用生图。最新AI确认调用placeUnpricedUnit，免费现象需查旧任务、实际收费版本、运行包与显示映射。

## 十项处理

| 用户反馈 | 层级 | 拟处理 |
| --- | --- | --- |
| 1 当前赛事缺项被当规程 | 会话编排/上下文 | 去掉以关键词决定创建的前端分流；服务端绑定当前授权赛事/项目、草稿与当前任务。模型判断咨询/查缺项/修改/新建/宣传等意图；服务端校验目标与可用动作。只问缺项不创建任务，不把用户问题保存成规程 |
| 2 Markdown未渲染 | 展示 | 双端共用安全Markdown组件，支持段落、标题、列表、强调、表格、代码块；禁原始HTML/脚本及危险链接，来源卡片由服务端事实独立生成 |
| 3 草稿阻挡历史 | 交互 | 对话区与草稿面板分离，顶部显示赛事/任务和状态；桌面放大后右侧可折叠草稿，小窗/手机用“对话、草稿”切换。消息只显示本次变更与下一步；回看历史不强制滚底 |
| 4 放大后关闭 | 交互状态 | 放大模式仅显式关闭/收起，不由外部点击收起；小窗保留既有窗外收起。弹层、拖动结束与焦点处理单独检查；关闭保留输入/任务，不取消请求 |
| 5 选择后没有下一步 | 工作流/提示词 | 每次有效修改后重新获取业务就绪结果；回答“改了什么、还阻塞什么、下一步”。区分保存草稿、发布、开放报名，不让模型自己声明可创建 |
| 6 名额含义不清 | 业务校验契约 | 错误关联具体项目、名称、计量单位和修复动作。单打按组/报名单位解释对应1人，双打对应2人；名额是报名单数，不是总人数。不能猜名额 |
| 7 结束错误没有依据 | 校验契约 | 返回错误代码、实际结束时间、当前服务器时间、时区与可执行修复；说明结束时间早于或等于当前时间，不写成晚于。已发布/有历史赛事保留原重大变更限制 |
| 8 建议仍是过去日期 | 时间上下文/确定性校验 | 每轮由服务端注入currentTime与Asia/Shanghai，比较使用服务器Clock。用户授权推荐时程序计算未来候选日期，模型解释；同时检查报名起止/比赛起止关系。不能保证场地和人员有空，候选不伪装确认事实 |
| 9 收费原文却生成免费 | 事实到配置契约 | 缺配置展示“费用待配置”，不映射成免费；保留收费原文与来源，生成待确认收费候选。正式免费/收费沿既有授权与人工核对，不能自动生效。首项198元/人/项、加项100元/人/项涉及跨项目计价，不能将所有项目统一为198或100，不能伪装既有固定整单版本已支持 |
| 10 宣传缺吸引力 | 内容与视觉产出 | 输入受众、渠道、真实卖点与风格；输出多个短标题、群邀请和朋友圈短句，事实缺失不补造。制作原创竞技/青少年/社区三类版式；主视觉可用组织素材、授权素材或受控生图，赛事文字和二维码由程序排版 |

## 最小架构调整

保留Vue→Java业务层→Node模型层。前端不拥有业务意图和资格判断：发送消息、选中对象与会话编号；Java重新授权并加载当前事实，附对象版本、来源及当前时间；模型只建议意图、候选修改和回答；Java限制目标/动作，复用原规则做就绪检查。低置信度、当前赛事与未保存草稿目标冲突时先澄清，不默认创建。模型失效时可通过原页面及缺项清单继续办理。

建议统一返回目标对象、拟修改差异、就绪结果和下一步动作。就绪结果分别提供canSaveDraft/canPublish/canOpenRegistration、blockingIssues和建议事项；每个问题包含代码、项目/赛事关联、当前值、规则依据及修复入口。公共校验逻辑与最终事务复用，最终写入前重新检查，不能把一次预检当提交成功。传模型的事实按用途最小化，页面DOM不是授权事实；金额、名额和日期不以模型文本作为权威。

办赛草稿需要明确区分：AI候选尚未写正式赛事、正式赛事草稿已保存、发布条件未满足、报名条件未满足。已保存当前赛事的缺项诊断不能套用新建候选流程。意图切换不抛弃已有草稿，也不能让未保存草稿绑架所有后续提问。

同意项固定靠近输入框，未同意时引导勾选，避免每次快捷点击都追加同一句聊天。模型同意按原账号/组织/上下文边界管理，不跨身份自动沿用。

## 收费范围需特别处理

“198元/人/项，加项100元/人/项”可以抽取并展示为原文候选，但跨项目首项/加项顺序、撤回重提、同一人并发报项与原独立付款义务的关系必须另行形成业务决定。短期方案保留待配置和人工明确既有可支持价格；不为了通过创建而改成免费。若用户要求自动落成差异计价，应另做ADR、模型/迁移、事务与专门验收，不能作为本轮提示词小修直接上线。小程序/对公付款也只能表示来源提及，不表示本平台已经接入相应通道。

## 宣传参考与产出

不需要用户先提供海报即可研究和原创设计。已检索可参考的作者项目[UAP Open羽毛球赛事视觉](https://www.behance.net/gallery/219662209/Visual-Identity-for-the-Badminton-Tournament-UAP-Open)与[Canva体育海报模板](https://www.canva.com/posters/templates/sports/)。本轮仅检索参考，不称已逐张评价或获得素材使用权。参考构图、层级和运动感，生成原创建议版；组织Logo、真实球场/选手照片和喜欢的样例可选提供。不要原样搬用网上海报或冒用名人/主办方素材。

内容采用“参与价值→可信卖点→关键事实→报名行动”，分别适配群/朋友圈/印刷海报。不编造奖励、认证、报名热度或稀缺名额，不承诺转化效果。主视觉先用原创版式和可用素材；应用内生图接入属于现有ADR-017未开启能力的扩展，应明确外部图像服务/成本与素材生命周期后实施。中文、时间、费用、报名链接和二维码继续用真实配置叠加，生成后验证小屏可读性、长标题/多项目溢出和二维码扫描。现有导出PDF为位图封装，精细印刷能力须单独验证。

## 实施顺序与验证

第一批：修意图分流/目标绑定、当前日期、统一预检与明确错误、免费兜底、后续动作。最高优先级是错误对象和错误业务事实。第二批：共用Markdown、独立草稿面板、放大关闭、同意提示与滚动状态。第三批：宣传内容与三套真实可导出版式；差异计价或应用生图扩展另按批准范围推进。

验收使用用户十项会话作为固定样本：当前赛事问缺项不得新建任务；无审核之后指出可执行下一步；每个项目缺名额分别提示；服务器日期固定2026-10-09时不得推荐7月；过期时间同时显示依据；198/100必须保留原文且不得免费落库；新对话/旧草稿/当前赛事切换不串对象；放大/选择弹层/拖动不误关；历史滚动不跳底；Markdown显示与危险链接处理；不同渠道宣传有内容差异，真实金额/二维码/导出验证。模型模拟、服务端确定性测试、真实授权角色与受控模型评测分开记录。不得用模型评价自己的回答代替验收。
