## 本轮新增体验：先用这几条路线测试

1. **登录、资料与头像：**从需要本人身份的页面进入登录，完成后应回到原任务。在「我的 → 完善资料」的 [个人资料页](http://127.0.0.1:5192/portal/profile) 点击「上传我的头像」，选择 5MB 以内 JPG/PNG/WebP，裁剪、旋转并保存；取消裁剪不上传、不改变原头像。成长页和房间提供返回资料页的入口，头像上传集中在资料页。返回房间应看到本人新头像，个人称号仍在头像上方。昵称、签名和公开范围在运动名片中维护；关闭公开后原分享地址无法读取。
2. **双打房间：**C 与 D 的已验收房间为 [双打交互验收房间](http://127.0.0.1:5192/portal/rooms/2109094962015641600)，两人已各自确认准备，尚未生成报名。可先查看状态，再通过本人会话取消/恢复自己的准备；另一人的状态不应跟着改变。不要把原演练起点当作空白环境重复生成同一事实。
3. **策划、脚本、公告、宣传：**A 进入主办方 → 赛事管理 →「Ui试用 · 羽毛球报名演练（模拟）」→「策划与文稿」。四类文稿独立保存。勾选必要信息用于 DeepSeek 后可真实生成；也可用明确标记的基础模板或手工填写。先保存再生成新稿；切换类型或离开时有未保存提醒。正文最多 10,000 字，支持编辑预览、历史载入、复制和 Markdown 下载。保存不会自动发布公告或向别人发送消息。
4. **赛事封面：**在同一赛事卡片点击「更换封面」。上传图片或选择「使用平台运动视觉」，预览后点「保存封面」，再打开公开页面核对。推荐 1600×900，JPEG/PNG/WebP，最大 5MB。AI 图片服务未配置时明确提示，现有封面与文稿仍保留；本轮开发生成的静态素材不算用户实时 AI 生图。
5. **政府与平台：**分别使用工作账号。政府在本人授权范围搜索主办方、查看资格与待审核材料；平台可搜索表对象、查看字段和能力开放情况。两类账号不替代主办方，也不能获取私人头像或参赛材料。
6. **首页与赛事筛选：**首页五个运动插画入口分别进入「我的报名、找队友、我的小队、成长与荣誉、赛果与证明」。点击「招募与匹配」查看房间；查看赛事是明确主操作，登录为较轻的次操作。首页近期赛事及 [赛事目录](http://127.0.0.1:5192/public/events) 用一行名称、运动项目、赛事状态筛选；下拉为浅色浮层，可用方向键、Enter选中，Escape或点击外部关闭。试一个不存在的名称，再清除筛选，应恢复真实列表。输入焦点使用中性提示，必填错误仍保留红边。不要把主站暂无公开赛事当成丢失演练数据。
7. **浮动体育助手：**点右下角小球打开窗口，拖动小球可移到更合适的位置；拖动应只移动，不误打开或拖出一张大图。小球可用方向键每次移动20px，刷新应保留位置，小屏自动收回屏幕内。窗口顶部可拖动，右下角可实际拖拽调整大小，也可放大、缩小、关闭。输入默认空；点任务卡只选择可取消的主题，不填固定长指令，已有本人草稿保留。写下自己的需求再发送，不发送不应调用模型。打开段位预览或未保存确认时，助手暂时隐藏，关闭业务弹窗后应恢复原输入与任务。关闭重开保留未发送内容，登录和注册页不显示浮泡。手机查看窗口是否留在屏幕内、聊天独立滚动及输入区可用。

本轮有真实模型、上传和匹配界面验证，新增真实隔离认证与弹窗边界补验；真实收款、退款、现场比赛及业务短信仍按后文流程另行验收。当前证据见[浮泡交互与传奇荣誉认证验证](../04-verification/浮泡交互与传奇荣誉认证验证-20261011.md)，第一轮见[正式产品界面与创作功能验证](../04-verification/正式产品界面与创作功能验证-20261011.md)。

## 4. 逐步操作与预期结果

下表是用户测试步骤；本轮仅验了账号入口及新赛事准备，不能把“预期结果”当成这场新赛事已经执行通过。

| 步骤 | 操作角色与动作 | 应看到的结果 | 记录什么 |
| --- | --- | --- | --- |
| 01 浏览与回跳 | 未登录打开新赛事，选择双打并继续；需要登录时用 C 登录 | 登录完成返回原赛事 / 项目，明确显示比赛时间、人数、名额及费用 | 回到哪一页；之前选择是否保留 |
| 02 本人档案 | C、D 各自进入个人档案核对模拟身份；不填真实证件 | 昵称与参赛资料分开；必要资料缺失时指出具体字段 | 缺项名称和补完后的返回任务 |
| 03 长期小队 | C 创建新的长期小队，邀请 D；D 本人接受 | 队长属于成员池；同一用户可以有多个小队，长期小队不等于本场两人名单 | 小队编号、成员数、邀请状态 |
| 04 本场房间 | C 从双打项目创建“试用双打一队” | 房主 C 已占 1 个席位，显示 1/2，不占正式赛事报名名额 | 房间编号、人数、名额余量 |
| 05 招募补员 | C 发布队友招募；D 查看该项目招募并申请加入；C 回应接受 | 申请未确认前不直接入房；确认后变为 2/2，再申请不能超员 | 谁申请、谁确认及显示反馈 |
| 06 自动匹配（另一组） | E、F 进入同一双打项目，分别自动匹配，双方接受 | 同赛事、项目与时间偏好兼容；收到邀请；本人接受后才入房，房主也计入人数 | 邀请时间、双方确认、实际房间 |
| 07 拒绝与超时 | 另一次匹配时选择拒绝，或等待默认 120 秒不接受；随后取消仍在排队的请求 | 未形成已确认两人房间；过期邀请不能接受，释放匹配席位 | 超时前后状态；是否能再次匹配 |
| 08 成员准备 | C、D 分别在本人会话确认准备 | 两个准备状态分开；C 不应代 D 确认；双方准备后可准备报名 | 席位和准备标记 |
| 09 资料和声明 | 房主准备报名后，C、D 各自填写本人字段、阅读声明并确认 | 管理人能看缺项；本人未确认时不能完成整单提交；没有代签 | 缺项提示、声明文字 / 图片是否可读 |
| 10 正式提交 | 管理人核对赛事、两人名单、规则和 100 元，再确认提交 | 整单冻结名单与费用，占 1 组名额；出现付款义务；连续点击不会创建第二单 | 报名编号、费用、剩余名额、提交反馈 |
| 11 部分收款 | A 在主办方 → 赛事 → 报名中打开具体单；核对演练说明后登记 40 元模拟到账 | 保留具体记录；净实收 40，尚欠 60；收费资格不能因上传图片或声明付款而直接通过 | 付款义务编号、实收、欠款、资格状态 |
| 12 足额与审核 | A 再登记 60 元模拟到账，然后根据资料完成资格审核 | 两笔到账留痕，合计 100；人工审核通过后报名资格通过；免费单分支不要求付款 | 两笔记录与资格变化 |
| 13 免费单打 | E 从单打项目本人报名、声明和提交；A 核对后办理审核 | 一人名单、免费分支、独立名额；不要求双打房间或真实付款 | 免费状态与单人名单 |
| 14 赛前通知 | A 从赛事通知入口选择受影响人员并填写演练通知 | 站内消息按对象范围可查询；仅把确有回执的渠道算已发送 | 消息编号；短信的供应商回执或未验证原因 |
| 15 逐人报到 | 在符合赛事窗口的现场演练中，A 为实际到场成员逐人报到 | 同单两个成员分别处理；真实报到里程碑每人每赛事只发一次 10 分 | 报到时间、成员、成长事实 |
| 16 对阵和场次 | A 人工安排有效报名组对阵，选择可用时间及球场 | 时间 / 人员 / 资源冲突明确拒绝；手机能看到每场的操作 | 对阵双方、场地、时间；冲突原因 |
| 17 正式结果 | A 录入、核对并提交一场有效比赛结果；不得把未赛事实当完赛 | 草稿与正式结果明确；有效完赛每人每赛事增加 30 分，不重复发分 | 结果版本、胜负、比分、成长增量 |
| 18 奖项与证明 | A 依据正式赛果或明确裁定办理奖项；参赛者查看本人证明和战绩卡 | 获奖依据可查；证明私有；分享卡含生成时间与最新状态入口 | 奖项依据、证明编号、保存效果 |
| 19 更正与撤销 | 在另一演练样本中更正结果或撤销无效结果，再复核受影响奖项 / 证明 | 原版本保留；成长以追加调整留痕；旧证明状态变化，新证明独立签发 | 新旧结果、成长调整及证明版本 |
| 20 问题与收尾 | 参赛者投诉并补充；主办方回复；政府在范围内协调；处理后进入赛事收尾 | 有编号、责任、回复、重开历史；比赛结束、资金收尾、问题处理分别显示；未结款或未结问题不能假称全部结束 | 投诉编号、未完成责任、最终收尾状态 |

## 5. 入驻与政府资格管理

2. 平台管理员在“平台管理 → 政府责任分配”将这件具体申请分配给 `phase1-government`。分配前，普通政府不应能办理或读取未授权申请。
3. 普通政府从“入驻审核”查看本人被分配的申请。先试补正 / 不通过并说明缺什么；申请者应看到说明并修改重提；再审核通过。
4. 平台按这件主办方明确授予资格管理、必要汇总与投诉协调范围。普通政府不能自己扩权。
5. 获批申请者重新进入主办方工作台。政府填写依据暂停其资格，申请者再尝试新增办赛 / 新增报名活动，应该被拒绝；历史查询、退款和投诉处理继续可办。
6. 恢复资格并核对新操作是否重新允许，保留暂停与恢复记录。

暂停资格测试优先使用新模拟组织，避免中途影响其他人正在体验的 A 组织。任何暂停都要把恢复作为同一测试的收尾步骤。此段为待人工试用流程，不能用 `admin` 的可见范围替代普通政府结果。
