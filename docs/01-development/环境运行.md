## 一期部署与运营待落实

测试/生产分别部署应用、PG、Redis、文件、凭据、地址和短信发送配置，不复用真实个人数据/收款码进行无隔离测试；同机容器不宣称完整物理隔离。生产主机/域名待确定，当前只操作 aisports-dev-*，不直接发布 local/模拟验证码配置。

上线前确定数据库/文件/必要配置的备份频率、保留周期、存放位置及失败监测；以简单工具/计划任务实现，不建备份平台。至少一次隔离恢复演练核对报名、资金、成绩和文件、恢复耗时/可恢复时间点，重新应用注销/删除限制，再确认可接受数据损失及停机范围。本轮未执行备份/恢复或配置真实生产参数。

交接核对实际反馈渠道及账号核验/资金/通知失败/恢复责任（可兼任）、分类资料期限/清理责任、供应商主体/签名/双类模板和受控真实短信、普通角色试运行证据。自助注销可暂不开放但平台需受理；具备实际证据后决定公众开放。

## 首次初始化及日常运行

根目录运行 `./scripts/Initialize-Environment.ps1 -Start`：生成忽略的 `.env`、Redis 配置、应用角色 SQL 和前端本地覆盖；通过 Docker CLI 拉取镜像、启动 Compose、验证数据库与 Redis。

空 PostgreSQL 数据卷按照 10-框架、20-工作流、90-应用角色顺序初始化。上游 PostgreSQL 脚本保留原文，不执行 MySQL 脚本。框架初始化已完成时不可盲目重跑框架脚本。`local` 和 `docker` 配置下，后端启动时由 Spring Boot 调用 Flyway 11.7.2，用数据库所有者连接执行打进包内的 `database/migrations/`。业务连接池仍是 `aisports_app`。`dev` 和 `prod` 不打开 Flyway。账本是 `flyway_schema_history`。容器健康只证明服务可连。`Test-Infrastructure.ps1` 仍可用独立 Flyway 容器做 `validate`。表列数量以 `database/verification/preparation.sql` 为准，不是 `catalog.py` 的目标模型。

现有数据卷启动不会重跑初始化。已经有业务表但没有 Flyway 账本的库会拒绝迁移，删除本项目数据卷后重建。以后的变化另写新版本，不改这三份基线。新迁移文件不要写 `BEGIN`/`COMMIT`，由 Flyway 包在事务里执行。占位符替换和 `clean` 都关闭。只允许运行一个迁移任务，禁止依靠 compose 重启升级数据库。

历史 M1.1 入口为 `./scripts/Initialize-M11Data.ps1`。它只补齐初始化登录，不能当作清空测试数据的命令。

要清空本机业务测试数据，运行 `./scripts/Reset-TestData.ps1`。它只连接 `aisports-dev-postgres` 和 `aisports-dev-redis`。表结构、迁移记录、框架租户和框架自带账号保留；文档中的试用登录保留账号，档案和业务记录去掉。办赛时生成的组织租户一并删除。这个入口会删掉当前库里的赛事、报名、队伍和资金，只用于本机开发库。

要补一组不用真实手机号注册的参赛登录，运行 `./scripts/Add-LocalTrialAccounts.ps1`。它只连接 `aisports-dev-postgres`，写入 `13100000001` 至 `13100000010`。登录入口是 `/portal/login`，密码用下文的本地试用口令。脚本不建参赛档案，登录后仍要在资料登记里填写。同一手机号已经绑定过的账号会保留，不改密码。清空测试数据会删掉这 10 个号，需要时再运行本脚本。

停止服务用 `docker compose stop`，恢复用 `docker compose start`。不要执行带 `-v` 的清理命令。备份 `.env` 与数据卷；丢失凭据时采用授权恢复流程，不能重新生成秘密后假定已有库同步改密。

后端：

```powershell
./scripts/Start-Backend.ps1 -JavaHome 'D:/Code/Lib/Java/jdk-17.0.12' -MavenCommand 'D:/Code/Lib/Java/apache-maven-3.9.12/bin/mvn.cmd'
```

启动脚本导入 `.env`，首次构建 `-Plocal -pl ruoyi-admin -am package`，之后启动已有 JAR。源码改变使用 `-Rebuild`，避免运行旧构建；Windows下需先停止运行实例以释放JAR文件。local 配置第二个 YAML 文档覆盖导入的 dev 值：PostgreSQL 驱动、隔离 Redis 前缀、随机 JWT、禁用 SnailJob 和远程监控、仅本机绑定、前后端均关闭 API 加密、保留工作流后端并关闭设计 UI。生产环境需要单独配置，不可直接发布 local 配置。

前端：

```powershell
./scripts/Start-Frontend.ps1 -NodeHome 'C:/Users/zyt/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin' -PnpmCommand 'C:/Users/zyt/.cache/codex-runtimes/codex-primary-runtime/dependencies/bin/fallback/pnpm.cmd'
```

Vite 开发监听 `0.0.0.0`、固定 5173（占用时报错），代理 `/dev-api` 到本机 8080。局域网设备访问 `http://电脑局域网IP:5173/portal/home`，接口同源走前端代理，不需要开放后端、数据库或Redis端口。局域网地址是普通 http，浏览器不提供 `crypto.randomUUID`；幂等请求键改由 `plus-ui/src/utils/requestKey.ts` 生成。可在 `.env.development.local` 设置 `VITE_APP_HOST=127.0.0.1` 恢复只监听本机。`pnpm-workspace.yaml` 只允许 esbuild 与 @parcel/watcher 执行安装脚本，并保留 quill 版本覆盖；首次形成锁文件后日常使用 `--frozen-lockfile`。[pnpm 11 配置来源](https://github.com/pnpm/pnpm.io/blob/main/blog/releases/11.0.md)。

本轮准备后已后台启动前后端，默认MCP关闭。2026-10-09 起 `captcha.enable` 为 false，登录图形验证码关闭；短信验证码和登录失败锁定仍按原配置。两个启动脚本的 `-Background` 使用隐藏窗口并记录 `.local/backend.pid` / `.local/frontend.pid`；`./scripts/Stop-LocalApps.ps1` 核验命令行属于本工作区后停止已记录进程，支持 `-Backend` 或 `-Frontend`。前台终端进程使用 Ctrl+C。此入口不停止数据库容器。

默认关闭时 `/mcp` 没有映射，上游异常处理返回 HTTP200、业务码404；这是框架已有错误封装，不是JSON-RPC成功结果。实际HTTP烟测入口 `Test-BackendHttp.ps1` / `Test-GeneratorHttp.ps1` 接受用户名与密码参数，要求专用本机实例临时MCP开启/验证码关闭；执行后恢复默认设置。测试不打印令牌，生成器导入元数据在finally清理，上游详情GET的重复提交冷却由脚本遵守。

## 验证与配置保护

腾讯云注册短信：在未跟踪 `.env` 配置 `.env.example` 所列 `TENCENT_SMS_*`，显式开启 `TENCENT_SMS_ENABLED=true`，保持 `PARTICIPANT_SMS_ECHO_CODE=false`，重启后端生效。已有签名和模板只对应注册，不能用于密码重置、注销或业务通知。所有环境共享环境绑定，凭据不进入源码。隔离验证选 `TencentRegistrationSmsSenderTest,ParticipantRegistrationSmsTest`；真实供应商验证通过 `scripts/Test-RegistrationSms.ps1 -Phone <已授权号码> -SendRealSms` 显式执行，会发一条短信并只记录受理结果，不创建账号、不写可注册验证码。收到短信和注册页完整办理需另行核对，见 ADR-024。

模型：`python scripts/generate-model.py --check`；生成目标为当前DDL、JSON目录与字典，历史V001不覆盖。数据库：`./scripts/Test-Infrastructure.ps1`，测试数据全部回滚。

后端在 `backend/` 执行：

```powershell
mvn -Plocal -pl ruoyi-admin -am -DskipTests=false '-Dtest=GeneratorPreparationTest,McpAuthenticationFilterTest,McpAccessTest' -Dsurefire.failIfNoSpecifiedTests=false package
```

上游默认跳过测试，并按 profile 过滤 JUnit Tag；新增准备测试标记 `@Tag("local")`，上述命令明确启用。前端在 `plus-ui/` 执行 `pnpm run check`，先构建以生成上游 auto-import/components 声明，再执行完整类型检查；已运行 Vite 后可单独 `pnpm run typecheck`。实际结果以交接记录为准，不以命令存在宣称通过。

框架自带管理员与示例组织不是公众平台业务种子。生产前删除演示数据、轮换后台初始密码、JWT 和其他上游示例密钥；公众账号、收款与外部认证待后续配置与开发。不得把管理员演示作为 TC 业务验收。

本地试用约定：手工创建的平台账号和登录密码都用 `123456`。已有试用号 `13000000000` 也是这个密码。这只用于本机开发，不是生产口令。
