# 新增需求可行性与快速迭代评估

日期：2026-10-08。性质：评估与建议，未冻结新增开发范围，未承诺交付日期。

恢复说明：按本次聊天中此前形成的评估内容重新生成，保留当时的范围、假设和证据边界。本次恢复不表示重新审计最新代码或重新验证商业、模型及业务效果。

## 1. 结论与依据

依据用户附件《保定AI体育平台需求与产品设想汇总_V0.1》、[文档入口](../README.md)、[交接记录](交接记录.md)、[ADR-011](../03-architecture/ADR-011-一期业务收口与交付边界.md)、[一期清单](一期未完成事项.md)、母版第 00—02 章及此前核对的赛事契约、C 端首页。

需求总体在技术上可行，但混合了业务工具、AI 辅助、用户关系、内容运营和商业交易五类不同建设任务。当前宜以真实赛事为入口，先交付 AI 办赛和推广两个可操作场景，再扩展协会留存和参赛发现。完整社区、平台竞技评级、学习型推荐和文旅交易不适合同时纳入一周迭代。

此前评估时，仓库已有正式 B/C 界面、组织准入、赛事创建/发布、报名、队伍、人工资金、报到、录分和证明基础。现有首页真实读取公开赛事，更多服务明确为预告；已有页面不能证明新增 AI、协会关注、会员、推荐和出行交易已经实现。此前为文档和局部源码评估，没有执行浏览器或真实角色办理。

附件记载 10 月 15 日目标，距评估日期约一周。该目标应进一步区分内部交互演示、受控试运行和正式运营；日期不是完成证据。原母版产品 AI 后置；附件体现了新增 AI 意图，本评估提出增量建议，但不把附件全部方向自动变成一期承诺。

商业上，赛事供给、用户参与、内容增长和商业服务链条具有逻辑关联，但组织复办、用户留存、客户付费和商家转化尚须真实验证。优先验证组织是否愿意为节省办赛和推广时间的工具或服务付费；赛事报名费不能直接认作平台收入，点击不能认作成交。

## 3. 第一批应当让用户实际操作什么

### 3.1 资料生成赛事草稿

进入现有组织赛事页，点击“从资料创建”，上传获准使用的规程。左侧显示来源文本，右侧显示候选字段及对应来源；缺失内容留空、冲突展示多候选，允许修改与重新识别。无法定位来源的内容标为建议，不以模型置信度当作真实证据。

第一版限定现有羽毛球模型可承接的赛事名称、时间、地点、运动项目说明、公开收费说明和规程正文。组别、容量、实际收费版本、收款主体与退改政策分别确认，不从一段收费描述直接启用收费报名。文件内容作为业务输入，不能改变权限或调用策略。

用户确认后调用现有创建接口保存草稿，继续现有配置和发布流程。已提交过报名的赛事不允许通过自然语言绕过配置锁定或重大变更限制。验证文件实际类型、组织归属和用途；新增资料解析须扩展合法上传契约，不能借用收款码用途。失败可重试或转为手动填写，不丢用户已修改内容。仅上传与办赛有关的获准资料，不默认把报名个人材料发给模型服务。

### 3.2 多渠道推广内容

在已有赛事工作区增加推广入口，选渠道、语气和目标受众后生成标题、正文、报名引导及短视频脚本。结果以可编辑卡片展示，提供复制、再生成和保存。

价格、时间、地点、组织及报名链接来自权威赛事数据。未确认信息明确提示，不自动夸大资质或补写退款承诺。草稿赛事不得生成可公开报名的假链接；保留生成时的数据版本，赛事一般信息更正后提醒重新生成。先支持人工发布，第三方自动发布另行接入。

### 3.3 可见与真实的验收区别

交互演示可使用明确标识的样例，证明上传、编辑、纠错、重试和跳转是否好用。真实功能版则必须调用真实模型、保存真实草稿、遵守组织权限，并能在刷新后继续操作。受控试运行再加入真实短信、普通角色主链及异常验证。三个层次分别记录证据，不互相代替。

建议资料提取先选 10 份获准且有人工标注的真实样本，覆盖缺字段、时间冲突、复杂表格、图片模糊和不支持格式；记录逐字段正确、漏识别和错识别情况，不预先承诺通用准确率。推广使用多种赛事状态核对事实，并检查超时、重试、跨组织读取及重复保存。

### 3.4 手动路径与 AI 入口

保留原有手动创建、配置、编辑和发布路径，AI 作为并列入口。任务入口可以优先展示目标输入、上传规程、继续草稿和推广生成，但手动能力不依赖模型成功。模型故障时用户仍能按原流程办理。视觉或原型完成不表示业务和模型已经接通。

## 4. 迭代与投入建议

以下为初步工程量判断，假设熟悉现有项目的一名全栈开发者、已有可用模型账号和真实样本；不是实测工时或交付承诺，不含供应商审批、复杂格式覆盖及完整上线验收。各项共享基础，不能机械相加。

| 工作包 | 初步投入范围 | 边界 |
| --- | --- | --- |
| 推广生成真实功能版 | 2—4 人日 | 包含最小模型接入、2—3 种模板、事实约束、编辑复制及基本异常 |
| 限定格式的资料到草稿 | 4—7 人日 | DOCX/文字 PDF、字段来源、人工确认与现有草稿接口；图片和复杂布局需额外验证 |
| 组织公开主页与安全复办 | 3—5 人日 | 不含会员、关注通知、社区或复制在途业务 |
| 兴趣/城市与规则赛事推荐 | 2—4 人日 | 不含学习型模型与竞技认证；城市结构化字段不足需补模型 |

到 10 月 15 日建议优先稳定已有赛事主链，新增部分以推广真实功能和资料草稿的限定场景为候选。若只有一名开发者，一周内同时完成两项稳定接入并补完现有上线缺口存在明显压力；先交付推广、再交付资料草稿更稳妥。若演示重点必须是上传资料办赛，则倒置顺序，并减少格式与字段范围。首次样本验证及模型接通后再校准排期。

现有真实短信、服务端人机校验、普通角色全流程、真实资金与并发专项、生产部署和责任参数继续沿一期清单管理，不因为新增展示功能而关闭。最小站内信和短信仍按 ADR-011 执行；收费仍为平台外实际收退款后登记。具体实现进度以最新交接及真实证据为准。

技术沿用现有 Vue 3/TypeScript、Java 模块化单体和 PostgreSQL，AI 增加薄的服务适配、任务记录与失败恢复即可，不先建设完整 Agent 平台或微服务。业务写入使用现有权限、事务、校验和幂等，AI 输出不能直接成为资金、名额或正式成绩事实。

## 5. 附件口径应在转 PRD 时修正

- 数据库为 PostgreSQL；附件第 11.4 节 MySQL 与当前决定不符。
- 已有报到扩展为分竞赛项目；附件赛事级描述不能覆盖 2026-10-08 后续实现。
- 收费一期是人工实际资金登记，平台支付回调和自动退款后置；资金收尾不是可随意删减的功能。
- 组织准入标志不等于主体验真或官方资质认证。
- 私人成绩/证明不自动公开，也不自动转换为竞技等级。
- 注册动画先评审独立注册引导效果，不把含义未明的描述当作已冻结工作包。
- 10 月 15 日是附件新目标，正式交付范围与准入条件仍需明确。

## 6. 技术可行性的外部核对

此前核对的 [Docling 官方格式示例](https://docling-project.github.io/docling/_generated/examples/run_with_formats/)展示 PDF、DOCX 和图片等多格式转换能力，证明可复用现有解析路线；不证明保定赛事资料的字段识别效果。本项目可选择适合 Java 单体的解析/模型适配方案，评估时尚未选定或安装该工具。

此前核对的 [阿里云 Model Studio 结构化输出说明](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen-structured-output)提供 JSON Object/JSON Schema 路线，支持把模型结果映射到候选字段；结构符合 Schema 不代表内容真实，也不代替业务校验。此前仅验证公开文档，不代表取得账号或已经接通服务。本次文件恢复未重新联网验证供应商能力。

下一步进入开发前，需明确第一批主场景、真实模型服务和可使用的样本，以及展示/试运行的交付名义。本评估不新增已承诺的一期开发项；既有必做缺口继续由一期清单追踪。
