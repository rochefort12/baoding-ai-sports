# ADR-041 赛事项目分别报到

状态：用户 2026-10-12 决定，已在本地隔离演练实施。原用户赛事尚未逐条验收。

用户报告同一人报到一个项目后，其他项目也显示已报到。本决定覆盖旧母版及 ADR-011 中“一场赛事一人一次报到”的范围：同一人在每个赛事项目分别报到一次。队长到场仍不能代表全队，单场检录仍是独立记录。

原实现没有项目字段，名单查询按赛事、人员判断状态；任意项目的有效收款也可授权赛事级报到。新增 `asp_checkin.unit_id`，有效项目报到按组织、赛事、项目、人员唯一。请求摘要和锁包含项目，前端发送行内的项目编号，展示及筛选按编号判断，避免重名项目、切换项目或异步返回污染。

新请求 `POST /sports/b/competition/events/{eventId}/check-ins` 提供 `personId`、`unitId`、`requestKey`。服务端校验组织、项目所属赛事、本项目正式提交并审核通过的冻结名单，以及本项目当前有效收款；并发和重复请求只产生一条有效记录。旧调用未传项目时，仅有唯一已通过项目的人员可由服务端确定项目；多个项目必须明确选择。旧赛事级请求键保留原摘要，不能拿来授权新项目。

整单撤回依据本报名的场次引用和本项目报到判断；其他项目的新报到不阻止本项目合法撤回。成长报到仍按赛事、运动、人员计一次，两个同运动项目不会重复加分；不同项目的到场不能生成其他运动的报到事实。

旧记录没有可靠的原项目证据。V040 不改原记录、不按现有报名推测或复制项目，保留 `unit_id=NULL`、原时间、请求键和核查证据。界面显示“待项目核对”，负责人核对本项目实际到场后可建立项目记录。旧未知项目到场在撤回判断中保守保留阻断，避免把已到场改判为从未到场；后续历史核查及纠正走独立、可追溯的办理，不自动撤销原事实。

迁移由模型源生成当前 DDL、字典和表模块元数据，已应用 V001—V039 保持不变。执行前备份隔离演练库，独立恢复验证旧报到完整指纹，先在副本执行 V040 和约束检查，再执行同一迁移到演练库；重复执行通过迁移账本跳过。约束测试写入只存在于副本回滚事务，不作为真实到场验收。

验证证据见[本轮报告](../04-verification/奖项材料与队伍报名修复验证-20261012.md)。覆盖同人两个项目、重复及并发、跨赛事拒绝、普通参赛者权限拒绝、本项目付款复核、撤回隔离、历史未知项目和桌面／手机展示。原用户资料、实际收费和实际现场验收仍需真实角色确认，不把合成演练当作完成。
