# ADR-020 AI助手目标分流与草稿就绪反馈

日期：2026-10-09。依据：用户十项助手反馈、改进方案及“OK，请开始修改吧”授权。当前实现及证据见交接，不表示一期全链验收完成。

## 对话目标

保留Vue、Java业务层与Node模型层。普通办赛聊天通过Java的`POST /sports/b/ai/assistant/route`获取受限意图：operations、draft、new、clarify。不能用“办赛”关键词直接把咨询写成资料任务。Java验证当前组织、当前赛事授权，模型只建议意图，不执行事务。taskId仅提示是否存在候选，后续get/talk重新验证归属和状态；模型不返回或改写目标ID。无有效意图时澄清，不兜底创建。明确点击草稿确认/继续与上传入口可直接进入原任务。

页面赛事目标按当前工作区路由确定，服务器重新读取授权事实；不依赖页面DOM或尚未加载的显示对象。当前赛事问题与候选草稿补充分别办理，既有候选不能抢占全部提问。原创建确认、幂等、终态及并发保护保持。

## 就绪与时间

AiDraftReadiness共用于候选只读预检与确认保存，提供阻塞代码、关联项目/字段、具体解释与下一步。保存草稿只要求原保存语义，不把发布必填全部强加给草稿。有效补充后显示下一步；查询当前赛事时，EventPublicationService.readiness复用发布规则，并提供当前项目实际价格及缺项。该预检不等于完成发布，也不替代事务内复验、联系人同意或报名门禁。

模型识别/讨论收到Java生成的上海时间；讨论附程序计算的未来周末候选。过期日期与错误顺序由程序拒绝，错误说明实际结束时间、当前时间、时区和修复方向。推荐日期不表示场地或参与者有空；既有赛事重大变更限制不变。

## 费用、显示与宣传

AI创建继续使用placeUnpricedUnit，不产生免费或收费生效版本；删除旧“按免费创建”提示。费用原文、费用待配置与正式价格分别显示。首项198/加项100仅保留原文和人工核对，不自动实现跨项目优惠。已经存在的收费版本不自动覆盖。

双端使用同一安全Markdown组件，关闭原始HTML和图片，净化输出；实际来源卡片由业务组件另行显示。办赛草稿移到独立可折叠面板，小窗独立滚动、放大后右侧显示；不混入时间线。放大窗口不会因外部点击收起；用户手动移动前，每次打开按当前屏幕重新定位右侧。未同意提示不反复追加聊天。

宣传提供竞技、青少年、社区三套原创球场/球拍版式，可选择受众；模型写邀请，赛事名称、时间、地点、实际价格和二维码仍由业务事实排版。未配置价格不能表示免费，未发布文案不能称现在可报名。保留组织宣传图、PNG/PDF导出，不接通应用内图像生成，不代发。图片/PDF为现有位图导出边界，不承诺印刷标准或转化效果。

## 验证边界

规则/控制器单测、严格接口夹具的UI检查、实际模型受控样本、真实HTTP匿名拒绝分开记录。实际报名/资金/多组织/模型竞态与普通角色切片仍保留；3次模型样本成功不表示意图或文案已全面评测。原始母版、迁移及业务数据不修改。

接续：用户要求根据赛事信息生图并兼容其他运动，最新主视觉与文字隔离决定见[ADR-021](ADR-021-多项目宣传主视觉与文字隔离.md)。原本轮固定插画/不接应用内生图是上一阶段实现状态；当前已补独立适配，真实供应商配置和质量验证仍待完成。

## 2026-10-09 就绪提示只展示一次

同一轮里，服务端曾把 `AiDraftReadiness.nextStep` 拼进模型 `reply` 并写入对话，候选面板再显示同一句。现改为：`reply` 只保留模型回答；结构化 `nextStep` 与缺项只在候选区展示一次。历史对话里如果整句或末尾就是这句就绪提示，页面不再重复贴出；正文中的正常表述保留。讨论提示不再要求模型在 `reply` 里复述“还不能保存赛事草稿”。

## 2026-10-10 下一步与聊天视觉区分

用户指出就绪提示虽然有用，但与正常回复白色气泡难以分辨。结构化提示改为聊天时间线外的独立行动卡片，明确“下一步”标题、方向图标与“草稿待补充”状态；未就绪用浅琥珀背景及侧边标记，可保存时用浅绿与勾选图标、“草稿可保存”。底部提示可在下方直接回复；只移除正文中服务端固定的“还不能保存赛事草稿。下一步：”重复前缀，具体缺项、项目名和名额含义完整保留，模型回复及服务端规则不变。

卡片只在 PENDING_CONFIRMATION 展示，已保存/放弃不留过时引导。长提示可换行并有独立高度限制与滚动，保留聊天和输入区的空间；使用 status 语义提示更新，不依靠颜色独自表达状态。正式 Vue 页面桌面/390px手机截图与隔离状态切换检查、类型检查完成情况见交接；没有真实模型、数据库或草稿保存写入。

## 2026-10-09 已确认事项不再追问，未定项改为可点选项

用户两轮办赛对话里，已经说过的审核、参赛形式、名额和费用意向仍被逐轮追问；时间对不上时只问“改比赛还是改报名”，不给具体日期；草稿可以保存时要求办赛人打出“确认保存赛事草稿”。

已确认的值不被模型随后交回的空值清掉。点选或同义短句由服务端直接写入草稿，不再交给模型重判。当前缺的一项做成输入框上方的选项：审核是人工或无需人工，参赛形式可以是个人、双人、团体或三种都要，名额用已经读到的数字，时间对不上时给出算好的具体起止时间。资料里 status 为 suggestion 或 conflict 的读法，按原文做成“就用……”选项。

“请生成赛事”“直接生成吧”在草稿还不能保存时，只指出挡住保存的那一项并给出选项，不再先要确认句。草稿已经能保存时，选项为“确认保存赛事草稿”，点下去才创建。费用意向只记在草稿里，`effective` 为 false，不生成生效价格，也不把规程原文改成统一价。竞赛规则说明仍可留空。保存草稿仍不等于发布。


## 2026-10-09 团体人数补充与保存预检一致

用户实际对话中“3-5人吧”“3-5人”被回答为已记下，但确认保存仍报团体人数缺失。候选预检原未检查团体minMembers/maxMembers，实际项目创建才拒绝。预检现按项目创建规则检查上下限，错误指出具体团体项目，不再给出可以确认保存的提示。

唯一团体项目的明确人数区间短回复由服务端直接写入minMembers/maxMembers，保留其他项目；多团体项目时不猜适用对象。已确认人数不被后续空值清掉。“报名从今天开始”和明确报名截止修改也可直接更新，不依赖当前首个缺项或模型复述。发布、价格和实际项目事务约束不变。隔离回归覆盖原对话中的时间补充、人数补充及后续空模型值；普通角色原资料再次保存仍需实际走查。

## 2026-10-09 通用项目分类识别与保留

用户指出年龄组再次被压缩成单双打，并进一步要求同样支持业余/职业、亲子/成人及其他分类。分类维度由规程确定，完整可报名项目名称是项目身份；individual/pair/team只描述人数形式，不能替代年龄、性别、水平、职业属性或关系类型。本期不因此建设分类规则引擎或自动资格核验。

有项目/组别/分组/竞赛/分类章节的原文在常规识别之外独立提取项目目录，完整名称及实际项目范围按原文读取，项目字段可继续留空待补。表格按实际适用组合展开，不自动做各维度笛卡尔积。每项必须有可在原文中匹配的引用；缺格式、无有效引用或重复名称时任务失败并保留资料，不把通用摘要当完整目录。没有明确目录时保持原有对话补充流程。该步骤新增一次模型调用，仍受原300秒总超时和原同意/限额约束。

确认“都要”保留所有已有详细项目，包括entryType为suggestion的项目；从项目名称明确的单打/双打可保持人数形式，但不推导参赛资格。单选已有形式不再额外生成同形式的通用项目。模型replaceUnits标记不能自行删除详细项目，只有用户明确删除/只保留等请求才按既有替换路径办理。后续时间、审核或名额补充不得合并分类项目。

隔离样本覆盖U年龄、业余/职业、亲子/成人、原文引用失败和后续补丁删除保护。真实规程的表格/OCR完整性及普通角色确认保存继续验收，不以模型目录自报完整替代人工核对。已创建赛事的项目不批量改写；应按原规程和正式报名历史分别办理。

## 2026-10-10 自然叙述与表格图片真实验证

真实模型在自然叙述中理解了分类但将units误放event内；章节关键词门槛又导致这些原文未复核。现对非空原文统一独立提取目录，由模型根据上下文判断可报名项目是否存在，取消关键词触发。兼容event.units并归一至顶层，已有顶层列表优先；没有增加分类专用分支。该变更使无章节原文也增加一次目录调用。

七种真实模型样本包含地域划分/举办地反例、职业属性、关系、自定义层、年龄×水平交叉及用户表格图片，修正后通过。图片16项按四行实际设置展开，出生日期未写成赛事日期。实际调用与隔离工具传输、普通角色保存仍有区别；详见[真实模型评测](../04-verification/项目分类真实模型评测-20261010.md)。年龄资格仍未新增结构化自动核验，跨页/模糊拍照与普通角色保存继续待验。
