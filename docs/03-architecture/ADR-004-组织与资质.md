# ADR-004 组织与资质

日期：2026-10-04。状态：已开发，待业务验收。模型迁移 V007 已应用。TC01–TC04 仍待业务验收。

最新补齐见 [ADR-011](ADR-011-一期业务收口与交付边界.md)：赛事责任组织/联系快照、组织自有字段目录、顶栏组织上下文、注销唯一管理人移交和平台受理责任；准入非资质验真及原开户边界不变。新增目标未实现/验收，不自动启用员工管理/资质到期等后续完整能力。

本决定细化 ADR-002 的 M1.2。M1.3 及以后的暂停点不变。M1.1 的手机号注册和本人档案不重做，也不恢复代报。原始母版不修改。母版里的执照清单、有效期、补正和员工岗位只作背景，不写成已经批准的规则。

业务流程见 [组织与资质业务流程](../02-modeling/组织与资质业务流程.md)。平台账号、技术租户、开户和管理会话见 [ADR-005](ADR-005-平台账号与租户主体.md)。

## 决定

平台只有一种用户。注册仍是现在的手机号注册，不在注册时区分参赛或办赛。登录后可以继续建参赛档案，也可以申请创建组织。参赛档案、组织和组织成员是三种关系，组织成员不是新的用户类型。

| 关系 | 落点 | 一期 |
| --- | --- | --- |
| 平台账号 | `asp_account` | 不新建别的用户表。现有登录仍暂时写在「平台参赛者」，目标模型见 ADR-005 |
| 参赛档案 | `asp_person` | 沿用 M1.1。没有档案也可以申请办赛 |
| 组织成员 | `asp_staff_grant` | 审核通过后给首次申请用户写一行。不在此表保存 `sys_user` |

组织申请是平台级数据，不是某个业务租户里的组织。新建 `asp_organization_application`，表上没有 `tenant_id`，并加入租户排除名单。若依不会给这张表自动补租户。申请人只能看自己的申请；超级管理员审核全部待审。这是服务里的授权，不是关闭租户过滤后的全局查看。

审核只决定是否开放办赛。通过不表示主体已经验真，不表示授权关系已经核验，也不表示办赛资质已经认证。因此本段不写 `asp_qualification`。

通过之后才为这个办赛主体新建租户，并写入 `asp_organization`。本期一个租户对应一个组织。首次申请用户成为该组织的初始成员，并按 ADR-005 开通租户主体。不修改平台账号去归属这个租户。登录页不让普通用户选择租户。新租户不出现在未登录的租户列表里。

组织是否已开放办赛，用现有组织状态 `certified`。这个值只表示平台已准入，没有资质审核或主体验真的语义。申请自己的状态是 `draft`、`pending`、`approved`、`rejected`。拒绝后可以再提交；被拒绝的那一版和当时的附件保留为历史。

只有若依超级管理员能通过或拒绝，这个权限不能分发。组织成员关系以后可以分给其他用户，本期只建立初始成员，不做分发页面。

未开放办赛的用户不能发布赛事、报名、收费、录分。这些功能不在本段实现。体育局不另做门户。页面做在现有 plus-ui，不新建前端仓库。

## 后期仍可变化

入口和页面可以以后再拆。用户、参赛档案、组织成员三者的关系保持不变。

以后可以做：主体真实性验证、办赛资质认证、补正、到期、组织内把成员授权分给他人、登录后按组织切换、一个租户对应多个组织。本期都不做。
