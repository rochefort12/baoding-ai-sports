# ADR-008 长期队伍

2026-10-06 补充目标见 [ADR-011](ADR-011-一期业务收口与交付边界.md)：代表队伍报名由当前队长按规则整单撤回（含已通过分支），重提独立义务、不改变原付款人；队长注销前移交，关闭结束有效成员关系但保留历史，新账号不自动恢复队伍/角色；R09 当前成员授权和历史展示仍待实现/验收。其中当前名单授权已于 2026-10-07 实现，历史展示仍未做，见文末。

日期：2026-10-05。状态：已开发，待业务验收。迁移 V010。TC11–TC20 仍待队员和队长验收。

本决定细化 ADR-002 的 M1.5。业务流程见 [长期队伍业务流程](../02-modeling/长期队伍业务流程.md)。报名边界见 [ADR-007](ADR-007-报名.md)。

## 决定

长期队伍使用已有 `asp_team`，不另建主键。这些表是平台共享表，没有租户列。查询必须先落到当前账号的成员、队长、申请或被邀请关系。`TenantHelper.ignore` 只出现在这层内部，不能据此列出全部队伍。

申请要当前队长同意，邀请要被邀请人本人接受。创建队伍的人直接成为唯一队长。一人可以同时是多队的有效成员。同一人在同一队同时只有一段有效成员；结束后不重新激活，再次加入新插一行。

队长是成员角色，不是另一种账号。有效队伍必须且只能有一名有效队长。队长不能直接退出或移除自己，只能先转让给当前队员，或者解散队伍。解散是终态，不恢复，也不删除队伍行。

队伍不归属组织。本期没有副队长、配额、队伍广场和入队费用。`asp_team_quota` 不读不写。`join_policy` 固定写 `open`，`visibility` 固定写 `members`，服务不按这两列分支。

成员外键是 `person_id`。只有账号状态为 `active` 且本人档案已齐的人能建队、申请、被邀请和接受。一期 `sport_id` 写现有羽毛球，创建后不改。

报名模块只通过 `TeamMembershipApi` 读取当前有效队伍、当前队长和有效成员，不引用队伍表。队伍模块不修改报名。`team_id` 为空的报名仍按 ADR-007。有 `team_id` 时，办理权来自当前队长，不看来时的 `submitter_account_id`。提交成功才写入 `team_name_snapshot` 并冻结名单。退队、移除、转让和解散都不回写已有报名。

临时双打继续只走 `asp_registration_member`，不写 `asp_team`。

## 本期不做

组织归属、官方代表队、创建审核、停赛、副队长、教练、领队、自定义权限、队伍广场、入队费、转会、合并、恢复、永久删除、比赛阵容、收费和录分。

## 2026-10-07 实施落点：退队后不能读取现名单

队伍详情只向当前有效成员返回队员。曾经入队但关系已经结束的人，再打开原队伍得到「你已经不在这支队伍里」，响应里没有现队员姓名。从未入队的人仍得到「队伍不存在」。我的队伍列表仍可看到本人已经结束的成员段和队名，不包含其他现队员。已结束成员段的单独展示仍按业务流程后做。
