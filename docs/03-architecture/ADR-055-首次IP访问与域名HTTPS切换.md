# ADR-055：首次IP访问与域名HTTPS切换

日期：2026-10-14。用户需要先让网站可访问，再完成域名绑定，要求提供发布操作。保持人工触发应用部署，不在本轮自动启动应用或改服务器私有配置。

## 决定

应用Compose的前端监听地址增加WEB_BIND_IP，默认127.0.0.1、WEB_PORT默认8088，保持原HTTPS反向代理模式。首次仅做IP可达验证时，由操作人显式在服务器私有server.env设置WEB_BIND_IP=0.0.0.0、WEB_PORT=80，并将backend.env的PUBLIC_BASE_URL暂设http://47.92.212.93。这只发布前端HTTP入口，后端/网关/PG/Redis/存储端口仍保持内网或回环。

目标ECS的依赖、框架及版本0标记已按ADR-054实际准备。应用凭据从backend.env.pending保留并完成；不手工执行业务迁移，第一次Java启动由Spring Boot Flyway执行V001—V003。通过GitHub成功构建的四文件发布包手动部署，不编辑已封存的旧包，不执行数据库或卷重建。

公网TCP80需要用户在阿里云安全组放行；没有阿里云管理API授权，本轮不修改云安全组。先验证IP页面/healthz，再把网站域名DNS指向ECS。DNS及证书/HTTPS入口完成后把PUBLIC_BASE_URL改为正式https地址，恢复WEB_BIND_IP=127.0.0.1及WEB_PORT=8088，由HTTPS反向代理接入。HTTP阶段仅做入口验证，真实登录、个人材料及业务使用在HTTPS配置完成后进行。

文件私有存储外域、供应商参数及正式容量/备份恢复继续独立准备；IP页面可访问不表示文件签名、短信、模型或普通角色业务已完成。操作说明使用新的成功构建ID，旧包仍按原回环模式工作。

## 验证

对默认回环8088及显式公网80分别进行非敏感占位Compose quiet渲染/端口结果核对，再做现有来源/digest/脚本检查。实际服务器应用发布、云安全组和公网访问由用户按手动步骤执行；本轮不声称已上线。
