# ADR-045 悬浮办赛表单与收费草稿删除

日期：2026-10-12。依据：用户要求审核页赛事最新置顶，仅配置收费的未发布赛事可删除；悬浮助手读资料后直接显示可填写表单，明确保存和创建结果，修复批量价格及多选丢失，减少重复提示。随后明确要求同一份草稿可持续通过聊天修改，并直接通过对话发布；交互、动画和样式由本轮完善。

本决定接续 ADR-011、ADR-029 与 ADR-044。源码实现、安装生效、普通角色验证和用户接受分别记录，不因本文同步关闭 21 项功能、17 项使用缺口或 7 个普通角色验收切片。

## 1. 审核页赛事顺序

报名审核页赛事选择接口 `GET /sports/b/registrations/events`，以及办赛赛事列表 `GET /sports/b/events`，按创建时间 `create_time DESC` 排序，同一时间按 `id DESC` 稳定排列。页面沿用接口顺序，最新创建赛事位于最上方。报名审核入口原按编号倒序，本次明确为创建时间优先，不把这一源码变化写成已复现全部现场问题。

政府主办方管理展示组织及赛事数量，当前没有逐场赛事审核列表；组织入驻审核不是赛事发布审批。入驻待审核申请另按创建时间倒序。主办方首页用于近期安排的开赛时间排序保留，不新增赛事发布审批。

## 2. 未用收费配置不阻止删除赛事草稿

赛事价格、免费版本和赛事收款方式属于配置，不是参赛者已经付款。仅配置每单金额或收款指引，不使尚未发布的赛事不可删除。此条接续 ADR-023 的身份及草稿保护；取代 ADR-006 末尾“未发布办赛草稿可以删除”段及既有办赛删除实现中“有收费版本即拒删”的旧条件。ADR-023 的本人报名草稿删除规则保持，不把赛事草稿和报名草稿混为同一对象。

`POST /sports/b/events/{eventId}/delete-draft` 仍只允许有效组织管理会话删除当前组织的 `publicationStatus=draft`、`holdingStatus=normal` 赛事。服务端持有赛事行锁后重新核验归属与状态；任何发布办理命令、正式报名锁、报名记录、名额占用、已填写报名采集值或付款义务历史均拒绝删除。已撤回、拒绝、关闭的记录及停用价格版本仍参与历史检查，不因当前没有待付款或净实收为零而抹去历史。已发布、下架或取消赛事不走此入口。

所有清理加入删除赛事的同一数据库事务。项目侧先核对报名、占用和采集值，再经纯契约 `FeeApi.discardUnusedDraftPricing` 由资金侧复验草稿、租户、正式报名锁及全部价格版本的使用历史；只清理未被使用的价格版本和赛事收款配置，再删除空采集项、名额与项目，最后清理宣传关联、处理关联任务并删除赛事。关联 AI 任务标为 `ABANDONED`，解除赛事结果关联并清除候选与提取正文。任一步失败全部回滚，不遗留部分清理状态。

该动作不删除付款义务、实际收款、冲正、退款或异常事实，也不办理退款。已保存赛事的删除不直接删除对象存储原件或收款码图片；未引用文件继续按既有授权和保留规则处理。还未形成赛事的 AI 任务继续使用原 `abandon` 接口，其资料处理契约不由本次赛事删除扩展。

## 3. 悬浮聊天直接填写办赛表单

读资料形成 `PENDING_CONFIRMATION` 候选后，在对应聊天回复附近显示办赛表单，已识别内容预填。默认显示待补或冲突字段，可展开核对全部内容及逐个项目；“查看表单”保留原文与图片核对入口。字段包括赛事名称、运动项目说明、地点、报名与比赛时间、联系人、收费说明、规程、退改说明及资料已有的参赛声明。运动项目说明使用 `projectName` 保存到同一候选，再随确认创建写入赛事，不以费用说明代替。

项目表单包括名称、参赛形式、每单人数、报名上限、金额和计费单位。报名上限按项目的整单数理解，双打一单两人，团队一单一支队；不把 32 单改成全赛事 32 人。缺项与冲突紧邻可填写字段显示，已填写字段不会在输入第一个字后消失。

资料未说明审核时沿用 ADR-044 的默认 `none`，来源标为默认且可人工修改；明确人工审核和真实冲突保留。原文未有声明，不由模型新增声明或开启成员确认。候选是材料与经办人补充的工作稿，不授予身份、资金或发布权限。

## 4. 批量价格与保存、创建结果

在当前报名整单价格上下文中，用户明确“全部项目 100 元”时，将本次明确金额累积到各项目候选的 `feeAmount`，整单口径为 `feeBasis=order`；不只写入聊天备注，也不再重复追问同一已确认价格。聊天表单提供“所有项目整单价”和“每个项目报名上限”，经用户点击“应用到所有项目”后更新各行。批量 100 元表示每个项目每单 100 元；免费明确填 0，未填不是免费。

按人、首项／加项、优惠、金额冲突、可变人数或含条件的费用仍保留原文及待核对状态；不能因出现“全部”就抹去真实条件。固定人数的简单按人换算继续按 ADR-044 留下单价、人数、整数分算式和来源。候选报价不是到账事实。

“保存表单”通过 `PUT /sports/b/ai/tasks/{taskId}/candidate` 携带 `expectedVersion` 保存当前可见输入，返回更新后的任务及版本，只更新候选。“创建赛事”先完成同一保存，再用保存返回的版本明确确认创建，不能使用旧父卡片版本或把输入框残留文字当创建指令。成功显示“赛事创建成功”、赛事编号及发布／管理入口；创建仍是未发布赛事，已核对的整单价格按既有确认事务写入项目初始价格，不要求再手抄一遍。

版本冲突、缺项、业务拒绝或连接失败显示具体结果并保留填写内容。保存成功但创建未完成，不能只显示无反应或把保存当创建成功。提交超时先重新读取任务；已创建则恢复同一赛事，结果仍无法核实时明确待核实，不自动重放创建。发布沿用原核对及明确同意流程，缺收款渠道、公开字段或时间条件仍由正式服务拒绝。

### 4.1 创建后继续修改同一草稿

`CREATED` 是 AI 任务已有赛事结果，不是赛事已经发布。服务端读取原赛事的真实发布状态，返回 `published`、`eventStatus`、`draftEditable`，不能仅看任务状态就切断对话，也不能把旧会话中的“已创建”当当前草稿授权。

符合当前组织、尚未发布、无发布或报名历史的原赛事，继续用同一个 taskId 与 eventId。普通聊天累积候选修改；“保存修改”或表单保存把已核对内容同步原赛事及原项目，而不是另建赛事。项目 ID 保持，不能凭项目名字新增或删除原项目。赛事字段、项目容量与价格同事务执行原业务校验；版本冲突、其他页面修改、越权、状态或历史变化都拒绝覆盖并保留填写。任务版本和赛事版本分别核对。新增项目、已有报名后的重大变更及团队规则不由这条持续编辑能力放宽。

在表单填了一半再发送聊天时，先保存这份可见输入，再基于返回版本处理新回答。原文核对弹窗未保存时引导先保存；对话版本更新而本地仍有输入时保留输入并显式重读。保存后的候选与实际赛事区分标示，尚未同步的修改不能被发布卡当作已生效资料。

“读取赛事当前内容”按钮或明确对话“重新读取赛事草稿”表示采用同一 eventId 当前已保存的赛事字段、项目目录与整单价格，重新建立持续编辑基线；读取本身不修改赛事。服务端在原赛事行锁内核验当前组织、未用草稿条件及任务版本，保留上一版候选为有界的 `previousCreatedCandidate`，原始资料继续保留。当前业务值的来源标为“实际赛事当前已保存内容”，不伪装成原始材料引用；原资料的封面选择也不冒充当前赛事图片。

表单读取前另保留当前未保存填写，可展开对照并回填。回填只改变本地表单，仍需明确保存；项目编号目录一致时才整体回填项目，目录变化时保留旧项目供逐项核对。读取失败不覆盖当前输入。旧版 `CREATED` 任务没有 `createdEventVersion` 及项目费用基线时，不能直接继续修改或保存覆盖实际赛事，必须先显式读取当前内容。普通 GET 任务或恢复会话不代替这一采用动作。此后保存仍更新原赛事与原项目，赛事版本及项目费用快照变化均拒绝覆盖，不另建赛事。

### 4.2 对话内核对并发布

用户说“发布赛事”时，先保存当前草稿修改；还没有赛事的完整候选按明确意图创建一次，再读取该赛事的公开资料与实际项目费用，在同一聊天区展示发布核对卡。卡片显示赛事名、运动项目说明、地点、时间、联系人、退改说明、项目整单价和真实缺项。卡片展示后，用户可点“确认发布赛事”，或直接回复“确认发布”。这句明确回复表示已核对卡片且同意公开所列联系信息；未展示核对卡时先展示，不直接发布。

确认使用原赛事发布服务，归属、资格、收费渠道、时间、公开资料和事务门槛照常校验。核对后资料发生变化时重新读取并要求按新资料确认。成功显示实际赛事编号；发布后恢复会话显示真实已发布状态，专用草稿编辑入口关闭，继续运营按原工作区办理。上述专用入口不开放通用 Agent 写渠道，不让模型直接确认到账、政府审批或正式赛果。

聊天发布核对卡读取真实赛事、任务及 `GET /sports/b/events/{eventId}/preview-fees`，保存任务版本、赛事 `eventVersion` 和 `previewHash`。点击或回复确认前再次读取；本地尚未保存、候选未同步、任务版本或实际公开资料／费用变化时先更新核对卡并清除同意，不能沿用旧确认。发布请求携带 `expectedVersion`、`expectedPreviewHash`、请求键及公开联系信息同意；正式发布事务在赛事行锁内比较版本和当前预览摘要（CAS），不一致以 409 拒绝并要求重新核对。该比较绑定聊天核对卡，既有兼容发布调用仍保留其原业务门槛，不把可选比较参数写成所有客户端的新必填。超时或失败仅在重新读取已确认真实 `published` 后恢复成功，否则保留失败及请求键；同一请求键沿用原发布幂等规则。

收费赛事缺少收款渠道时，核对卡内可填写并保存线下付款说明，复用现有赛事收款设置接口及版本校验；渠道名称沿用正式模型“线下付款”，不接受虚构收款码或到账事实。已有渠道完整保留，公开核对展示实际说明。保存后重新读取公开资料、费用和收款配置，清除旧同意，仍须明确确认发布。免费赛事不依赖单独收款权限；收费设置读取或保存被原权限拒绝时保留错误，不绕过。发布预览摘要还包括实际收款配置 revision，即使渠道仍可用，说明修改也使旧核对失效。

## 5. 多选与聊天空间

参赛者选择多个咨询主题时逐项累积为可见标签，再次选择或点击取消可移除单项；保留用户自己的输入文字，发送时将当前多个主题和问题合并成一条消息。办赛助手建议回复逐行累积到输入区，可检查、取消并一起发送，不用最后一次选择覆盖此前选择。

结构化缺项以表单字段及项目提示展示，移除回复后重复附加的“下一步”整段和占用输入区的重复缺项栏；不隐藏业务拒绝、原文冲突或创建结果。更多操作和资料说明按需展开，表单与消息共用可滚动聊天区，保留发送入口与正常阅读空间。

本轮用户追加要求文档拖拽上传。拖入悬浮聊天窗口时显示落点提示，松开后加入待发送附件，保留文件名、大小和单项移除；不自动发送或自动创建。与选文件入口共用格式、数量、大小、授权及当前处理状态校验，拒绝不支持的文件或文件夹时保留已选附件；拖入网页文字或链接不当作文件。窗口内文件拖拽阻止浏览器跳转，穿过子元素不闪烁提示，结束、关闭或取消时复位。办赛及共享助手按各自既有格式范围办理，不因支持拖拽而放宽资料读取或发布门槛。

一期的组织隔离、真实足额收款、名单与金额快照、授权、幂等、事务及正式发布门槛保持。此次调整不确认实际资金，不替参赛者报名，不办理政府审批、正式成绩、真实短信或现实赛事验收；验证与未验证边界由本轮统一证据另行记录。

## 6. 运动项目说明引用失败的局部恢复

2026-10-12 用户贴出任务 `2109658595451772929` 的 `SOURCE_FIELDS_INCOMPLETE`，实际既有调用记录显示项目目录识别成功，运动项目说明 `projectName` 校验连续三次失败。原记录不包含完整模型响应，具体错误措辞未观察；源码会拒绝跨段拼接、改写、错误引用及超长说明，不能将未经原文校验的措辞直接写入。

该短字段校验失败时，只进行一次有界、只读的说明重取，选择原文中的连续说明或明确运动名称，仍使用原 sourceId／逐字引用校验。不重新生成其他履约字段、声明或已核验项目目录。再次无法核对的说明清空并标记 missing，交由既有必填表单补充，保留其他识别结果；摘要不能重新填入未经核验的说明。原文字段及声明校验规则不放宽，创建及发布必填门槛保持。真实模型服务、配额或超时错误继续报告，不借此恢复成成功。

用户随后要求修好后自行测试。本补丁仅修改网关并重载既有隔离服务，不执行测试、模型重试或用户任务办理；新代码不能沿用上一轮已通过测试的结论。实际接受以用户后续重试及记录为准。
