# ADR-014 邀请通知与报名详情交互

日期：2026-10-08。依据：用户《临时登记的问题》新一轮记录及对两项建议的同意。资金权利仍以 ADR-011/013 为准。

## 确认与实现

- 临时参赛邀请、长期入队邀请自动生成目标账号的持久站内信；短信由邀请人选填，默认不勾选。同一邀请版本和渠道去重，一份有效邀请不反复申请短信。真实渠道尚未接通，选择后只记录未送达原因，不冒充发送或撤销有效邀请。
- 通知携带限定站内路径，邀请链接不作为授权。参赛邀请仍验证目标账号；长期入队深链新增 `/portal/teams/invitations/:invitationId`，仅指定受邀本人可读取队名和邀请状态。退出后的成员权限仍按旧边界，不因链接恢复。
- 参赛成员本人确认后，可以看到本次当前伙伴的姓名与确认状态。正式提交前名单可能调整；不额外公开手机号、证件、健康资料。尚未接受者不开放完整当前名单。
- 复用 `aisports-api/InvitationNoticeApi` 契约与现有通知/投递表，不跨模块引用实体或 Mapper，不另建通知平台。通知与邀请同事务保存；通知和投递显式使用相同租户，避免报名组织动态租户与平台消息关联错配。不变更表结构。
- 报名详情文字行、状态行、操作区统一留白。详情抽屉允许点击左侧收起并导航；办理资金弹窗时保留上下文。平台超级管理员原生若依样式不变。
- 足额后把普通收款入口改成“补记其他实际收款”，金额为空，备注必须说明原因并二次确认。相同付款人/金额/时间提示核对，按钮忙碌时不重复提交；接口原幂等/锁继续承担事实保护。确有其他真实款项仍可登记，不用金额上限隐藏多收款。
- 到账后重新读取资格，自动通过时明确反馈；资格审核区直接显示已通过等当前状态。真实资金记录不直接删除或撤销：用户尚未明确此前第二笔是否真实发生，现保留。
- C端详情页使用明确的返回目标：报名详情回本人报名，填写报名回赛事，参赛邀请回我的参赛，入队邀请/队伍详情回我的队伍。一级入口依靠主导航，不强塞多层面包屑，也不无条件跳浏览器历史。

## 验证边界

单测、隔离界面与真实运行结果见交接及[本轮执行记录](../05-ui/邀请与报名详情改进记录-20261008.md)。真实邀请双方走查、短信接入与普通角色验收不因设计或模拟通过而关闭。
