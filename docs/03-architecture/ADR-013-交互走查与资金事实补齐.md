# ADR-013 交互走查与资金事实补齐

日期：2026-10-08。状态：用户确认，代码及迁移已修改；普通角色整段验收继续单独登记。

依据为 ADR-011、用户《临时登记的问题》及本轮明确答复：同赛事项目重名校验同意；双方一胜一负或同时平局同意；资金处理方案同意。已有测试赛事重名项目按序号区分亦获明确确认。原问题记录保留，不覆盖。

## 确认的规则

- 同赛事有效项目名称去两端空格后不重名，英文大小写不区分。创建、改名受后端校验及数据库唯一索引约束。无正式报名历史可修改类型/人数并移除；有历史只允许不改变含义的一般名称更正，不删除历史。移除关闭项目，保留已有关联。
- 通用结果为胜/负、负/胜或平/平；手动录分和批量导入均校验。暂不增加各运动专项计分判定。参赛者只查看本人正式结果，包含双方名单、中文胜负和分局比分。
- 资格拒绝不取决于是否已经登记收款，不要求先造到账。拒绝、撤回或取消后真实迟到/误付款仍可登记，并产生按原款处理的退改事项；到账不恢复参赛资格。
- 人工登记填写每笔实际金额、付款人、实际时间；允许分次收款。净有效实收为有效分配减实际退款，足额才满足收费审核条件。超额也按实际事实保存并提供待办，不把实收改成应付。付款通知可选，不能替代真实收款，也不是成功前置条件。
- 退款按每笔原有效收款填写实际金额、时间、接收人及原退改依据。接收人与原付款人不同须核验并记录授权依据；累计不得超过原有效收款。部分退款保持待办，剩余款按规则退款或有依据地无需退款结案。
- “撤销此笔错误到账”只纠正错误记录，不表示真实退款。已发生实际退款的原款不能直接撤销，应受控核对；不自动删除报名、报到、场次或赛果。

## 实现边界

资金仍放报名详情，复用组织 payment 权限，不建设财务平台、在线支付或授权审批。组织身份/租户/当前义务及原款关联后端校验，资金写入锁 PostgreSQL 义务行，幂等键重放同一事实，不允许改变金额后复用。

V019 新增退款接收人及依据字段、有效项目名称唯一索引。迁移只按用户确认区分指定测试赛事的既有重名项目，保留 ID 和关联，不重写已应用迁移。旧退款缺失接收人不推断补造。

新增 `POST /sports/b/registrations/units/{id}/edit`、`/remove`；`GET /sports/b/events/{id}/preview-fees` 仅组织授权预览。到账沿原 confirm 接口；reverse 指定 paymentId；refund 追加实际 amount、occurredAt、recipientName、recipientBasis。收款明细返回净实收、累计实退及逐笔待办。预览草稿不改变公开接口或发布状态。

设计地图和人工测试同步见 [交互修改执行记录](../05-ui/交互修改执行记录-20261008.md)。实际运行结果以执行记录、交接和本地验证日志为准。真实短信、并发专项、受控资金更正和普通角色验收不因本决定自动完成。
