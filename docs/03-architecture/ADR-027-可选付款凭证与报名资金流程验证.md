# ADR-027 可选付款凭证与报名资金流程验证

日期：2026-10-10。状态：用户授权本轮完整收费报名流程测试、模拟上传凭证及自动修复明确问题，已实施。延续用户原先“强烈推荐，但平台不强制上传”的决定；取代 ADR-011 与收费流程中旧的“付款截图后置/不上传截图”边界，其他资金规则继续遵循 ADR-011。ADR-025 中赛事级多渠道收款等未完成事项不因此完成。

## 决定

凭证上传与付款声明、实际到账、参赛资格分别处理。正式提交的收费报名，在本次付款义务仍 open 时，由本人报名管理人或代表队当前队长自愿上传。允许 JPG、PNG、WebP，每张 5MB、最多 5 张；不做 OCR，不据图片自动确认金额或到账，不要求上传才能声明、登记实际收款或审批。

新增 V027 `asp_registration_payment_proof`，引用报名、当次付款义务、上传平台账号和私有文件。上传请求键及 SHA-256 核验重复请求，同键不能更换内容。沿用报名队伍/容量锁，存储后重新核验身份、报名状态与义务编号，防止上传期间撤回重提而挂到新义务。对象先存后引用失败时，由既有七天未引用文件清理兜底；已引用凭证纳入保留扫描。

凭证用途 `payment-proof`、敏感性 finance，专用存储契约与鉴权读取。通用组织媒体上传不接受该用途，通用图片读取拒绝凭证。本人管理身份、本组织 payment 动作和赛事归属都在服务验证；不返回公开 URL，图片响应 no-store。只在当前付款义务列表中展示，不把历史材料或旧到账自动带到新提交。

C 端付款弹窗加入提示、选填上传、预览；通过后仍可查看本次凭证。手机弹窗限定视口高度，正文可滚动，底部操作保留。B 端报名详情有 payment 权限时展示图片用于人工核对。旧收费页按具体原收款撤销错误到账，退款填写实际金额、时间、接收人和原因；收款按钮防重复，请求键稳定，部分到账后默认填写剩余金额。

## 验证与边界

真实本地普通平台账号与组织管理会话、HTTP、PostgreSQL、Redis、MinIO 和正式 Vue 页面完成 46 项流程断言。测试组织准入由管理员准备，赛事、报名、资金及审批均用普通角色。收款和退款是显式 SIMULATED 合成账目，没有银行、微信或支付宝真实转账；不能用此证据宣称正式收费运营验收完成。
