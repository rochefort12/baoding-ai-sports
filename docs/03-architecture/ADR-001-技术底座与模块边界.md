# ADR-001 技术底座与模块边界

日期：2026-10-03。状态：用户指定的技术方向已接受，具体业务模型为工程设计初版。

一期最新业务及复杂度边界见 [ADR-011](ADR-011-一期业务收口与交付边界.md)。框架版本、模块化单体、纯契约/PG 权威和生成器约定保持；正式提交占整单名额，无临时占位/跨项目总人数去重，通知 outbox 用于最小双渠道取消闭环，不提前引入消息平台或微服务。

## 决定与来源

后端采用 RuoYi-Vue-Plus v5.6.2（提交 `8136a0191a2258c0e1b36a8146a1c5ebc070c139`），前端采用 plus-ui v5.6.2-v2.6.2（提交 `d0d451967676707021b9857df529c395b27e90a7`）。保留上游许可证和目录规范。代码在 `backend/`、`plus-ui/`，根目录 Git 统一管理业务、文档和基础设施，上游元数据缓存于忽略的 `.upstream/`。

采用 Java 17、上游 Spring Boot 3.5.15、Vue3 / TypeScript。业务主库 PostgreSQL，Redis 辅助会话、缓存与锁。开发镜像固定为 PostgreSQL 17.11-bookworm、Redis 7.4.11-bookworm，并锁定拉取摘要。

用户要求单体并保留微服务演化可能，因此一个 Spring Boot 入口、一个开发业务数据库，以模块和公开契约划分边界。无需为准备工作引入服务发现、网关集群或跨服务事务。

## 代码边界

- `ruoyi-admin`：应用组装、配置和启动，不承载业务规则。
- `ruoyi-common-*`：复用上游基础设施，不把体育业务混入通用模块。
- `aisports-api`：独立 JAR，只包含跨模块接口、DTO、调用者上下文和领域标识；本期先建立身份、日历契约，其他契约随实际实现完善。
- 后续 `ruoyi-sports-*`：按 identity、organization、team、event、registration、finance、scheduling、competition、venue、notification、governance 等边界实现业务。不是一表一个服务。
- `aisports-mcp`：MCP 传输与认证适配，依赖公开工具及现有安全能力；不提供模型推理或产品 Agent。

依赖方向：业务实现 → API 契约 → JDK。业务实现可以使用本模块 Mapper 和上游 common。禁止业务模块直接访问其他模块 Mapper。Controller 遵循上游 Bo/Vo 和 R/TableDataInfo；跨模块 DTO 不携带这些 Web / ORM 类型。

## 数据与事务

`sys_*` 保留框架后台账号、租户、权限；`asp_account` 为平台运动用户账号，显式关联可选的后台账号，不把每个租户 sys_user 都当成新运动者。共享身份、长期队伍和公共运动目录与赛事材料、资金记录分开。

同租户关系在数据库使用 `(tenant_id, id)` 组合外键防止错误关联。跨领域聚合外键在当前单库可用，未来拆分以版本化 API 和一致性事件替换；不能把同库 JOIN 作为公开调用契约。外键不等于访问授权。

报名、占位、费用义务在本地事务内协调；人数去重按引用维护。跨步骤通知等通过事务 outbox 发出，消费幂等。支付回执、通知和实际比赛属于外部已发生事实，备份回滚不能抹除。写操作使用请求幂等键、版本校验及明确事务。名额互斥使用通用锁，见 [技术规范](技术规范.md)。当前默认单机实现，Redis 实现保留为配置项。数据库仍用 `used_count` 上限做结构防线，名额排队不使用数据库行锁。

## 未来拆分

优先识别通知、文件、计算任务等可独立边界。迁出前完成契约版本、身份与租户上下文传递、超时重试、幂等、事件、可观测性和旧写入关闭。当前 API 接口为进程内调用；之后可实现远程适配，不让业务调用者直接依赖 Feign 或 HTTP 客户端。

## 验证边界

准备工作提供源码锁定、模块编译、数据库模型、环境和生成器验证。业务模块、权限授权和 TC01—TC80 的完整运营链需后续实现，不能由框架启动替代。

## 2026-10-07 补充：本机测试数据可以整库清空

开发库里的走查账号、组织和赛事需要一条明确的清空入口。`scripts/Reset-TestData.ps1` 只允许连接 `aisports-dev-postgres` 与 `aisports-dev-redis`。它删除业务测试行、办赛时生成的组织租户，以及本项目 Redis。表结构、已应用迁移、框架租户、框架自带账号和运动项目目录保留。文档中的试用登录保留账号和手机号绑定，不保留档案和业务记录。

这不是生产清理，也不代替迁移或验收。`Initialize-M11Data.ps1` 仍只补初始化登录，不承担清空。

对象存储的默认配置在启动时写入 Redis。清空 Redis 后，下一次取存储客户端时从数据库重新装入，不把「文件存储服务类型无法找到」直接返回成附件保存失败。

## 2026-10-08 补充：局域网页面的幂等请求键

用电脑局域网 IP 的 http 地址打开页面时，浏览器不提供 `crypto.randomUUID`。建立竞赛项目、发布、报名、到账和录分使用的请求键改由 `plus-ui/src/utils/requestKey.ts` 生成。本机 localhost 仍优先使用浏览器自带方法。

2026-10-08 用本机 WLAN 地址重跑关键风险脚本，页面从该地址打开并通过。这不把跨设备访问记成已验证。

## 2026-10-08 补充：协作规则安装到本仓库

用户安装 2026-10-08 的 11 条 Cursor 规则。规则只放在本仓库 `.cursor/rules/`。交接仍写入 `docs/01-development/交接记录.md`，需求变化仍写入 `docs/03-architecture/` 的 ADR，本期未完成仍写入 `docs/01-development/一期未完成事项.md`。

模块边界保持本节：一个业务域一个现有 Maven 模块，包名 `org.dromara`，跨模块走 `aisports-api`。一表一工程、`com.jiechu.retailos`、`plus-ui/src/retailos/`、`.必要流程说明/` 和 `改造计划执行/` 不进入本仓库。生成器仍只下载 ZIP，报名、名额、资金、竞赛和跨组织校验仍按业务语义手写。本期不启用产品 AI，不新建独立 MCP Gateway 或三级 Agent 运行时。

被取代：上一句「本期不启用产品 AI」只被 [ADR-015](ADR-015-通用AI内核与从资料创建赛事.md) 收窄。从资料创建赛事可以使用通用 AI 内核；仍然不建设完整 Agent 平台，也不把 Spring AI 用作模型网关。

## 2026-10-09 补充：本地试用号可以直接入库

本机开发库可以不经过短信注册，写入 `13100000001` 至 `13100000010`。入口是 `scripts/Add-LocalTrialAccounts.ps1`，只允许连接 `aisports-dev-postgres`。每个号写入参赛者租户里的后台用户、平台账号和手机号渠道；渠道摘要与当前本地 `phone-pepper` 一致，密码散列使用《环境运行》里的本地试用口令。不建参赛档案，不改已经绑定同一手机号的账号。`Reset-TestData.ps1` 仍会删掉这 10 个号。这不是生产开户，也不代替注册验收。
