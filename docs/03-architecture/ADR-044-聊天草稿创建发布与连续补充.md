# ADR-044 聊天草稿创建发布与连续补充

日期：2026-10-12。依据：用户要求在草稿操作旁提供创建赛事，聊天可以继续核对发布；年龄、收费等回答写入草稿后，只问剩余事项。

保存表单只更新候选，不占报名名额，也不公开。表单内“创建赛事”先按原版本校验保存当前输入，再把明确创建意图交给既有赛事确认服务；聊天卡也提供创建入口。服务器仍核验本人、组织、版本、必填内容、项目价格和声明选择。重复操作和旧版本沿用原保护，不把一句模型判断当创建授权。

创建成功保留当前任务，聊天卡切换为发布／管理赛事。发布弹窗读取实际赛事和公开费用预览，由用户核对项目、退改及公开联系人后明确发布；沿用既有发布接口与幂等键。缺收款渠道或其他发布条件时展示服务端拒绝，可进入同一赛事工作区完善。发布成功及刷新恢复后显示已发布，收起删除草稿，不办理资金或替参赛者报名。

连续补充以当前候选和最近待确认问题为依据。明确的单项年龄范围写入参赛规程，保留原条款；明确的按人／按单报价更新对应项目价格。单人一人、双打两人以及已确定人数的团体可换算整单价格，同时展示换算；人数可变的队伍保留按人报价，继续确认整单总价。多项目的裸报价只能对应当前明确追问的项目，不能批量覆盖。项目顺序保持，以免下一句对应错行。

对话保存实际补充原句及字段来源，下一步从更新后的缺项重新选择。完整有效价格和已答年龄不再重复追问；费用意向不等于已经配价。改价只替换程序追加的当前报价摘要，原资料收费条件保留。一句包含多个事项时交给模型完整合并，简单报价快捷路径不能只处理费用而丢弃其他回答。模型输出仍是候选；未知对象、金额、权限或矛盾必须继续核对。只记录可见回复、字段和执行结果，不索取隐藏思考。

本轮实现与接受范围见[聊天连续办赛验证](../04-verification/聊天连续办赛验证-20261012.md)。隔离模拟赛事通过不替代三位用户的真机接受、真实收款、短信或现实赛事。

用户补充决定：价格可能已在上传文档内，必须先理解资料，不要求用户重复填价。模型逐项目核对原文金额、计费单位、适用范围与条件；费用必须有实际原句引用。明确整单价直接预填；有逐字按人单价和明确固定参赛人数时，程序用整数分计算整单候选价并保留单价、人数、算式和来源。可变队伍人数、首项／加项、优惠、冲突金额不可展平成一个整单价，保留条件后追问未确定部分。

组合回答仍由模型完整合并年龄、规程等内容；其中独立且明确的报价原句再与当前项目和固定人数核对，避免模型将“每人50元”再次理解成“每人还是每单待确认”。只有唯一项目或明确所有项目的报价适用此纠正，条件收费、问句、否定或多项目歧义不抢答。用户仅说“继续下一步”不提供新的业务事实，候选字段保持，模型只选择后续问题。

用户接续决定：上传资料未说明报名审核方式时，AI建赛默认无需人工审核（none），不再询问是否人工审核，也不提供该缺项选择。默认值标记为平台默认，不伪造文档或办赛人确认原句；在预填表单可见并可修改。文档明确人工审核仍按原文，人工表单和用户明确更改优先于默认；仅咨询区别不改已选方式，真实原文冲突不静默覆盖。初始独立原文核对纳入registrationReview引用，通用摘要不能凭空决定人工审核。后台候选生成、查看、连续回答与创建读取共用默认规则，普通手动建赛其他入口原契约保持。无需人工审核仍遵守ADR-011：免费正式提交后按规则生效，收费必须实际足额收款，不由默认值跳过资金核对。上传完成生成候选，用户按“创建赛事”明确建立，再核对发布。
