# ADR-024 腾讯云注册短信接入

日期：2026-10-09。用户决定：先完成注册短信，现有模板仅用于手机注册；密码重置、注销须匹配各自模板后接入。实施与验收结果见交接记录，不因资源已批准关闭一期全部短信事项。

## 范围与契约

复用工程 sms4j 3.3.5 腾讯适配器，不新增第二套短信 SDK。注册沿用 `POST /auth/participant/sms-code` 和 `POST /auth/participant/register`；不改变账号/档案模型，不新增短信登录。真实短信不回显 `debugCode`。人机验证仍独立办理，不能将发出短信当成阿里云人机验签已完成。

已通过腾讯云模板只读接口核对审核状态和两个参数：注册验证码、有效分钟数。服务端生成六位随机数字，按顺序传入验证码和 `5`；收件人按中国大陆 E.164 格式发送。实现依据 [SendSms](https://cloud.tencent.com/document/product/382/55981) 和 [模板查询](https://cloud.tencent.com/document/product/382/52067)。只发送给单个收件人；必须有且仅有一条 `Code=Ok` 受理状态，不能把空状态或 HTTP 成功当成发送成功。供应商受理与终端收到分别验收。

验证码缓存用途仍分别为注册、重置、注销，有效期五分钟，注册校验沿用已有单次消费。发码在现有 IP 限频外，保留每用途每号 60 秒间隔，增加跨用途同号 60 秒间隔和滚动 24 小时最多 10 次获取限制。限频使用号码摘要；失败请求也占获取次数，避免供应商故障时刷接口。重新获取前作废旧码，供应商受理后才缓存新码；失败不留有效新码。关闭供应商自动重试，避免超时未知结果重复发送。Redis 故障按失败处理，不退回无限发码。

配置在所有环境通过 `tencent.*` 绑定，`TENCENT_SMS_ENABLED` 默认 false。凭据、应用、签名、模板均通过未跟踪 `.env` 或部署环境提供；配置不全拒绝发送。`PARTICIPANT_SMS_ECHO_CODE` 默认 false，仅显式本地模拟且真实发送关闭时可回显；真实服务开启后即使误开模拟回显，也不返回验证码。注册/重置/注销请求参数不写耗时日志，轻量登录事件中的号码脱敏。

## 验证与后续

隔离测试检查参数顺序、国际格式、缺少配置、空/失败受理状态、异常不泄露供应商原文、不重试、缓存顺序、发送失败、跨用途冷却、每日限额、已注册号码和模板用途隔离。`TencentRegistrationSmsLiveTest` 默认不运行，只有显式 external 标签及真实发送开关、已授权测试号码同时提供才发一条测试短信；不创建账号、不写注册验证码缓存、不绕过人机验证。

真实注册页从人机验证、获取短信、输入验证码到账号建立仍需普通用户完整走查。本地阿里云服务端验签原有关闭状态未被本轮更改，正式上线前须完成验签配置与真实验证。密码重置/注销模板、报名邀请/赛事取消通知短信、送达回执及正式环境资源仍列入一期未完成事项。
