# ADR-016 AI 办赛工作台与运营助手接入

日期：2026-10-09。状态：用户授权根据已确认原型替换正式 B 端，并补齐接口；已实现范围与验证见 UI 接入记录。本决定扩展 ADR-015 的产品入口，资格、资金、发布仍遵循 ADR-011。

## 导航与视觉

正式组织工作空间沿用 RuoYi 的路由、身份和缓存能力，隐藏已打开页面标签。一级页使用侧栏定位，赛事工作区及 AI 办赛页使用面包屑；九个赛事任务继续通过 query 切换。管理员保持原生 RuoYi。新样式集中在 business-ai.scss，冷白、青蓝与少量紫色，背景模糊用于导航、AI 图形层和浮窗，正文与表单保留清晰实底。

AI 办赛为主入口，手动创建为同尺寸边框按钮，两条路径都有效。运营概览显示本组织真实赛事、正式报名、资格待审、付款声明待核对、资金收尾及最近提交分布；接口失败显示未知，不填模拟数据。

## 助手边界

浮动助手可拖动、键盘移动、放大/还原，读取当前路由和赛事。聊天、模型回答、保存草稿及设置都不自动跳转；用户明确点击工作区链接才导航。跨页保持办赛任务，同一账号/组织在 sessionStorage 仅保留任务编号以便刷新恢复；文件、草稿和任务归属必须重新经服务端验证。

AI 办赛复用既有资料任务、模型讨论、Java 校验和原子创建事务；新增无文件文字启动入口，初始只建候选任务，不建赛事、不发布。创建成功后可以再次开启新任务。原文件上传和手动表单保留。

运营咨询/推广草稿复用 Node 模型客户端，只返回纯文本，不注册写入工具。服务端读取当前组织及选中赛事的授权数据，不接受客户端组织编号或自报统计。只发送必要赛事内容、七日汇总和最多六条对话；不自动附带成员名单、付款人、流水、证件、附件或登录令牌。调用外部模型须明确勾选同意。运营咨询可拟写文本，不发送或发布。

修改设置通过受控表单调用原 PUT 赛事接口，保留资料和审核设置；页面变化撤销旧表单，服务器继续验证状态、时间和归属。资格、资金、取消与发布继续走既有任务界面，不开放模型自主办理。

数据组件为应用生成的报名统计图，通过无脚本 sandbox iframe 展示，并用 CSP 禁止外部资源。模型输出不作为 HTML 执行。暂不开放任意模型代码运行或组件市场。

## 模块契约与统计口径

赛事模块通过 aisports-api 的 RegistrationOperationsApi 获取标量汇总；报名模块复用管理项目授权和 FeeApi，不跨模块读 Mapper/实体。数据库仍为业务事实来源，Redis 不保存报名、资金或赛果权威数据。未新增表或迁移。

- currentEntries：当前 submitted / approved 整单，包含历史赛事。
- pendingReview：可继续办理且采用人工审核的赛事中 submitted 数量；无需审核、取消、结束或开赛后为零。
- unpaidEntries / declaredEntries：当前正式报名中正额 open 义务 / 已声明的其中部分；声明不是实收。
- pendingFunds：存在未结资金动作的报名，包括退出、取消等历史。
- occupied / capacity：各项目 usedCount / limitCount 之和，单位为组（单），不是人数。
- trend：上海时区最近七日，每条报名最近正式提交时间的分布，包含已退出历史，不累计每次重提。

读取为刷新时的近实时多次查询，不承诺跨表同一瞬间的财务快照。当前复用费用查询按报名汇总，大型历史数据需另做批量聚合和性能验证；不把此页作为财务对账。

## 验证边界

正式构建、隔离接口交互、规则单测、真实匿名拒绝和真实模型连通分开记录。上述验证不关闭普通角色端到端业务验收，不表示任意自然语言写操作、收费项目自动创建或外部渠道发布已经开放。
