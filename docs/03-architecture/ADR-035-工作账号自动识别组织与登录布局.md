# ADR-035 工作账号自动识别组织与登录布局

日期：2026-10-11。依据：用户要求工作账号自动确定所属组织、移除登录前组织选择，其他第三方入口仅保留可见微信，修复登录插图与表单底部断层。状态：工作密码方式及布局已实现、实际验证并安装主站，见[本轮报告](../04-verification/工作账号自动组织与登录布局验证-20261011.md)；微信真实授权仍未开放，设计不代替通过证据。

## 工作账号认证

`POST /auth/login` 新增 `grantType=work-password`。输入为 `username/password/clientId` 及开启时的 `code/uuid`，不需要 `tenantId`。服务端完全不采信该请求中的组织编号；保留旧 `password` 与既有参赛平台、组织授权兑换流程。

工作密码方式仍要求客户端原有完整 `password` 授权项，不增加客户端授权记录，也不按字符串子串判断授权。服务端先执行原账号失败锁和验证码，再在认证内部查询同名候选、核对真实密码，必须唯一命中。不同密码的同名账号可确定对应主体；同密码命中多个组织时拒绝任意选第一条，不向匿名用户返回组织或绑定列表。随后检查实际租户启用/有效期，在服务器确定的租户中重新读取账号并核对密码、状态和主体类型，再签发原若依工作会话。

`app_user`、兼容参赛租户100001、技术平台租户900001及平台账号映射的组织技术主体不能由新入口直接登录。主办方自然人仍通过手机号平台身份及有效组织授权进入，不用技术密码绕过 `asp_staff_grant`。这一边界不因隐藏下拉而放宽。

缺省进入 `/index`，由真实 `getInfo` 角色与菜单渲染政府、平台或相应工作台；已有安全回跳保留，不能把客户端传入的组织或目标路由当成授权。

## 微信入口与布局

工作页移除组织下拉、匿名组织目录请求、语言折叠及其他供应商按钮。微信图标采用仓库已有微信矢量形状，独立静态SVG，不生成二维码或新认证身份。`GET /auth/work-methods` 仅返回 `wechat.available`，本期工作微信授权尚未开放，值为false；点击给真实不可用反馈，保留用户已填账号及密码。不得仅凭存在OAuth配置就假定真实授权可用；原资料绑定及其他既有社会化认证不在本轮改造范围。

共享认证容器明确使用两栏伸展；摄影栏填满实际表单高度，报错、微信反馈或较长注册内容增加高度时仍保持同一底边。手机改纵向连续排列，原账号/注册/恢复任务回跳及输入校验保留。

## 验证边界

新增服务测试覆盖同名唯一定位/歧义、客户端精确授权、失败锁、验证码、账号/租户状态、身份限制及并发重读。真实服务以独立合成工作租户和普通政府/平台账号验证，不改现有人密码或组织授权。浏览器检查工作台路由、微信不可用后表单保留、手机/桌面图片连续及错误态。

工作微信的服务器一次性state、固定安全回调、唯一绑定主体解析及真实OAuth仍需后续独立验收后才开放，不用可见图标当作微信已可登录。原一期真实短信、银行和现场赛事等边界保持。
