# ADR-028 赛事统一收款与打开即用宣传文案

日期：2026-10-10。依据：用户要求项目外部滑动切换免费/收费并输入金额，微信、支付宝、银行、自定义收款码和线下付款统一在赛事维护；打开宣传材料即可有文案，AI海报继续生成，数字错误要可理解。本决定接续ADR-011、025、026、027，不改变实际足额收款才能通过、凭证非强制及提交产生独立义务的规则。

## 费用和收款指引

项目列表直接切换免费/收费；收费显示金额（人民币元／单），明确保存，不默认把未配置项目当免费。新建项目复用同一滑动控件。赛事工作区的赛事设置一次选择全部收款渠道，二维码为已有payment-qr私有组织材料；银行账户只用于付款指引，不纳入公开赛事、宣传事实或AI调用。线下方式必须给出地点或联系办理方式，各二维码必须上传有效图片，银行必须填写开户名、开户行及账号；每类最多一项，不建设支付网关或财务平台。

财务模块维护租户隔离的asp_event_payment_config（V028，V029显式检查JSON必需字段，避免CHECK的NULL结果放过缺项）。FeeApi只暴露就绪判断和用途授权后的指引DTO，模块不交叉引用实体或Mapper。项目金额仍在不可变收费版本，新模式event表示使用赛事收款；已有offline/organizer_qr版本和历史义务不改写。无正式报名时配置赛事渠道后，现有收费项目的新提交同样使用统一指引，不需要逐个重设二维码；免费项目仍免费。新event模式收费项目没有赛事渠道不能发布或正式提交。

配置、改价和正式提交在PG赛事行锁下串行。沿ADR-011，首笔正式提交后锁定项目金额和赛事收款设置，取消/结束同样停止修改。配置带乐观版本，过期表单拒绝覆盖。正式提交把全套渠道、二维码文件编号和说明复制到当次义务quote_snapshot；参与者只读本次快照。旧义务缺二维码快照时读取该义务引用的旧收费版本，禁止回到当前active版本。当前配置和义务快照里的文件都计入保留引用，避免清理旧付款材料。

报名管理人可选择一个渠道付款、查看银行资料和授权下载该渠道二维码。无义务的草稿、跨报名账号、跨组织和平台会话不能读取对应付款资料。可选凭证继续关联当次义务，任何指引、声明和凭证都不替代真实到账核对。

## 宣传文案

打开即从当前赛事事实准备基础标题、邀请、群消息和朋友圈文字，不调用外部模型、不写宣传行。未公开明确筹备、取消明确已取消，未知费用明确待确认；已公开正常赛事可以带实际公开链接。已保存AI文案过期时退回最新基础文案，避免继续显示旧金额。copySource区分basic和ai，saved继续表示实际AI宣传行已保存。

明确同意并点击AI生成海报，沿现有图片→文案→颜色/排版流程。AI文案失败保留已有图片和可用文案，可只补文案。数字校验将198与198.00视为同一个金额，保留手机号等前导零；未知数字的提示指出具体数字、当前赛事资料无法核对、AI版本未保存以及基础文案仍可用。没有通过关闭校验容许模型杜撰金额。

## 验证边界

定向数字/基础文案/渠道校验单测、界面隔离回归、类型和构建；真实普通本地角色按Test-EventPayment验证配置、发布门禁、快照、隔离、图片存储和付款审批。模拟组织、二维码、凭证及资金明确标记，不是真实转账或支付SDK验收；实际结果在交接和验证记录更新，21项功能、17项缺口和7类角色切片不因文档整体关闭。
