# ADR-021 多项目宣传主视觉与文字隔离

日期：2026-10-09。依据：用户认可三种视觉方向，要求主视觉依据赛事信息生成并兼容后续其他项目，内部实现细节由开发处理。本决定接续ADR-017/020的固定插画阶段，不扩大一期竞赛业务的羽毛球试运行范围。

当前接续：[ADR-022](ADR-022-Seedream平面体育主视觉.md)已按用户要求改用Seedream 5.0 Flash和平面体育设计。以下场馆图、图片上小标识及未配置供应商是当时阶段记录；当前默认图、渐变排版与实际接入状态以ADR-022及最新交接为准。

## 生成与排版

文案模型和图像模型是独立能力，不能把现有聊天密钥默认发送到新供应商。Node提供/internal/visual，配置AI_IMAGE_API_KEY、AI_IMAGE_ENDPOINT、AI_IMAGE_MODEL；HTTPS images/generations兼容接口，仅接受base64图像，不抓取模型返回的任意URL。默认1536x1024，响应和图片分别限制8MiB/5MiB；Java读取真实图片尺寸，512以上、边长不超过3840、像素不超过8294400。部分兼容模型需要AI_IMAGE_RESPONSE_FORMAT=b64_json；GPT图像模型原生返回base64，不发送不支持的该参数。契约依据[官方图像接口](https://developers.openai.com/api/reference/resources/images/methods/generate)，供应商适配和真实质量仍需实测，不能以兼容格式宣称所有厂商可用。

图像只接收服务端赛事名称、运动项目，以及办赛人选择的受众、关键词和视觉风格；不发送联系人、收费、报名材料或身份编号。明确运动项目优先于名称暗示，未知或歧义项目提示使用通用运动氛围，不默认羽毛球、不混入无关器材。模型只生成无字示意主视觉，不生成标题、日期、金额、链接或二维码；画面不冒充实际场地照片。自动风格选择依据名称/项目/受众/关键词，只影响视觉语气，不推断报名资格。

图片仅占上方主视觉区域，保留中央裁切安全区；文字区使用不透明纸色与深色字，图片上的小标识有不透明底。标题/邀请/完整费用按实际字体测量换行并扩展画布，CTA与二维码各有独立保留区；已取消不放报名二维码。信息始终来自当前赛事事实，图像生成失败不撤销保存文案或既有图片。

## 保存与授权

新增POST /sports/b/events/{eventId}/promotion/visual（consent/style/audience/keywords），原生成文案入口保留；配置图像能力时生成文案后可接续主视觉，换风格不会仅因选择就触发付费请求。PromotionView增加projectName/imageEnabled/visualFileId/visualStyle/visualStale。赛事归属在调用前核对，同赛事Redis锁防并发重复生成；网络请求在数据库事务外，短事务重新核对名称与项目、锁宣传行并写文件引用，数据库乐观版本保留。24小时内每租户每赛事最多10次请求，失败及缓存复用也计请求次数；没有完整计费/额度平台。

V025在asp_event_poster新增四列主视觉文件、名称项目摘要、完整请求摘要、视觉风格。图片复用StoredObjectApi的event-banner用途和组织隔离，仅在宣传材料关联，不覆盖赛事公开封面。相同名称/项目/受众/关键词/风格复用已有结果；名称或项目变更后不再显示旧主视觉。其他赛事事实变更继续沿原factDigest过期机制处理。对象存储与数据库仍沿既有文件生命周期边界，后续替换图片的孤立对象回收需沿保留/清理事项接续，不新建媒体管理平台。

无配置时不假装实时生图：优先现有宣传图，否则使用本轮生成的通用运动场馆素材；该素材没有羽毛球或其他专属器材。已有三张带文字方向图仍是提案，不作为正式背景。通用素材在plus-ui/public/images/promotion/sport-neutral-arena.png，由内置image_gen生成并复制入项目；未接入Codex工具作为产品后台调用。

## 验证与剩余

真实迁移、编译、单测、UI隔离夹具、图像像素/导出检查与实际供应商生图分开记录，见交接。当前环境图像端点/模型/密钥未配置，不声称已完成真实动态生图验收。需要正式供应商接入后核对真实多项目器材、风格、图片质量、延迟/失败、存储与普通角色隔离；原一期业务切片不随此文档关闭。
