# ADR-033：悬浮助手、传奇段位与世界荣誉认证

- 日期：2026-10-11
- 依据：用户本轮明确要求全局可移动聊天浮泡、紧凑赛事筛选、资料页头像上传、更高级静态头像框，并追加传奇及世界前三名认证。
- 状态：设计与实现依据；实际运行和开放结果以本轮独立验收回执为准。

## 产品交互

参赛端使用一枚全局浮泡，登录及注册页不显示。登录导航不再放重复助手入口，赛事列表不再放独立“AI找赛事”按钮。公开咨询与已登录办理任务共用可拖动、放大、缩小、调整尺寸的聊天容器，原消息和任务记录保留。规程及初次参赛、办赛等功能卡保留，点击只选择可取消的主题，输入框默认留空且保留用户自己的草稿；只有用户发送时才提交主题和本人文字。服务端当前任务的具体答案选项仍可由用户明确点选。位置保存只包含界面坐标。

赛事筛选收为一行搜索与选择控件。首页五项业务入口复用受管理的运动艺术资源；文字、焦点、点击及业务跳转继续使用实际按钮或链接。图片禁用原生拖拽，避免拖动误触。手机和桌面保持卡片对齐，动效遵循减少动态效果设置。

下拉使用统一浅色浮层，保留键盘、required及错误反馈；输入焦点为中性轮廓，错误保留红色。聊天窗入场440ms、退场280ms，尺寸切换采用540ms的FLIP视觉变换，响应布局一次提交，避免逐帧改宽高；减少动态效果时跳过。动画时长不是固定帧率或设备性能承诺。聊天功能卡使用独立透明静态图片，保留真实文字和点击语义。

头像上传和裁剪集中到“完善资料” `/portal/profile`，保留 `/portal/identity` 兼容地址。公开名片与参赛实名资料继续分开。工作账号访问公开页面时不读取参赛者私有资料。

## 成长与认证分开

成长序列为新星、青铜、白银、黄金、铂金、钻石、星耀、王者、传奇。默认传奇门槛 19200 分；门槛由版本化成长规则管理，历史积分和奖励不重放。八种可装备段位各有独立透明头像框，新星保留欢迎样式。高段位使用轻量流光与粒子层，减少动态效果时关闭动画。

世界冠军、世界亚军、世界季军是独立外部荣誉，不通过成长积分自动授予，也不替换已获得的成长段位。认证申请记录实际年份、赛事、运动项目、名次、结果来源和私有证明。平台负责人手工核实本人身份、世界级赛事性质、公布主体和正式结果，按当时资料版本确认。未经核实的申请不显示认证徽章。

申请可保存、提交、补正、通过、拒绝和撤销。通过后默认不佩戴、不公开。本人选择佩戴，每个运动项目同时佩戴一项认证荣誉；对外展示同时要求公开名片和该项荣誉两次授权。撤销立即停止佩戴和公开，并保留决策历史。材料只能由本人和授权核实人读取，历史引用材料不能被未引用文件清理任务删除。

徽章标题由核实后的年份、赛事、项目、名次生成，不能直接接受用户或模型自称。用户举例中的年份和赛事不作为事实或预置奖励写入。

世界冠军、亚军、季军各配独立透明徽章及头像框。仅有效、已佩戴、对应运动、带合法核验年份的批准展示投影使用世界框；不从未批准申请、空快照或互相冲突的佩戴记录推断最高名次。世界框不替换成长积分、参与称号与队长标识；段位目录只预览成长框。九项新图片的提示词、原图和派生文件摘要见 `docs/05-ui/assets-20261011-v4/assets.json`。

## 工程与开放

复用 `asp_honor` 的独立表模块及 `asp_file` 私有文件、动作执行、审计和通知能力。V037 增补传奇规则，V038 追加认证字段；已应用迁移不重写。跨表动作使用现有公共契约和事务执行器，不引入表模块实现互依。

六项认证动作只开放人工 UI 渠道：保存、提交、核实、佩戴、公开范围、上传证明。模型不能确认外部荣誉，Agent 渠道保持关闭。开放前绑定实际 JAR、源文件、定义摘要、测试证据，执行真实备份并核对无关渠道及业务事实。

合成材料可以验证系统流程、授权和存储，不能证明某人具有真实世界荣誉。真实核验机构、证据核验责任、首次实际认证和真实赛事闭环仍需单独验收。
