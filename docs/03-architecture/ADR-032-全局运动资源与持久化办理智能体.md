# ADR-032：全局运动资源与持久化办理智能体

日期：2026-10-11。状态：用户批准实施，分项验证。接续 ADR-029—031；原业务母版及冻结验收不重写。

## 用户决定

采用已确认的独立产品风格，覆盖参赛、主办方、政府与平台实际页面。移除固定界面的广告口号、演示和研发成熟度说明；真实业务错误、授权条款、测试资料中的模拟标识以及岗位管理信息不冒充成功或正式数据。

登录入口改为轻量账户入口，认证页面不放助手。全局助手改为小尺寸无星形/菱形点缀的运动图，禁止原生图片拖拽。重新设计聊天窗口、任务卡、补问、材料提示、历史恢复与固定底部输入。问答和页面通过业务对象上下文衔接。

## 成长与艺术资源

新星0、青铜40、白银120、黄金400、铂金1000、钻石2400、星耀4800、王者9600。这是参与成长段位，不是竞技实力排名。V035新增不可变规则版本，保留旧规则、积分与荣誉事实；历史“荣耀”名称保留，展示艺术兼容星耀资源。

七档独立位图徽章、七种原生透明头像框、六种原生称号饰件、三枚金银铜正式奖牌及两张运动艺术背景接入组件。称号在头像上方，佩戴仍由本人或队长选择已获得荣誉。未知段位保留文字；未知奖项使用中性展示，不依据模糊名称猜测金牌。

图片只装饰，不烘焙时间、费用、状态、声明和正文；表单、错误与确认保留可读文字。艺术角落层不挡点击。响应布局使用等高卡片与明确图片边界；动画尊重减少动态效果。

## 持久化办理智能体

V036将工具目录、技能、业务地图、分工和摘要写入现有 `asp_agent_version`，八个职能定义追加第二版，历史运行锁定原版本不变。持久化目录包含11个MCP工具；只有6个受控通用运行工具可被智能体使用，旧人工会话工具不转成运行授权。六项技能与五条业务流程包含前置、依赖、人工责任和能力编码。

服务端每次过滤当前身份、授权、组织、能力开放渠道与页面对象；技能说明不能授权，UI开放不等于Agent开放。工具、派生回答和运行历史均保持本人范围。任意地址、伪造回执与伪造完成卡片由服务端过滤，补问每轮最多三项。

模型先理解目标和当前进度，已授权且输入齐全的事实查询优先真实读取，再给下一步及必要问题；缺材料说明用途。发布和正式报名停止在具体确认内容，政府审核、实收退款、正式结果和奖项保持责任人确认。记录可见目标、补充、工具、回执、用量和版本，不保存隐藏思考。

真实测试发现模型返回非法结构以及只给清单、不读本人事实。失败运行保留；修复限定在通用编排和输出协议，不用伪造回复兜底。最终结构化回复使用受约束JSON格式，工具办理阶段保持正常受控调用，排版不重放工具。原个人任务接续后真实读取本人成长、报名和房间；其他场景实际读取比赛类型和本组织赛事。结果与授权边界见最新独立验证记录。

## 开放与交付边界

先在既有5192/8082演练环境通过管理员API候选开放五项只读能力：比赛类型、房间查询、本人成长、本人报名及组织赛事。主站新渠道通过主站管理员办理，写动作按逐项证据开放。新资源和持久化目录不表示所有能力已通过真实模型执行。

实际备份、恢复、迁移重复执行、旧业务事实摘要、编译、页面及普通角色查询分别留证。实时外部生图、真实短信、资金和现场赛事及完整一期21/17/7验收仍按未完成清单处理。新验证报告独立于原冻结报告。
