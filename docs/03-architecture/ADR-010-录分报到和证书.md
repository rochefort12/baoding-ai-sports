# ADR-010 录分、报到和证书

日期：2026-10-06。状态：已开发，待业务验收。迁移 V013。

本次同步目标见 [ADR-011](ADR-011-一期业务收口与交付边界.md)，变更尚待实现/验收。

本决定细化 ADR-002 的 M1.7。业务流程见 [录分报到和证书业务流程](../02-modeling/录分报到和证书业务流程.md)。

## 决定

报到、场次、结果和获奖写在赛事组织租户。不抽签/自动编排/自动发奖，不改冻结名单。收费资格通过有有效实收前置；通过后冲正欠款无人报到时暂停新报到，已有报到/场次人工协调，不自动清除结果。免费和其他足额有效款不误拦。取消停止全部新执行/证明，结束后不新增正常报到/场次，但可整理已有场次结果、依据及资金。

手工场次挂在一条内部阶段上，格式记为 `SYSTEM_MANUAL`。这条阶段不展示给用户，也不解释成小组赛或淘汰赛。阶段的规则版本为空。不为了满足外键去写一条虚假的竞赛规则。

一个场次只有一条结果。草稿可以改。正式确认后的状态是 `confirmed`，本期不能改、不能删、不能被导入覆盖。逐场录入和批量导入写的是这一条，导入只进草稿。

获奖按报名授予并关联正式结果或承办方确认的排名依据及操作者/时间，再按冻结名单投影 `asp_honor`，共用 `award_key` 和 `registration_id`。私人页面证明展示赛事、组织、项目、称号及日期，不冒充外部官方等级。本人可见所参与场次的正式赛果，无奖也可看；不见草稿/无关私人信息，双打各看本人单，取消历史标识。队长不能因此看队员私人证明。

请求键记在 `asp_execution_command`。相同键且内容相同则返回原结果，不再写第二笔。相同键但内容不同则拒绝。另一把请求键也不能突破「一场赛事一个人一次有效报到」和「一个场次一条结果」。

办赛人员沿用 `organize`。不新增产品角色。

## 本期不做

抽签、自动赛程、专项计分、改判、检录、自助报到、实际出场、证书文件和公开链接。旧“不考虑付款报到”的规则不再覆盖 ADR-011 的误确认冲正报到限制。

## 2026-10-07 实施落点：导入只查找当前项目

批量导入必须带上办赛人员当前选中的竞赛项目。场次编号只在该项目的手工阶段里查找。别的项目可以有相同编号，导入不会写入那一场；当前项目没有这个编号时直接拒绝。同一次导入的请求键把项目编号算进内容，换到另一个项目会被拒绝。逐场保存的请求键包含场次编号。同一把键、相同比分换到另一场会被拒绝，重试仍返回原结果和原场次。场次列表带回草稿里的双方胜负，重新打开录入窗不再把 A 负改成 A 胜。

## 2026-10-07 实施落点：取消后停办，以及本人赛果和获奖依据

赛事取消后，报到、建场、保存或确认结果、导入和授予新证明都拒绝。已经确认的结果和证明仍可查看。本人在「我的证明」里看到自己所在已冻结名单对应的已确认赛果，包含场次、比分和双方胜负；赛事已取消时标明这是历史。不返回录分草稿。

授予称号必须填写依据，并和称号一起写入获奖事实。称号不能写成运动员等级或官方认证。
