# ADR-012 UI 入口与原型交付

日期：2026-10-07。状态：品牌暂定名称及两端要求由用户提出；首版色彩/标识/布局为待评审设计建议，原型已生成，正式界面未接入。

## 用户要求与决定

用户要求 B 端“简洁方便直观，操作不复杂，需要能复用 ruoyi 框架前端”；C 端“独立入口和界面”。品牌名称暂定“AI运动”，暂无 Logo、色彩及指定参考产品，授权结合保定、AI、参赛者/运营管理关键词提案。

先交付可点击 HTML 原型及设计说明，用于评审，再按业务实施顺序落实到现有 Vue 3 / Element Plus 前端。两端视觉和入口独立，技术上继续复用同一 plus-ui 工程；不新增第二套账号或后端，不把独立入口解释为新工程/小程序承诺。HTML 不是原生 Figma 文件，不宣称已实现业务。

## 设计与实现边界

本轮采用临时几何 A 标识、莲池绿/暖橙和原创羽毛球矢量插画。颜色、图形、排版均待用户评审；AI 品牌不意味着一期增加智能审核/推荐/助手。C 端优先手机，B 端优先电脑；正式实现复用 RuoYi 菜单、授权和 Element Plus 基础组件，共用样式集中在 plus-ui/src/assets/styles/。

原型数据全部虚构，只在浏览器内模拟；不生成真实二维码、不连接支付/退款/短信接口、不修改当前业务数据。界面区分资格、声明、有效实收、退款、报到及通知；业务语义继续以 [ADR-011](ADR-011-一期业务收口与交付边界.md)为准。原始母版不修改。

## 交付与后续

入口与范围见[UI 设计说明](../05-ui/AI运动-UI设计说明.md)。本轮为重点页面原型及部分入口概念片段，未设计页面明确记录，不能按全部 Page Map 或普通角色验收宣称完成。

已有 R01/R02/R03 修复与下一步 R04 的实现顺序保持，以最新交接为准；UI 评审/原型工作不覆盖该顺序。正式 Vue 页面、其余详细交互和实际验收继续在[一期清单](../01-development/一期未完成事项.md)中跟踪，不增加已确认业务范围。

## 2026-10-07 补充：通用体育平台与保定城市站

用户明确：羽毛球只是一期试点，UI 应为通用赛事平台，并考虑后续场馆运营、本地生活撮合、体育信息流；可以按效果判断是否放未来入口。另要求保定元素增强，但运动仍为主。首版首页把羽毛球当整个平台主题的表现被取代，见本节；原配色仍属待评审建议。

决定：平台品牌、主导航与首页不绑定单一运动。C 端采用首页/赛事/我的运动/我的；新平台首页 C00，赛事目录按项目扩展。场馆与运动生活放首页次级预告，不增加多个空的一级栏目；体育信息归运动生活方向。预告明确未开放，介绍愿景与返回路径，不做虚假交易/预约/发布/匹配或上线时间承诺。

B 端在同一组织/授权上下文中区分平台工作台、赛事运营空间与后续场馆/内容生活服务空间。未来空间只做设计预告，不创建实际权限菜单或继承赛事权限。现有 RuoYi 前端与模块化单体决定保持。

保定采用城市站、当地文案和低对比古城/亭檐/莲池概念线稿，运动者/跑道/球类为主视觉。不是官方地标复原/品牌授权，AI 品牌不表示新 AI 功能。

这是平台 UI 定位与扩展结构调整，不扩张 ADR-011 一期可运营能力。其他运动赛制、场馆商业预约、撮合/资讯发布等规则、权限及交付另行明确；预告不作为一期功能补齐或验收通过。详细说明见[平台级 UI 信息架构](../05-ui/平台级UI信息架构.md)。既有代码修复及下一项继续以最新交接/清单为准，不固定为历史 R04 顺序。

## 2026-10-07 补充：办赛申请与审核结果在 B 端承载

用户要求补齐“我要办赛”、申请办赛及后续审核查看；平台超级管理员复用 RuoYi 原生并追加审核业务页，其视觉原型本轮可以暂不添加。决定：C16 保留发现入口，新增 B16 申请及 B17 本人进度/版本详情；准入前使用平台账号，准入且获得有效组织授权后进入 B02。首版原型的申请说明弹窗替换为完整办理链路，平台审批 P01/P02 的一期业务要求不取消。

“资质审核查看”沿 ADR-004/ADR-011 的平台办赛准入审核，不擅自启用正式资质认证、固定证照清单、补正/到期。保留一人一份申请、待审冻结、拒绝版本及重提历史；通过只表示办赛准入，不宣称主体验真。材料上传按最新文件边界后置，不修改旧业务代码或已有文件，原型可无附件提交。

## 2026-10-07 补充：B 端框架一致性

用户指出办赛申请与其他 B 端界面不一致，要求先核对地图/旅程及样式元素。核对 38 个现行逻辑页面、八条旅程和 13 组状态，未发现定义删除，但局部原型未覆盖全站。决定申请服务与组织工作台共用 B 端侧栏、顶栏、页面标签、任务标签、卡片/标题/按钮及移动菜单；准入前后的权限菜单与上下文仍按原规则区别，不能因统一布局给未准入账号赛事操作。正式路由和标签导航复用 RuoYi 原生布局/TagsView，不引入标签页独立会话。详见 [覆盖检查](../05-ui/UI覆盖与一致性检查.md)。

## 2026-10-07 补充：平台账号入口与任务返回

用户要求消除 C00 / 本人档案落点冲突并补齐 C03/C04 原型。决定：访客根入口与普通平台登录均到 C00；合法原任务优先，报名缺档案再补齐返回，不统一强制建档、不自动提交 / 付款。C 端独立手机号登录 / 注册 / 恢复 UI，管理员保留原生 /login 用户名入口；沿原平台账号和组织授权契约，不新增账号种类。C 端移除租户、社交、记住密码、语言及若依品牌页脚，保留实际启用的验证码；表单空白，无预填凭据。注册标题“注册”，成功回登录并保留安全目标；恢复同样回登录，真实会话撤销按既有规则。

C12 主承载确定为 C11“加入/退出记录”标签，随 C10/C11 绘制；C10 保留本人历史投影，退队者不能获得完整队伍详情权限。不新增历史一级页面，不用标签设计冒充新增后端全队历史权限。

正式目标 `/portal/home`、`/portal/login`、`/portal/register`、`/portal/forgot` 待 Vue 实施；旧路由需兼容，匿名白名单逐页限定。本轮交付 HTML 模拟及 [登录与导航决定](../05-ui/登录与导航设计决定.md)、[Cursor 实施提示词](../05-ui/Cursor-前端登录与导航实施提示词.md)，不修改正式认证代码 / 数据，真实服务与普通角色验收仍按最新清单。

## 2026-10-07 补充：公开页沿用原型版式，宣传图替换默认球场图

文首「正式界面未接入」和「颜色、图形、排版均待用户评审」只保留为当时的状态。用户已要求正式 C 端公开页的布局、样式和图例贴近 HTML 原型。虚构赛事名称不进入正式数据。

这不改变报名、收费、审核和取消规则，也不把 B 端页面改成同一套版式。
