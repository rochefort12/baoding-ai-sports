# ADR-017 文字办赛与宣传材料

日期：2026-10-09。状态：用户已确认方案。办赛端按此实现。参赛引导只记录，等 C 端界面改完再接入。

## 文字规程

办赛人可以把规程原文贴进 AI 办赛。这段文字就是资料来源，和上传文件一样进入识别、对话和确认创建。不把整段规程截成一句聊天。短的办赛想法也可以贴在同一处。上传资料和手动创建保留。

单次不超过 20000 字。正文存在任务的解析结果里，不另存成对象存储文件。

## 宣传材料

入口在办赛助手，并且必须已经选中一场赛事。一次生成三份材料：

- 群消息：微信群和 QQ 群共用，可以复制。
- 朋友圈：短句加一张竖图。
- 海报：同一套画面，可以打印、下载 PNG、下载 PDF。

模型只写标题、邀请、群消息和朋友圈短句。时间、地点、承办、项目金额由程序按当前赛事填进画面。文案里的数字必须能在这些事实里找到，否则整次不保存。不写官方认证，不自填名额，不由模型写链接。

已发布的赛事才放公开路径和二维码。草稿和已下架可以看版面，不放链接。已取消的群消息要写明已取消。赛事事实变化后，已保存的材料标成过期，二维码先拿掉，办赛人重做后再放。

不代发到微信或 QQ。图像生成密钥 `AI_IMAGE_API_KEY` 留空，不请求生图。有宣传图就用宣传图，没有就用固定插画。

材料写在已有的 `asp_event_poster`。V024 补正文、事实摘要和公开路径。群消息继续用版式 `wechat_group`，QQ 不另加版式。来源编号只放在路径上，打开次数仍等公开页以后再统计，本轮不改 C 端。

## 参赛引导

参赛者用同一段对话找公开赛事、询问一场比赛、查看本人报名。模型决定要不要查，程序只提供只读事实，不代报名、不代付款。等 C 端界面修改结束后再改参赛端。本轮不改 C 端页面、公开页和参赛接口。

## 接续：多项目无字主视觉

最新依据为[ADR-021](ADR-021-多项目宣传主视觉与文字隔离.md)。用户认可方向并要求兼容其他赛事；已实现独立图像服务适配和无字主视觉保存，原本轮不请求生图的阶段安排由该决定接续。当前环境仍未配置正式图像供应商，不把接口实现写成真实动态生图完成。
