# ADR-030：产品组件与视觉体系

日期：2026-10-10；2026-10-11 按已批准的独立视觉更新。状态：依据用户要求实施。用户要求自有 JS/TS/CSS 组件化，并明确成熟产品、丰富交互和实际功能优先。

## 决定

采用 Vue + TypeScript 原生基础组件和集中 SCSS 设计变量。2026-10-11 用户批准的视觉使用暖白底色、石墨文字与主操作、运动橙重点、少量金属荣誉色；替代早期深绿方案。标题、主操作、状态、下一步先于说明文字；展示实际赛事、队伍和记录，不为视觉效果创建业务数据。

参赛、主办方、政府和平台共用品牌及基础视觉。参赛端突出赛事、席位、称号、成长和报名进度；主办方突出待办与赛事；政府突出分配范围和审核；平台突出对象和能力管理。手机布局保留必要任务，表格在容器内滚动。

建立 SportButton、SportField、SportCard、SportPill、SportTabs、SportMetric、SportHeader、SportEmpty、SportBrandMark 和 CourtScene。共享标题和空态适配已有 Consumer 入口；原生输入用于参赛登录/注册/找回密码及工作账号登录。焦点、显隐、校验、忙碌禁用、键盘筛选和减少动态效果均属于组件契约。

全局样式从 index.scss 统一装配，业务和旧 AI 外观先于 design-system.scss；移除页面对全局样式的重复导入，避免运行时顺序导致端之间变色。若依菜单、会话、权限、租户及复杂业务控件继续复用，样式变化不改变授权。

## 边界与验证

本轮不迁移数据库，不重新发布能力，不改变 Agent 渠道开放状态。资金、资格、正式结果仍由已有业务动作处理。复杂表格、上传、日期控件和业务弹窗继续使用已有实现；本轮交付不是全量控件库替换。

真实隔离服务验证普通角色页面及原生表单，主环境验证匿名首页/登录。模拟账号和业务事实仅用于隔离环境；首次真实注册、短信、多格式材料模型办理、真实赛事和资金等仍按原一期清单验收。证据追加新版本，保留之前冻结的发布记录和失败记录。

## 2026-10-11 首页与认证交互修订

首页“我的集结”和参赛待办采用同一网格轨道：桌面纵向两卡等高，窄屏横向两卡等高；真实名称按可用宽度换行。空态占赛事网格整行。页头登录为轻量账户入口，文字保持可读对比度，品牌图标在各断点保留。消费端头部、正文与页脚使用一致的内容边界，手机避免叠加两层横向留白。

静态主视觉、品牌与助手入口图片显式关闭原生拖拽；全局图片禁用浏览器图像拖拽，Shell 对原生 img dragstart 做补充拒绝。该限制不取消文件上传拖放、文本选择、正常链接点击或保存图片的显式入口。助手入口只保留小图和简短任务文案，认证页不提供助手入口；聊天内容和业务执行另按智能体契约办理。

认证页使用真实落地的运动静态图片作为左侧视觉，表单为独立高对比区域；返回链接与注册、密码恢复继续保留原任务。删除“当前未启用某厂商验证码”的配置说明，真实验证加载或发送失败仍反馈错误；只有接口返回实际模拟验证码时才展示演练事实。样式调整不更改注册验证、短信通道、密码规则或权限。

本轮用 Test-HomeAuthLayoutUI.mjs 仅检查主站5190与演练5192的匿名首页、登录、注册、密码恢复，在390/730/1024/1440宽度下检查布局、等高、静态图拖拽、品牌可见、登录文字对比度和返回任务。此检查不发送短信、不注册、不登录、不办理赛事，不作为真实用户注册/恢复或一期业务闭环验收。截图必须目检，自动几何结果不能替代视觉评估。

补验 Test-HomeAuthenticatedLayoutUI.mjs 只使用既有隔离普通参赛者会话，真实读取本人名片和首页进度，检查同四断点及减少动态效果、两入口桌面页脚对齐，不重新登录或重放业务。匿名二轮32页面/297项通过，私有回执保留 home-auth-1791684245035；首轮32页面回执也保留。普通会话首轮25项通过后，目检发现手机赛事卡正文过窄，原回执 home-authenticated-1791684440394 继续保留。赛事卡模块修复封面和正文列宽后，补验增加封面与正文可读宽度检查，四断点复测29项通过，回执为 home-authenticated-1791684701108；390宽截图已目检，封面、地点、费用和正文正常呈现。上述结果只证明这批页面和布局边界，最终类型、构建与整体结果以本轮汇总验证为准。
