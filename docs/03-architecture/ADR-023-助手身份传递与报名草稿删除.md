# ADR-023 助手身份传递与报名草稿删除

日期：2026-10-09。依据：用户将报名查询、审核付款解释、宣传图片保存链路及报名草稿删除边界交给本轮处理；界面调整由Cursor接续。延续ADR-011，不改收费、资格、租户授权和资金规则。

## 本人查询与模型解释

Java给Node的内部JSON也必须遵守Long字符串传输。原guide方法把平台账号写为数字，JavaScript解析后舍入，回调因此查询错误账号。改为原样字符串，Node回调不采用模型指定的账号；旧的不安全数字请求拒绝，不尝试猜回原编号。实际只读核对发现准确编号对应2条本人创建报名，舍入编号0条；包含成员关系的本人工具返回3条。证据仅保存计数，不保存账号、手机号或成员资料。

本人快照超过最后一页仍保留真实total，返回空页而非异常；序列化失败明确报读取失败，不伪造空报名。模型回答本人进度须本轮查询，读取拒绝/失败/缺少total不能解释为没有报名。草稿、邀请、正式提交及通过分别理解，付款声明不等于到账。

办赛讨论、运营咨询与参赛引导使用一致的审核收款解释：人工审核由承办方核对决定，收费实际足额收款才可通过；无需人工审核的免费报名提交且检查通过后生效，收费需真实足额收款且重验申请、窗口和规则后生效。咨询区别不改变审核模式；无需审核不表示谁都能报。实际合成模型咨询样本正确区分两种方式与收费条件，action为ask，未修改审核选择；样本不代表全部模型质量验收。

## 宣传图片保存

失败日志定位到asp_file所有者账号外键：后台sys_user编号被误当平台账号。保存前通过OrganizationSessionApi获得仍有管理授权的平台账号，并核对当前租户；保存图片使用该平台账号，不能通过放宽外键或造账号绕过。赛事授权、同意、限频、同赛事锁与生成后重验保持。

promotion/visual可独立于文案调用。模型成功后短事务创建空宣传关联行并保存图片，返回现有PromotionView；saved仍为false，直到三个渠道文案完整生成。空关联行不表示宣传文案、发布或外部发送成功。后续生成文案沿同一行保存，保留已有关联图片，不覆盖公开封面。并发更新失败仍回滚，不静默覆盖。

## 删除从未提交的报名草稿

新增DELETE /sports/c/registrations/{registrationId}，登录本人原提交人或代表队当前队长可操作，不能仅凭知道编号删除。按团队锁→容量锁顺序，事务内重验办理权及报名状态，遵守组织租户。

仅draft且从未正式提交可删除。submittedAt、正式提交幂等键、名单版本、付款义务任一存在均拒绝；任何成员仍占名额也拒绝。撤回后的draft不删除正式历史，不办理退款或释放容量。先清理本次成员字段值，再删成员和草稿，旧邀请链接失效；版本条件删除失败回滚。最小业务审计记录操作者、对象、时间及成员数量，不保存个人材料。

无新表/新迁移，不重写历史迁移。界面入口、取色和历史会话不在本轮编辑范围；前端接续契约见对应界面说明。真实普通角色、跨组织、删除/提交竞争及完整对象存储验收继续保留。
