# ADR-018 C端AI发现与公开参赛咨询

日期：2026-10-09。用户已确认 D 通用运动插画与桌面/手机结构，并授权替换正式 C 端；本轮实现界面和公开只读咨询，原报名业务规则仍以 ADR-011 为准。

## 决定

正式 C 端使用独立 ConsumerShell，与 B 端共享冷白、青蓝、深蓝及少量紫色 AI 光感。首页采用已有 D 平面社区运动插画、左侧渐弱背景、局部玻璃命令卡；赛事与办理正文保持清晰实底。原 HTML 与概念图继续留在 `docs/05-ui/ai-native/`，不把原型的虚构赛事、伙伴或本地草稿迁入业务。

发现首页突出 AI 找赛事、看懂规程、我的下一步，同时保留手动筛选、赛事详情、项目选择、本人资料、报名、邀请、资金办理和结果查询。桌面主导航是发现/赛事/我的参赛，个人入口在右侧；手机有发现/赛事/AI助手/参赛/我的。未开放的段位、陌生人社交、信息流学习、出行与本地商业服务先不展示，不出现无法办理的按钮。

赛事目录的项目取自真实公开赛事，不固定为羽毛球，也不虚构其他项目供给。首页按公开阶段排序、报名中优先，并说明推荐口径；不推断竞技水平或宣称个性化模型推荐。

## 只读接口与模型边界

新增 `POST /sports/public/ai/assistant`，匿名可用，请求为 `eventId? / message / consent / project?`。同意项必填真，问题不超过 2000 字，项目筛选不超过 80 字。使用现有 IP 限流，默认每 60 秒最多 6 次，包括无效请求；只读 POST 关闭前端写操作重复提交拦截，保留发送中防重与服务器限流，允许即时重试。

服务端通过 EventPublicationService 重查正式公开范围：已发布且所属组织仍准入。指定赛事不可见时直接拒绝，不能降级成读取其他赛事。未指定时按阶段优先取最多 8 场；可按明确项目过滤。取消和阶段保留，不把已取消、未开始或截止赛事当可报名。

模型仅接收最小公开快照：赛事名称、项目、地点、比赛/报名时间、阶段、取消状态、公开收费描述。选中赛事时另取公开项目价格/付款方式、审核模式、文字规程/须知和公开退改原则；两份文字各最多 6000 字，注明截断或存在图片。图片本轮不识别，价格以费用 API 配置为准。联系人、付款指引、附件编号、登录令牌、租户身份、私人名单/证件和付款人不进入该上下文。

复用 Java 到本机 Node 网关的内部令牌和原兼容模型客户端；网关采用 `consumer.participation` 场景，不注册工具、不持有用户会话、不写业务。提示明确引用赛事和信息部分，缺项或图片请查看原文，不判定最终资格。模型纯文本与服务端生成的来源卡片分别呈现，不执行模型 HTML、脚本或链接。来源卡片意味着本次提供给模型的数据范围，不能当作每句回答已自动核验。

响应为 `reply / sources / refreshedAt`。来源含服务端赛事编号和固定详情路径；前端自己构造站内链接。浮窗聊天不会改变路由，只有用户点击卡片进入详情；切换赛事清除旧问答与同意项，避免沿用旧依据。窗口可拖动、放大、还原和关闭；手机使用底部入口。

## 私人进度与手动办理

“我的下一步”是受控业务组件：有平台身份才调用既有本人报名/收到邀请接口；访客显示登录入口，失败显示重试。它与报名详情共用状态解释，成员确认来自真实成员状态，资格、付款声明、实际资金分别维护。个人数据不发给模型，不把付款声明当资格通过。

办理动作始终由原页面和服务端校验执行。此次没有修改提交、名额、审核、撤回、资金、成绩和通知事务，没有新表或迁移，没有模型自动报名、支付、确认伙伴或跨组织查询。

## 验证与剩余边界

验证证据与真实验收分开，见 [正式接入记录](../05-ui/C端AI正式接入记录-20261009.md)。UI 夹具中的身份、模型回复和写入禁止只验证交互；仍需普通参赛者在真实组织赛事上完成完整链路。模型问答在上线前需继续进行规程缺项、图片、规则冲突、注入与错误回答评测，以及容量/费用观察；本轮不把这些列为已验收。

## 2026-10-09 同一段对话检索和本人报名

找比赛不再由服务端按问法先取 8 场。模型根据这句话和之前的对话决定检索条件、是否重搜、是否用偏移继续看下一页。后端按名称、项目、地点和收费说明做相关性排序，报名阶段靠前，默认不含已取消；每次最多返回 8 场，并带回总数和是否还有更多。页面同时写明还有更多。

正在查看的赛事只作为编号交给模型。模型需要规程或收费时再读取这一场。未公开的编号读不到，也不会因此拒绝整句提问。

同一段对话可以查询本人报名。已登录时，账号来自当前平台登录，模型不能改账号。返回的是报名状态、资格、付款声明、到账状态、成员确认数量和待确认邀请数量，不含证件、手机号和他人姓名。未登录时只说明需要登录。首页上的「我的下一步」卡片仍直接读报名，不经过模型。

这些读取与 MCP 使用同一套查询。MCP 默认关闭；打开后多两个只读工具：公开赛事分页检索、当前登录者自己的报名。产品对话不依赖 MCP 是否开启，由本机网关按内部令牌回调。

金额和日期仍由模型依据检索结果书写，程序没有在显示前逐句核对。来源卡片只包含这次工具实际返回、且仍然公开的赛事。
