# ADR-036 通用智能体委派确认与恢复

日期：2026-10-12。依据：用户要求修复审查问题并完善强 Agent 的通用能力。实现沿用 ADR-029 的注册、鉴权、事务执行和既有任务表；验收及部署范围见本轮验证记录。主站写渠道是否开放由逐能力验收决定。

## 授权与本人确认

确认卡在原运行内重新核验 active Agent/version、原能力快照、当前 grant、账号、岗位权限、组织及 Agent 开放渠道。子任务还须与父任务当前授权取交集，并保有对应委派 grant。当前支持的 grant 规则只有 `{"inheritActorScope":true}`；其他结构拒绝使用，不能把未实现的对象规则当成已授权。

本人登录会话签发确认，执行重新绑定原 Agent 身份；预览摘要变化拒绝办理。确认及成功回执保留 run_id，执行渠道是 agent。事务提交后的接续令牌在独立事务中提交，再交给模型线程，避免成功业务之后出现未提交令牌。模型不能确认真实资金、政府审批、正式结果或荣誉。

## 委派与可恢复结果

V039 追加 revision 3，保留所有旧版本和历史运行。目录有十三个 MCP 契约，其中八项允许受控运行：sports_playbook、sports_capabilities、sports_preview、sports_execute、sports_propose、sports_delegate、sports_children、sports_recovery。六项办理技能和五条业务流程继续复用。

父任务读取直接子任务的当前状态、可见答复及失败原因，不能读取其他根任务或其他人任务。子任务仍在运行时，父任务可以进入 waiting_children；子任务返回后按未消费的 version 接续父任务。待补充、待本人确认、失败和停止均是具体进度，不代表整个业务目标完成。本人从任务界面处理子确认卡。停止选中的递归子树，撤销令牌，不停止其父任务或其他兄弟任务。

成功工具结果、实际输入、确认回执及原请求键作为可见步骤保存。下一轮在当前能力与对象预览授权下恢复；权限缩小时屏蔽原派生回答。业务输入相同的非确认动作，在同一根任务中使用同一服务端请求键；人为需要再次办理同样内容时应新建任务或带新的对象版本。本人确认动作以任务和确认消息编号固定请求键。较大结果保留摘要和重新读取提示，不把截断结果当成完整事实。

父任务回复前核对已消费的子任务版本；最后一次读取后才返回的子结果触发接续，避免提前结束而未汇总。只读恢复直接更新当前事实，不查询不存在的写入回执。可见答复结构无效时，仅再进行一次没有工具的排版请求；仍失败则保留进度及实际回执，不重放业务。

## 预算与材料容量

每个任务锁定版本预算，子任务只能缩小父预算。默认层级 3、每轮工具调用 30、活动窗口 300 秒、每轮模型用量 30000、根任务累计 120000、根任务最多 4 个子任务。根任务锁串行分配预算，子任务及重新接续一起计入累计用量。轮次摘要防止旧线程释放新轮次预算；停止立即失去执行权，预算在结算或过期处理后释放。无法观察供应商用量的请求，保守消耗整轮预留量。

供应商返回的实际用量是结算依据，超过本轮预算后停止后续请求；单个响应可能已经超出估算额度，该超量仍计入累计记录。预算控制不等于供应商账单的精确硬上限。模型输入压缩重复目录，保留依赖、人工责任、输入字段和事实回执，减少重复发送人工入口 schema。

通用材料原上传规则保持每轮四份、合计 20MB、单份 15MB。最多六张模型图片，每张编码后 JPEG 不超过 512KiB；通用 Agent JSON 请求上限为 8MiB，Java 预检和网关拒绝均有明确材料超限原因。其他网关业务仍用原 2MiB 上限。压缩及传输通过不表示长材料全部识别、正确 OCR 或无限模型上下文。

## 兼容入口与剩余范围

Agent 没有动作上下文时，禁止通过旧兼容服务执行；已注册能力在执行器中使用明确的表范围和事务。赛事创建、修改、发布及项目创建、报名草稿、正式提交六个兼容入口跟随对应 UI 能力开关。

其他旧兼容声明和异步写入口仍须逐项缩小并回归；不全局打开 require-action-context 后把拒绝旧业务当成完成改造。真实图片供应商、实际赛事及资金、微信、短信、真机容量和整个一期验收继续按原清单处理。

## 办赛材料实测补充 2026年10月12日

用户随后授权编写通知和公开官方材料对照上传。本轮的整理、比较冲突、整合人工补充不代表授权保存业务草稿或委派办赛，后续补充也不扩大原授权。当前无可确认能力时模型工具菜单移除sports_propose，实际动作仍由既有服务端复核。未开放动作不反复试探，不提高预算绕过失败。原预算失败任务在修复后原编号接续。

专用资料页与现有运营助手采用同一价格/版本/声明契约：页面展示每单人数、名额和整单金额，用户选声明确认方式，明确保存时携带当前任务版本；文字修改后刷新版本。原文明确整单价格被模型误标按人时，只在同项目逐字引用、同金额且无相反/附加/冲突口径条件下校正候选标签，不换算、不判断到账，仍须普通主办方核对保存。具体已验范围见[通知验证](../04-verification/办赛通知真实使用验证-20261012.md)，不据合成输入开放主站写能力。
