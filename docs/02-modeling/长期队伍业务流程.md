# 长期队伍业务流程

日期：2026-10-05。状态：已开发，待业务验收。依据 ADR-008。报名见 [报名业务流程](报名业务流程.md)。

2026-10-06 新增目标见 [ADR-011](../03-architecture/ADR-011-一期业务收口与交付边界.md)，尚待实现/验收：顶栏身份/组织切换；仅当前成员访问当前队内资料，R09 待修；代表队伍报名可由当前队长按限制整单撤回、重提独立付款；注销前队长/唯一组织管理人移交，关闭结束本人有效队员关系且不改历史名单，新账号不自动入队/继承角色。

模型写入 `database/model/catalog.py`，并由 `scripts/generate-model.py` 同步。库结构用 V010 变更。已应用的 V001–V009 不改写。

## 1. 谁在用

| 角色 | 本期能做 |
| --- | --- |
| 已建档的平台账号 | 创建队伍并成为队长；申请加入；接受或拒绝发给自己的邀请；查看自己的有效成员身份 |
| 队长 | 修改队名、邀请、审批申请、移除普通成员、转让队长、解散、代表队伍报名 |
| 普通成员 | 查看本队有效名单，主动退队。不能代表队伍报名 |
| 超级管理员 | 不创建队伍，也不代替队长或队员操作 |

页面在平台参赛者入口。组织管理会话不能操作队伍。技术租户不存放队伍。

未建档或必填未齐的账号不能进入这些动作，因为成员行指向 `asp_person`。一期项目固定为已有羽毛球。

## 2. 队伍

创建成功时队伍为 `active`，同时写入创建人的一条 `active` + `captain` 成员，`join_source` 为 `create`。不另走申请或邀请。

解散只有当前队长可以做。队伍变为 `disbanded`。全部有效成员变为 `ended`，`end_reason` 为 `team_disbanded`。待处理的申请和邀请变为 `invalidated`。已提交和已通过的报名不改。解散后不能恢复。

队名可以由当前队长修改。改名写入 `asp_team_history`。已提交报名仍显示提交时写入的 `team_name_snapshot`。

`join_policy` 固定 `open`，`visibility` 固定 `members`。没有队伍广场。申请人填写队伍编号后只能看到这个编号对应的队名和状态。邀请由队长填写对方已注册手机号，对方档案已齐才建立邀请。

## 3. 成员

状态只有 `active` 和 `ended`。角色只有 `captain` 和 `member`。结束原因分开记：`member_left`、`captain_removed`、`team_disbanded`。

普通成员可以退出。队长不能直接退出，也不能把自己移除。转让必须一次完成：原队长变为 `active` + `member`，目标必须已经是当前队员，并变为 `active` + `captain`。不能直接转让给队外账号。

队长可以移除普通成员。退出、移除和解散都只结束成员行，不删除，也不改报名。

同一人可以同时在多队保持有效。同一人同一队同时只有一条有效成员。再次加入新插一行，旧的结束行保留。

当前页面把每一段成员关系都列出来，所以退队后再加入会看到两条。这是展示问题，存储不改。后续界面约定：我的队伍和队伍成员只显示 `active`。已结束的段放到单独的队伍审计，或加入/退队记录界面；具体版式在 UI 开发时再定。

2026-10-07 起，队伍详情接口只向当前有效成员返回现名单。已退出或被移除的人不能再读到现队员。没有成员关系的人仍看不到这支队伍。本人列表里的已结束段还在，历史展示界面仍未做。

## 4. 申请和邀请

同一账号和同一队伍同时最多一个待处理的申请或邀请。已是有效成员时不能再申请或再邀请。互斥用 `MutualLock`，键是 `team:{teamId}`。不用 `@Lock4j`，也不读 `asp_team_quota`。

申请：`pending` → 队长 `approved` 并建立 `active` + `member`；队长 `rejected` 不建成员；申请人 `cancelled`。队伍解散，或此人已经从另一条合法路径成为成员时，记 `invalidated`，不能记成从未发生的拒绝或撤销。

邀请：`pending` → 本人 `accepted` 并建立成员；本人 `declined`；队长 `revoked`；前提消失时 `invalidated`。接受时核对当前档案就是被邀请人。不使用邀请链接、过期时间和使用次数。

待处理的申请或邀请不是成员。

## 5. 和报名的边界

个人报名和临时双打不写 `team_id`，成员确认仍走报名邀请。

代表队伍时：

- 只有当前有效队长能创建和继续修改、提交、撤回。
- 创建时不自动把队长写入名单。名单从当前有效成员中选择。
- 选中本人当场确认。其他人仍是 `pending_confirmation`，必须本人确认。队伍成员身份不等于参赛同意。
- 同一队伍在同一单元再次创建时返回已有报名。数据库不另加「一队一单元一条」的唯一约束。创建人若已在该单元有一条个人报名，不能再插入代表队报名，反过来也一样。
- 提交前重新核对队伍仍是 `active`、操作者仍是当前队长、已确认成员仍是有效成员，以及其他报名提交条件。名单里有人已经离队时提交失败，系统不自动删除该成员。
- 提交成功写入当时队名，并冻结名单。之后改名、退队、转让、解散都不改这条已提交或已通过的报名。
- 草稿和已拒绝保留原成员。队伍解散后这条报名还在，但不能再提交。
- 转让后，原创建人不能再代表队伍办理。`submitter_account_id` 不改。

报名提交代表队时先取 `team:{teamId}`，再取名额锁，避免和成员变更交叉。

## 6. 本期不做

组织归属、配额、副队长、队伍广场、入队费、恢复、永久删除、比赛阵容、收费和录分。

TC11–TC20 仍待业务验收。TC13 的建队和加入上限没有已批准数值，本期不启用。

## 2026-10-08 邀请通知与深链实现

`POST /sports/c/teams/{teamId}/invitations` 可选 `requestSms`，缺省为 false。新邀请和站内信同事务，目标仅采用已注册本人身份。队长可复制待接受链接；`GET /sports/c/teams/invitations/{invitationId}` 仅指定受邀本人查询队名、状态及渠道摘要，不开放全队名单。接受/拒绝仍沿原接口与队伍锁，不以链接替代授权。

返回的 InvitationCard 增加可选 notice（inboxStatus/smsStatus/smsReason）；旧邀请无记录不假定送达。真实短信未接通；勾选时留失败原因，邀请继续有效，不复用注册验证码用途。前端独立确认页回我的队伍，退出后仍按原成员权限限制。详见 ADR-014。

## 2026-10-12 可转发分享授权接续

用户要求未注册者也能通过队长链接加入。按 ADR-042 增加独立 share 邀请：七天有效、当前队长生成/复制/撤销/更换，匿名仅预览队名与有效性；登录、注册及本人资料补齐保留上下文，明确点击确认后直接加入。分享不同于指定受邀本人的 direct 邀请，前面的「不使用邀请链接、过期时间」描述只保留为原版本规则，不能用于新增 share 路径。

接受来源与本人唯一，当前成员重试不多插；已用旧链接的人离队后不能重放复活。队长转让、账号停止、解散、撤销和到期使旧授权不可用，成员与正式报名继续分离。邀请接受和团队变更增加 PG 队伍行锁。队长获新成员站内信，被移除队员获本人变更站内信，不宣称短信已送达。模型、V041、接口和验证边界见[长期队伍分享邀请接口](长期队伍分享邀请接口.md)；实现不等于真实新用户或微信小程序验收。
