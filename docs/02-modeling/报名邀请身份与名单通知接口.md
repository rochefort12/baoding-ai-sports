# 报名邀请身份与名单通知接口

日期：2026-10-12。依据 ADR-011、ADR-029、ADR-040 与用户本轮第 2、3 项要求。本文描述源码契约；构建、实际普通角色和用户试用以本轮独立验证报告为准，不把设计当成通过。

## 身份和隐私

`EntryCard.members` 新增 `invitationName` 和 `mobileTail`。只有本条报名当前有权办理名单的账号获得这些邀请对象标签；姓名从此报名关联账号的当前必要档案或昵称读取，手机号只在服务端投影末四位。没有本人确认的成员仍为 `pending_confirmation`，其 `legalName` 和 `personSnapshot` 不被邀请标签填充。已确认名字沿用本人参赛快照。正式名单、参赛字段和声明仍由本人确认及正式提交冻结。

动作私有查询以 `registration.tenant_id + registration.id` 限定，关联范围仅本单成员、提交人和办理人；不开放账号搜索，不返回证件、生日、健康、完整电话或其他赛事答案。非办理人普通成员不会因此得到他人手机尾号。本人邀请详情 `InviteView` 新增 `inviteeName`、`inviteeMobileTail`、`initiatorName`，现有登录账号与邀请收件账号逐次核验先于投影，链接不能代表身份。

已确认成员的办理人名单卡不再提供旧邀请令牌复制入口；本人收到的私有历史入口保持可重新查看，并按当前状态显示只读。邀请方复制操作明确收件人姓名及手机尾号，受邀页面先核对本人和报名发起人。

## 邀请及旧通知恢复

按手机邀请、队伍一次准备名单及逐次加入队员继续使用 `InvitationNoticeApi.created`，站内信与成员写入同事务。通知含发起人名字、赛事和比赛项目及本人查看指引，不复制完整个人资料。队伍逐次加入成员返回卡片改为通知写入后投影，避免首次返回“未生成”的错误回显。

新增 `POST /sports/c/registrations/{registrationId}/members/{memberId}/remind`，无请求体。必须是当前办理人、可编辑报名且指定成员为本单待确认成员。重新打开邀请不偷偷产生写入；历史缺站内信由明确“发送站内邀请”按钮恢复。沿现有 `registration-invite:memberId:version` 加收件账号唯一约束去重，同一版补发或并发重试不重复广播，不重置本人确认。

## 移出通知

`DELETE /sports/c/registrations/{registrationId}/members/{memberId}` 保留当前办理权限、可编辑状态、名单锁与版本删除检查。成功移出其他账号时，保存 `registration-roster-removed` 持久站内信；删除未提交草稿也通知其其他成员。通知与删除同事务，消息保存失败回滚删除，不出现名单删除成功但消息丢失。本人移出自身不另发自通知。

通知业务键为 `registration-roster-removed:memberId:version`，收件人为被删除成员的账号。内容说明具体赛事和项目的本次邀请已取消，不影响其其他报名。原令牌随成员删除失效。跳转固定 `/portal/registration`，避免将已失去成员身份的人导回无权查看的报名详情。重复删除不存在成员仍返回原有拒绝，但不额外发通知。

## 共用通知种类

邀请通知服务和参赛端消息列表按种类对应白名单路径，不能跨用其他邀请的私人目标或接受任意重定向：

| 类型 | 收件范围 | 站内目标 |
| --- | --- | --- |
| `registration-invite` | 指定参赛成员本人 | `/portal/registration/invite/{token}` |
| `registration-roster-removed` | 被移出本次名单的人 | `/portal/registration` |
| `team-invite` | 原指定队伍受邀人 | `/portal/teams/invitations/{id}` |
| `team-joined` | 队伍加入动作确定的当前队长 | `/portal/teams/{id}` |
| `team-member-removed` | 队伍动作确定的被移出成员 | `/portal/teams` |

长期队伍分享加入及队员移出由队伍入口动作自行核验、调用纯通知契约；此报名修复不把开放分享链接当成特定受邀人的私人邀请。消息未读/已读仍按现有持久通知办理；短信状态独立，真实短信未接通继续明确记录，不解释为真实送达。

## 验证入口

服务测试 `RegistrationInvitationExperienceTest` 验证待确认身份标签与快照分离、四位尾号防御、错误对象拒绝、删除通知同事务及失败回滚。`InvitationNoticeTest` 补种类、目标隔离与名单变化通知。普通角色脚本为 `scripts/Test-RegistrationInviteExperience.mjs`，在最终包激活后选择已有独立回归上下文，创建新的模拟赛事/项目/队伍并走桌面、手机消息点击、本人确认及邀请方移出的实际流程。令牌、凭据和续验状态留未跟踪 `.local`，公开回执不输出私人邀请路由；不直接改库，不使用旧成功对象，也不代表真实客户赛事验收。
