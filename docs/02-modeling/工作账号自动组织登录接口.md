# 工作账号自动组织登录接口

业务决定见 [ADR-035](../03-architecture/ADR-035-工作账号自动识别组织与登录布局.md)。此接口用于若依工作账号；参赛者和主办方的平台身份及进入组织工作区沿原身份链办理。

## 工作账号登录

`POST /auth/login` 新增 `grantType: work-password`。账号、密码和客户端编号必传，验证码开启时沿原规则传 `code`、`uuid`。工作登录表单不传 `tenantId`，即使调用者额外提交，服务端也不将其作为身份选择依据。

服务端先执行原账号失败锁，再查找同名工作账号并校验密码。只有一个有效密码匹配时，进一步核验该组织、账号状态和身份；按该账号真实组织签发原结构会话。同名不同密码可定位不同组织；同名同密码匹配多个组织时拒绝登录，不返回组织清单，不默认选择第一条。不存在、错误密码和受限制身份均不能得到会话。

客户端须有原 `password` 精确授权，未知客户端、部分匹配及复合授权字符串不能放行。验证码保持一次使用，IP限频和原认证审计保留。参赛者兼容租户、平台技术租户及映射组织技术主体不可借此绕过平台身份。

旧 `password` 授权类型和显式租户登录保持兼容；工作页面不再请求 `/auth/tenant/list`，原兼容接口仍存在。没有新增匿名账号归属查询接口。

## 微信入口状态

`GET /auth/work-methods` 为限频公开查询，目前返回 `data.wechat.available: false`。这表示工作微信登录尚未开放。前端入口直接可见，点击反馈暂不可用并保留输入；没有模拟二维码、登录 Token 或授权跳转。

真实工作微信仍需服务器一次性state、安全授权回调、已绑定工作主体的唯一解析和普通账号实际扫码验证。此状态查询不读取或暴露第三方密钥，静态图标展示不作为登录接通证据。

## 默认工作台

登录成功沿现有 `getInfo`、权限路由和安全回跳进入工作台：平台管理员看到平台业务，普通政府岗位看到管理范围内的主办方业务，其他工作账号看到其真实组织及岗位可用菜单。组织归属由服务端会话确定，页面样式和客户端地址参数没有授权能力。

## 验证边界

实际本机API验证、真实表单登录、响应布局及安装证据见 [本轮报告](../04-verification/工作账号自动组织与登录布局验证-20261011.md)。停用或过期组织、验证码开启、连续失败锁及受限制身份等策略的单元测试不能写成已执行的真实HTTP场景；真实微信不计通过。
