# 赛事资料建赛接口

本接口是既有普通主办方材料建赛入口，属于 `asp_event` 手写业务动作。它与通用 Agent 能力渠道分别受控；材料上传可用不表示所有 Agent 具备建赛或发布权限。

## 任务与源文件

`POST /sports/b/ai/tasks` 接收 multipart `files` 与资料处理授权。历史兼容参数名 `bailianConsent` 保留，页面说明使用当前实际模型用途；旧授权不改写含义。`POST /sports/b/ai/tasks/text` 接收粘贴或对话源。上传/粘贴先提交任务和源，再请求模型，防止视觉回调读取未提交记录。

`GET /sports/b/ai/tasks/{taskId}` 返回 `TaskCard`，包含状态、当前 `version`、提取覆盖、候选 JSON、缺项和错误。读取重新核验当前账号、组织和任务。原文及文件不因知道 ID 而公开。内部文件/页面读取校验任务级受控签名；loopback 回调来自当前后端实例，不允许网页指定任意地址。

DOCX 和文本 PDF 使用段落/页块；扫描 PDF 和图片使用实际视觉识别结果。候选字段保留引用。无法识别、冲突、覆盖不足和不支持旧格式分别提示，不用模型推测补全材料。识别失败可恢复原任务，不另建任务伪装成功；存在人工补充后不以重新识别静默覆盖其内容。

## 候选与确认

事件候选包括名称、地点、报名/比赛时间、联系人与联系方式、退改原文、规程和独立 `declarationText`。项目候选包括名称、`entryType`、最少/最多人数、报名单上限、`feeAmount`、`feeBasis` 和来源状态。金额保持十进制精度；`feeBasis=order` 才能直接初始化整单价格。明确零元是免费，空金额保持待补充；按人收费、附加费用、矛盾报价或不明单位不能自动当整单价格。

2026-10-12连续建赛决定优先：来源明确且人数固定的简单按人收费可计算整单候选价，保留原文单价、人数和整数分算式；人数可变、首项／加项、优惠、矛盾或未明仍待核对。资料未说明报名审核方式时 `registrationReview=none`，来源标为 `default`，不再追问；明确人工审核保留 `manual`，真实冲突不覆盖。用户可在表单修改默认值。无需人工审核不跳过收费实际足额收款要求。

尚未创建赛事时，“保存表单到草稿”更新候选；表单及聊天“创建赛事”使用当前版本明确确认创建。创建后继续通过同一聊天累积修改，“保存修改”或表单保存更新同一赛事、原项目容量及价格，项目 ID 保持。发布仍由普通主办方核对并同意。年龄、价格等回答累积写入候选，不清空已答内容。详见[ADR-044](../03-architecture/ADR-044-聊天草稿创建发布与连续补充.md)和[ADR-045](../03-architecture/ADR-045-悬浮办赛表单与收费草稿删除.md)。

2026-10-12悬浮表单接续见[ADR-045](../03-architecture/ADR-045-悬浮办赛表单与收费草稿删除.md)：候选形成后直接在聊天里展示已预填表单，默认列出待补和冲突字段，允许展开核对全部内容及各项目。运动项目说明为 `event.projectName`，不能用收费备注代替。结构化缺项在可填写字段旁提示，不再把同一“下一步”追加到每条回复或在输入区重复列出。

`PUT /sports/b/ai/tasks/{taskId}/candidate` 接收 `expectedVersion`、`event` 字符串字段、`units` 字符串字段数组及 `cover`。保存当前可见值后返回新的 `TaskCard` 和 `version`。`PENDING_CONFIRMATION` 更新候选；`CREATED` 重新核验原赛事的归属、未发布及无发布/报名历史条件，同事务更新原赛事与原项目。其他页面已修改时拒绝静默覆盖；不新增或删除项目。“创建赛事”先保存表单，再按保存返回的版本通过既有 `talk` 明确确认；不从旧卡片版本或发送输入框中取创建依据。版本已变且本地仍有未保存输入时保留本地内容并提示读取最新候选，不静默覆盖。

已创建任务读取实际赛事后返回 `published`、`eventStatus`、`draftEditable` 和赛事版本。`talk` 普通回答继续更新候选，`proposal.createdDirty` 区分尚未同步的修改；明确“保存修改”同步原赛事。“发布赛事”返回发布意图及原 eventId，前端在对话内读取实际公开资料和费用核对卡。“确认发布”仅在实际核对卡已显示后代表明确同意并调用原发布服务；资料变化重新核对，缺项失败保留。已发布任务可恢复查阅，专用草稿编辑关闭。

批量表单“所有项目整单价／元”设置各行 `feeAmount` 与 `feeBasis=order`，“每个项目报名上限／单”设置各行 `limitCount`；需点击“应用到所有项目”，不是填入批量栏就自动覆盖。当前整单补价上下文中的明确“全部项目100元”同样更新各项目候选，不只记在收费说明里。每项每单100元与按人100元分别理解；真实按人、附加、优惠、矛盾或未明确单位仍按上文规则核对。

`POST /sports/b/ai/tasks/{taskId}/talk` 使用 `message`、当前 `expectedVersion` 和显式 `declarationAckRequired`。页面“确认保存草稿”通过同一普通主办方入口提交当前候选；开关由责任人选择，不由模型决定。`POST /sports/b/ai/tasks/{taskId}/confirm` 支持完整 `ConfirmDraft` 与幂等请求键：版本、原文声明、开关、项目和价格均与当前候选核对。静默改价或过期确认被拒绝，并保留原候选与任务。

原声明必须有可核对来源；没有声明时不得凭模型新增声明或开启逐人确认。已有声明允许主办方选择仅供阅读或要求每位参赛成员确认。费用提议须有当前组织经办人的收费授权；身份、组织和授权从服务端取得，不能由模型或确认参数授予。

## 原子保存与后续责任

成功确认在一个事务中创建未发布赛事、支持的比赛类型与参赛项目、确认的初始收费政策，并保存任务结果。表工程通过 `CompetitionTypeApi` 与 `FeeApi` 纯契约办理，不引用其他表工程实体或 Mapper。未开放比赛形式/人数被拒绝。不得在项目缺比赛类型时留下看似成功但不能组队报名的草稿。

回执中的 `created`、`eventId` 和任务 `resultObjectId` 以真实写入为准。任务已创建时再次确认返回同一赛事；不能重复建赛。缺项、模型错误或后端业务错误不能记为工具成功，即使运输层返回 HTTP 200。

悬浮表单创建成功明确展示成功状态和赛事编号，再提供核对发布及管理入口。保存完成但创建被拒时显示当前缺项或拒绝说明；表单和已保存候选继续保留。创建请求超时先读取原任务，若已形成赛事则恢复该对象；读取仍失败时显示结果待核实，不自动重放创建。这里的创建成功仅表示未发布赛事及确认项目／价格已写入，不表示公开、付款或现实办赛完成。

保存草稿不发布赛事、不确认到账或退款，也不办理政府审批、正式赛果和荣誉。后续由普通主办方配置实际收款说明，在首次发布卡核对公开联系人与退改内容并明确同意公开；发布继续检查组织资格、报名时窗、项目/价格及所需规则。材料完整且拟议价格已确认时不再要求手抄项目价格。

## 同一赛事持续编辑与显式重新读取

`CREATED` 表示任务已有 `resultObjectId`，与赛事实际 `publicationStatus` 分别判断。`GET /sports/b/ai/tasks/{taskId}` 投影返回 `published`、`eventStatus`、`draftEditable` 和 `eventVersion`；普通读取不自动采用外部修改为候选。新建成功后由服务端保存 `proposal.createdEventVersion` 与 `createdCatalogSnapshot` 作为持续编辑基线，项目绑定原项目编号。聊天补充更新候选，候选 `createdDirty=true` 表示尚未同步；表单保存或明确“保存修改”才在同一事务中更新原 eventId 及原项目。赛事版本、项目／容量／有效费用目录与基线不一致时以 409 拒绝，不另建赛事，也不静默覆盖其他页面的变更。

表单“读取赛事当前内容”使用当前任务版本调用 `POST /sports/b/ai/tasks/{taskId}/talk`，`message="重新读取赛事草稿"`，显式采用原赛事当前业务内容。服务端取得原赛事行锁并复验归属、未发布且无使用历史的草稿条件及任务版本，再读取赛事字段、原项目目录与当前整单价格，只更新任务候选和基线，不写赛事。字段来源标为“实际赛事当前已保存内容”；原文与上一候选仍保留，后者存为一层有界 `previousCreatedCandidate`，不递归累积历史。原资料封面选择清除，赛事实际已有图片保留。

前端读取前另保留当前表单未保存填写，提供展开核对与回填。回填只回到本地表单，仍需保存；只有前后项目编号目录一致时才整体回填项目，否则保留旧项目供逐项核对。读取失败保留当前输入；返回结果必须仍关联同一 eventId 且 `draftEditable=true`。旧版 `CREATED` 缺少赛事版本及项目费用基线时，普通修改和保存以 409 拒绝并提示先读取当前内容，不能拿旧候选直接覆盖实际赛事。显式读取后继续使用同一 taskId、eventId 与实际项目编号，项目增删仍到原项目管理入口办理后再读取。

## 聊天发布核对与版本比较

聊天发布卡同时读取原赛事、原任务及 `GET /sports/b/events/{eventId}/preview-fees`，核验任务结果编号并记录实际公开内容、项目费用、任务版本、`eventVersion` 和 `previewHash`。明确确认前再次读取；本地输入未保存时先保存，候选尚未同步、任务版本或实际核对内容变化时更新卡片、清除公开同意并要求重新核对。尚未读到版本或摘要时不能提交聊天发布确认，登录上下文变化也需重新核对。

`POST /sports/b/events/{eventId}/publish` 的聊天确认请求包含 `requestKey`、`contactConfirmed=true`、已核对的 `contactName`、`contactMethod`、`expectedVersion` 及 `expectedPreviewHash`。正式服务取得赛事行锁后比较实际赛事版本及由当前项目、费用和公开信息重新生成的预览摘要（CAS）；任一不一致以 409 拒绝，仍执行原资格、归属、时间和公开字段检查。版本／摘要参数对既有兼容调用仍为可选，不能据此声称全部发布客户端已强制使用此比较。重复请求键返回原发布结果；错误或超时仅在重新读取同一赛事真实为 `published` 后恢复成功，否则保留原失败与请求键，不把候选保存或 HTTP 运输成功当发布成功。

收费发布核对还读取实际赛事收款设置。没有渠道时，可在本卡填写线下付款说明，保存走既有 `PUT /sports/b/fees/events/{eventId}/payment-config`，携带当前 `revision` 并完整保留其他渠道。名称沿用正式模型“线下付款”，保存只配置公开办理说明，不确认任何收款。成功后重新读取实际内容并清除同意，仍需明确发布确认。免费赛事不读取单独收款设置。预览摘要包含实际收款配置版本，即使修改前后均有可用渠道，配置变动也拒绝旧摘要。权限和正式报名后锁定规则继续由既有接口核验。

## 赛事草稿删除与未用费用配置

已创建但未发布赛事使用 `POST /sports/b/events/{eventId}/delete-draft`，与未形成赛事的 `POST /sports/b/ai/tasks/{taskId}/abandon` 分开。仅设置收费金额、免费价格版本或赛事收款方式，不算已有付款；无使用历史的配置可以随赛事草稿清理。正式报名锁、任何报名、名额占用、采集值、付款义务或发布办理历史仍拒绝。清理全部加入事件删除的同一事务，经 `FeeApi.discardUnusedDraftPricing` 复验并清除未用价格与收款配置，再清理空项目等依赖；失败全部回滚，不删除任何资金事实。完整归属、状态、关联任务和原件边界见[赛事公开业务流程](赛事公开业务流程.md)。
