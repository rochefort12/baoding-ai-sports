# 赛事材料与封面接口

依据 [ADR-029](../03-architecture/ADR-029-表模块与智能体闭环.md) 与 [ADR-031](../03-architecture/ADR-031-独立视觉落地与办赛材料工作室.md)。本接口管理本组织赛事的工作草稿及展示封面；正式发布和其他业务事实仍由原业务动作办理。

## 读取与版本

`GET /sports/b/events/{eventId}/materials` 要求登录，并由赛事业务层核验当前组织和租户。返回上游 `R` 包装；`data` 包含：

| 字段 | 含义 |
| --- | --- |
| eventId | HTTP Long 字符串 |
| eventVersion | 赛事当前总版本，数字；用于保存封面 |
| facts | 当前赛事名称、运动、时间、地点、报名截止、组织、联系人、费用、规则、声明和发布/取消状态；服务端取得 |
| factDigest | 当前事实的 SHA-256；文稿保存与生成必须绑定该摘要 |
| aiAvailable | 服务端文本模型凭据和内部调用配置是否存在；不表示一次真实模型调用已成功 |
| materials | 以 plan、script、announcement、promotion 为键的私有草稿对象，未保存类型可以不存在 |

每份草稿包含 `kind`、`title`、`content`、`version`、`source`、`factDigest`、`updatedAt`、`updatedBy`、`history`。`source` 是 `manual` 或 `ai`；`version` 是该类型独立版本，未保存时为 0；`history` 最多保留 10 个旧版本，不递归嵌入历史。时间带时区偏移；用户 ID 使用字符串。个人参赛证件、付款材料及模型凭据不进入这些事实。

## 写入动作

三项写入均使用 `POST /sports/platform/actions/{actionCode}/execute`，只允许已开放 UI 渠道内的主办方。身份、租户和组织由服务端取得，不接受浏览器自报。正文结构：

```json
{
  "input": {
    "eventId": "赛事编号",
    "kind": "plan",
    "expectedVersion": 0,
    "factDigest": "读取接口返回的64位摘要",
    "title": "赛事执行策划",
    "content": "待主办方核对的工作草稿"
  },
  "requestKey": "每次新办理的唯一请求编号"
}
```

| 动作 | 输入与行为 |
| --- | --- |
| event.material.save | eventId、kind、expectedVersion、factDigest、title、content；人工保存为 manual 来源 |
| event.material.generate | eventId、kind、expectedVersion、factDigest、consent；note 可选，最多 1000 字。consent 必须为字符串 confirmed；真实模型成功才保存 ai 来源 |
| event.cover.save | eventId、expectedVersion；fileId 可选，必须为 HTTP Long 字符串；省略 fileId 恢复默认展示 |

`kind` 仅允许 `plan`（策划）、`script`（主持及现场脚本）、`announcement`（公告）、`promotion`（宣传）。标题必填、最多 200 字；正文必填、最多 10000 字，与统一执行器及模型输出限制一致。文稿的 `expectedVersion` 取当前同类型草稿版本，封面的 `expectedVersion` 取 `eventVersion`，两者不可混用。

成功返回 `data.receiptId`、`actionCode`、`status=succeeded`、`replayed` 和 `result`。文稿 `result` 为保存后的草稿；封面 `result` 包含 eventId、status=saved、bannerFileId。断线重试必须使用原 input 与 requestKey：成功请求重放原回执，不再次生成或加版本；相同编号携带不同内容拒绝。

版本或事实变化返回业务冲突，页面保留编辑内容，需重新读取核对后办理；错误不能显示成功。生成前核对版本和事实，成功写入前在赛事行锁下再次核对；失败不覆盖原稿。成功回执与业务写入共同提交，失败记录独立保留。材料存储为 `asp_event.operations_materials` JSONB 对象，不开放通用 CRUD。

## 封面文件与 AI 候选

`POST /sports/b/media?purpose=event-banner` 复用现有组织受控媒体上传，multipart 字段为 `file`，返回 fileId。编辑器接受 JPEG、PNG、WebP，最大 5MB，建议 1600 × 900、主体居中。`GET /sports/b/media/{fileId}` 为受控图片读取；公开封面通过 `GET /sports/public/events/{eventId}/media/banner`，须满足既有公开赛事及组织准入约束。声明、付款等其他用途的文件不能作为公开封面。

上传或点击“使用平台运动视觉”后先形成待保存选择，保存封面动作成功才关联赛事；平台静态资源必须真实上传后关联，不把预览当保存。已发布赛事可以调整展示封面，但不改规则、名单或收费依据；取消赛事拒绝更新。

封面 AI 复用既有 `POST /sports/b/events/{eventId}/promotion/visual`。调用成功只产生候选，主办方明确选择后再保存。图片供应商配置与文本模型独立；未配置时保留上传、默认视觉及已有候选选图入口，不能把静态素材当作实时 AI 成功。

## 页面与验证

主办方赛事列表 `.managed-event-card` 中“更换封面”打开“赛事封面”弹窗；保存使用 `data-testid=cover-save`。材料入口是 `/org-desk/workspace/{eventId}?task=materials`；稳定选择器为 material-studio、material-tab-{kind}、material-title、material-content、material-template、material-generate、material-consent、material-save。基础模板明确不调用 AI；文稿可编辑、复制、保存、查看有限历史及下载 Markdown，下载标记为待核对草稿，保存不会自动发送公告。

2026-10-11 隔离 8082 的真实 HTTP 检查 28 项通过，包含四类实际 DeepSeek 调用及落库、幂等重放、私有读写拒绝、版本/摘要冲突、真实图片上传和公开读取、错误用途拒绝、图片服务不可用保护，以及 10000 字实际保存、10001 字明确拒绝且不覆盖原稿、原文恢复为新人工版本。恢复复核通过；后续 UI 更换封面导致旧检查点断言失败的记录保留，脚本修正后按当前版本真实重办封面检查。证据在 `.local/product-release-20261011/materials-http-*.json`；对应恢复脚本为 `scripts/Test-ProductMaterials.mjs`。另有 7 项 Java 与 5 项 Gateway 模拟单测，Gateway 全套 40 项通过。隔离环境没有第二组织赛事，实际跨组织 HTTP、真实图片模型、完整普通角色页面体验及最终业务闭环没有借此宣称通过；三项能力的 Agent 渠道保持关闭。此验证不代表主环境已开放。
