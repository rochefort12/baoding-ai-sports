## 1. 谁在用

| 角色 | 本期能做 |
| --- | --- |
| 参赛者 | 提交报名后查看应付金额、收款方式和承办方说明。不能自己确认到账 |
| 承办方付款人员 | 为竞赛单元发布收费版本，人工确认到账，冲正误确认，处理已付款报名失效后的无需退款或已退款 |
| 承办方审核人员 | 审核整单，收费通过要求本次有效实收净额足额；付款可先于审核，不自动取得资金操作权 |
| 超级管理员 | 不代替承办方确认到账 |

付款人员要有 `payment` 授权。审核继续用 `organize`。新开通的组织两样都有。收费设置放在报名审核的竞赛项目上，不再单独使用「收费记账」菜单。

建立项目时一起保存是否收费、报名费、付款方式和付款说明。已有项目用「收费设置」修改。保存时系统仍会退役上一档并记下新的一档。已经提交的报名继续使用提交时的金额和付款方式。

目标：正式提交后可立即打开付款指引，显示真实适用收款码/线下说明和冻结费用依据。点击已付款是声明，不产生到账；付款凭证可独立自愿上传，强烈推荐但平台不强制，也不代替到账核对。承办方填写实际付款人、金额、时间并核实到账；满足实收条件才能审核通过。无需审核收费赛事到账后重验规则/窗口自动通过，免费不造付款。不能用合成回执或模拟到账试运行真实收费。

正常付款开赛、拒绝、撤回或取消关闭，报名截止不关闭仍有效申请。迟到/误付款继续登记人工收尾，不恢复资格。人工资金操作集中报名详情收费区，简明汇总、记录和表单，复用 payment 权限，不新增完整财务菜单或审批流。

后续能力见 [收费记账后续增强](收费记账后续增强.md)。

## 2. 收费版本

每个竞赛单元单独编号。草稿可以改。激活后金额和收款方式不能改。要改价就新建下一版并激活，原来的 `active` 变为 `retired`。历史义务仍指向提交时的那一版。

| 方式 | 金额 | 参赛者看到 |
| --- | --- | --- |
| `free` | 0 | 无需付款 |
| `event` | 大于 0 | 使用赛事统一配置的微信、支付宝、银行、自定义收款码或线下指引；正式提交时冻结到当次义务 |
| `offline` | 大于 0 | 线下说明 |
| `organizer_qr` | 大于 0 | 真实收款图、主体和说明；启用前授权人员核对可用/主体一致，无有效图不开放收费报名 |

没有 `active` 版本时不能提交。

2026-10-10 接续：项目只切换免费/收费及保存金额，渠道在赛事设置统一维护，见[ADR-028](../03-architecture/ADR-028-赛事统一收款与打开即用宣传文案.md)与[接口](赛事收款指引接口.md)。`offline/organizer_qr`保留旧版本与历史义务；配置赛事渠道后，已有收费项目的新提交也使用统一指引。首笔正式提交后金额/渠道锁定，PG赛事行锁串行；参赛者读取当次义务快照，不读取active收费版本的二维码。新event模式缺渠道不能发布或提交，免费不要求配置渠道。

公开报价从有效版本同源读取，按整单计费；收费开放前说明撤回/拒绝/取消是否退款、计算方式、办理时限及联系入口，冻结报名适用依据。已有正式历史不能改价/收款主体/退改承诺绕过重大变更限制；旧“另起版本即可随时改价”的路径只适用于无正式历史的配置阶段。

## 3. 义务

提交成功才产生义务，和审核通过无关。

| 情况 | 义务 | 付款行 |
| --- | --- | --- |
| 金额 0 | `not_required` | 不插入 |
| 金额大于 0 | `open` | 尚未到账时不插入 |
| 确认到账 | `settled` | `confirmed` |
| 未付款时撤回或拒绝 | `void` | 不插入 |
| 已付款后撤回或拒绝 | 保持 `settled` | 保持 `confirmed`，另记待处理的资金后续 |
| 再次提交 | 新的一行 | 旧付款不抵扣新义务 |

同一报名同时最多一条 `not_required` 或 `open`。

## 4. 确认、异常和冲正

人工确认实际付款人，可为未注册第三人；一期不启用回调自动确认。支持必要多笔实收/补款，净有效实收（扣实际退款、排除冲正）足额才满足条件；少付待补，多付人工处理，不跨报名抵扣。各笔独立留痕，重复请求和金额/并发由服务端保护，现有异常表/接口需适配，不以“金额不符”拒绝保存真实资金。

义务已经 `void` 之后才到达的真实付款仍然记账，义务保持 `void`，并记待处理的资金后续。

误确认通过冲正保留原记录及审核事实；实际资金重新汇总，元数据错误可授权更正留痕，退款不当作冲正。无人报到的已通过欠款单暂停新报到，补足解除付款限制；已有报到/场次人工协调不清历史/改判/撤证。已退款不能直接冲正成退款超实收，先核对真实资金受控修复。免费/其他足额款不误拦，取消等失效规则保持。

## 5. 退款记录

退款全人工：核对原收款及冻结政策→确定退款安排→平台外实际退钱→登记真实金额、时间、接收人和原款关联。分待处理、办理中、已退款、无需退款；分次未完成仍办理中，无需退有原因/政策依据。累计有效实际退款不超过有效实收。原则上退原实际付款人，变更接收人核验其授权并记依据，不随队长更换转给新队长，不新增在线授权审批。免费/未付不造退款，仅声明须先核对实际款。

## 6. 本期不做

平台收款、微信/支付宝支付集成、成员分担计价、自动退款/对账、旧付款结转、按人数或阶梯计价、发票和服务费结算、复杂审批/双人复核。必要补款和分次退款登记一期完成，控制页面复杂度。

## 2026-10-08：资金事实补齐

本轮取代上一实施段的整笔金额限制：确认实际金额允许分次，多笔有效实收减实际退款计算净额；拒绝、撤回和取消后可登记真实迟到款但不恢复资格。退款填写实际金额/时间/接收人/必要授权依据，累计不超原款，部分保持待办；撤销指定错误到账不等于退款，已实际退款原款禁止直接撤销。详见 ADR-013 和交互执行记录。受控更正、真实普通角色与并发验收仍未完成。
