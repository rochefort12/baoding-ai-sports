# 智能体技能与业务地图接口

复用 `asp_agent`、`asp_agent_version`、`asp_agent_grant`、`asp_agent_run`、`asp_agent_step`、`asp_agent_message` 和原确认/回执表，不建立第二套身份、资金或报名系统。V036 在既有智能体版本追加 `tool_catalog`、`skill_catalog`、`business_map`、`playbook_hash`；目录源是 `database/seeds/agent-playbook-v2.json`。目录和可信提示词按 revision 锁定，旧版本及旧运行保持可追溯；上传资料和模型输出不能改这些目录。

## 读取及调用方式

平台管理 `GET /sports/platform/management` 的 agents 投影增加三个目录和 playbook_hash，只向既有平台管理权限展示。没有模型凭据、运行令牌或材料正文。新运行选择最高 active revision，子运行继承父身份及权限范围。

受控 MCP `sports_playbook` 只在服务端签发的本机运行身份下可用，返回 revision、sourceHash、toolCatalog、skills、businessMap、actions 和已核验格式的页面 context。动作来自当前实际注册表，受角色、实时岗位权限、定义摘要和开放渠道过滤；地图过滤角色并标记每步 uiEnabled/agentEnabled。页面入口不会授予助手操作权限；未开放动作不能执行。每次 MCP 调用重核运行、账户、组织、岗位权限及预算。

V039 的 revision 3 目录源为 `database/seeds/agent-playbook-v3.json`，旧 revision 2 保留。目录保存十三个 MCP 契约。受控运行可使用 sports_playbook、sports_capabilities、sports_preview、sports_execute、sports_propose、sports_delegate、sports_children、sports_recovery 八项；原有五个登录会话工具保持 agentAllowed=false，拒绝以 Agent 令牌调用。工具仍取锁定目录与真实 MCP 清单的交集，没有任意 SQL、Shell 或网络工具。

`sports_children(waitSeconds)` 只读当前运行的直接子任务，waitSeconds 是 0—10 的整数，返回 children[{runId,status,goal,version,reply?,errorCode?}]；撤权结果不附私有答复。`sports_recovery()` 返回 records，包含仍可访问的历史输入、状态、原请求键及真实 receipt/result；先通过当前能力和对象预览检查，不能用旧回执绕过撤权。输入、长结果都有保存上限。非确认执行的 requestKey 由服务端按根任务、动作和规范化输入生成，模型改键不能重复成功写入。

状态新增 waiting_children，界面继续轮询并提供停止。确认接受时重新核验原运行授权、当前对象预览及 Agent 渠道；本人会话只负责签发确认，执行保持 Agent 身份与 run_id。重复或过期确认拒绝。停止作用于所选子树。每轮预留、累计用量、层级及子任务数量使用锁定预算，见 [ADR-036](../03-architecture/ADR-036-通用智能体委派确认与恢复.md)。

## 页面块

原 `/sports/agents/runs` 的启动、补充、资料上传、停止和确认接口不变。detail 增加 playbookVersion 与 sourceHash，messages.blocks 保留已有 JSON 数组形式。除材料、本人确认卡和真实回执，新增：

| kind | 字段及用途 |
| --- | --- |
| guidance | title、summary、workflowCode、version、sourceHash；简要说明本轮目标和下一步，版本与摘要由服务器附加 |
| question | key、label、hint、options；一次先补最关键的信息，最多四个短选项 |
| checklist | title、items[{label,state}]；模型状态只允许 todo/pending，不能凭模型标记业务已完成 |
| navigation | label、code、path；code须存在于当前角色实际开放的页面能力，path由持久化地图及当前对象提示生成，不接受模型地址 |

每次回复最多八个块，问题/标题/清单有长度和数量限制。模型不能生成正式确认、资金成功或回执块；这些仍从原真实业务办理返回。发布、正式报名等确认卡绑定实际对象、版本、名单、金额，内容变化须重核。原 requestKey 幂等及事务回执保持。

revision 2 运行先读取可信 sports_playbook 和 sports_capabilities，将当前服务端实际可执行能力及输入 schema 交给模型。查询本人进度、积分或已有对象时，若已有授权及必要参数，先通过已登记只读能力取得真实事实，再总结和补问；问候、流程说明和明确只要设计方案的请求不强制查询私人资料。规则不写死某五个动作，也不能将 UI 入口误当 Agent 授权。

工具选择阶段使用原生 tool calling，不附加 JSON 输出模式。模型已结束工具阶段但答复结构不合规时，再以 `response_format={type:'json_object'}` 做仅排版的请求；该请求没有 tools，不能重放任何成功动作。提示包含 reply/blocks/kind 示例，最终仍由服务器筛选角色、导航及块类型。JSON 参数依据 [DeepSeek 官方 JSON 模式](https://api-docs.deepseek.com/guides/json_mode/)；拆分两阶段是本项目为避免排版限制干扰业务选择所作的设计，不代表已证明供应商 JSON 模式与工具调用不兼容。首次 MODEL_OUTPUT_INVALID 和首次仅给清单而未查询事实的运行与失败验收证据都保留；空内容、非法结构或超时仍明确失败，不用模拟回复冒充办理成功。

## 可恢复进度与边界

开始时保存可见目标和自然的办理提示；模型调用、目录版本、工具、委派、确认与回执保存可见步骤。故障保留目标、资料、历史与原成功回执，补充后继续原运行；停止与过期撤销运行令牌。最终回复落库前重新核验身份与当前导航能力，目录摘要不一致拒绝继续。只记录可见答复、过程及供应商用量，不请求或持久化隐藏思考。

目录落库及流程引导不表示 Agent 动作开放。本轮不通过迁移开放能力、不替责任人确认政府审核、真实收退款、正式结果或荣誉，也不重放既有报名、资金和比赛事实。实际模型、普通角色、授权拒绝及故障验证另追加新证据，旧正式报告不改写。

## 只读事实的候选验证

首批可验证的查询为 `type.catalog`、`room.query`、`registration.mine`、`growth.card`、`event.mine`。这些能力的定义均无业务写表、无需人工确认，但仍须绑定当前定义摘要、普通角色证据和候选开放记录。`event.mine` 接受可选字符串 eventId，省略时读取本组织列表；指定赛事先检查所属组织，再读取关联项目和发布检查。参赛查询沿用当前本人及有效队员身份，浏览器或模型不能指定其他账号。

`scripts/Test-AgentReadFacts.mjs` 分 direct 和 `--model` 两阶段。前者通过真实 HTTP 检查本人事实、非成员房间与队伍拒绝、跨组织赛事拒绝及禁止账号覆写，生成候选证据；后者只在平台负责人另行开放恰好五个候选只读渠道后运行，核对真实模型的 MCP 查询步骤和实际积分、报名/房间数量、比赛类型及赛事名称。`--continue-facts` 只向原未完成查询的 waiting_input 任务追加一次原目标，保存原答复摘要和发送状态，不创建替代任务；故障任务通过单独 `--resume-failed` 恢复。脚本不开放任何渠道、不初始化数据、不修改资金或赛事，输出另存 `.local/agent-playbook-20261011`。直接查询通过不能替代模型场景通过，候选通过不能替代主环境发布。

## 2026-10-12 材料、流式进度与候选表单

见ADR-037。通用运行和资料办赛复用原件读取、位置清单、Word嵌图转写与原文引用。每次图片读取不超过六张，每个引用绑定文件、序号、SHA256和位置；已完成可见转写可复用，不能因此绕过当前归属或预算。通用Agent的所有视觉用量仍结算到原根任务，材料输出窗口最多6500 token且受剩余额度约束；超过限额明确失败。已提供材料的初始请求使用JSON模式减少重复排版，普通业务工具选择仍为原生调用；结构恢复阶段没有工具，不能重放办理动作。

普通办赛会话的实际接口：

| 接口 | 作用与边界 |
|---|---|
| GET /sports/agents/runs/{id}/stream | 当前本人运行的可见快照、工具/材料步骤、待确认及结果 |
| GET /sports/b/ai/tasks/{id}/stream | 当前组织可见资料任务的真实识别阶段；不返回隐藏思考 |
| GET /sports/b/ai/tasks/{id}/sources | 原文块、视觉序号、类型、位置、候选转写/用途；现会话和任务关系校验 |
| GET /sports/b/ai/tasks/{id}/files/{fileId}/visuals/{index} | 私有有界JPEG预览，不接受URL或跨任务文件 |
| PUT /sports/b/ai/tasks/{id}/candidate | expectedVersion、event、units、cover；仅更新候选，不创建赛事 |
| POST /sports/b/ai/tasks/{id}/materials | 同任务补充文件，consent和expectedVersion必填，保留人工修改与原件 |
| POST /sports/b/ai/tasks/{id}/confirm | 原确认、版本、项目/整单价及声明约束；派生同任务封面并创建未发布草稿 |

SSE仅重读可见快照，断线不重发创建/确认；浏览器身份或任务改变时关闭旧连接。主办方在同一助手窗口使用通用执行器或办赛候选，不再用“其他任务”切换。来源引用的source_quote在网关从已授权材料组装为可见文本；模型不能用它生成正式确认/回执或扩权。图片推荐、来源填写和表单修改仍是候选决定，不能据此关闭正式业务及外部服务验收。

source_quote可用startRef/endRef指定连续原文范围，或者sourceRefs指定实际位置；不存在、重复或不可读来源拒绝。明确完整引用时，遗漏最多一次无工具的紧凑索引选择，取出正文仍用完整授权材料，不重读全文或取得新预算。最终可见回复最多10000字符，超限明确要求拆分。图片转写可在资料侧选择／划选填入，仍标明候选视觉文本须对照原件。确认草稿动作明确声明asp_file读写以派生封面，文件归属、图片哈希及原版本／价格约束照常执行。
