# 赛事收款指引接口

依据[ADR-028](../03-architecture/ADR-028-赛事统一收款与打开即用宣传文案.md)。金额仍按项目整单；统一渠道只是承办方静态指引，不产生支付交易或实际到账。

| 接口 | 用途及授权 |
| --- | --- |
| GET /sports/b/fees/events/{eventId}/payment-config | 本组织payment权限读取赛事渠道 |
| PUT /sports/b/fees/events/{eventId}/payment-config | 同权限、无正式提交且未取消/结束；revision与当前一致才保存 |
| GET /sports/b/fees/events/{eventId}/payment-config/{channelType}/qr | 同权限、仅当前赛事配置引用的二维码 |
| POST /sports/b/fees/units/{unitId} | 项目金额版本；free金额0，event金额大于0，无正式历史才可改 |
| GET /sports/c/registrations/{registrationId}/payment-instructions | 报名管理人，正式提交后的当次义务快照；非公开查询 |
| GET /sports/c/registrations/{registrationId}/payment-channels/{channelType}/qr | 同报名授权，只读对应快照中该渠道的文件 |
| GET /sports/c/registrations/{registrationId}/payment-qr | 旧入口兼容，取当前义务原始指引第一张二维码，不取当前项目active版本 |

PaymentSettings包含revision（数字）、instruction（最多1000字）、channels。channel包含type（wechat/alipay/bank/custom_qr/offline）、label、qrFileId（HTTP Long字符串）、accountName、bankName、bankAccount、instruction（最多500字）。每类最多一条，微信/支付宝/自定义码必需payment-qr且同租户有效图片；银行三个字段必填；线下必填办理指引。银行字段不会残留到其他渠道。空渠道可保存筹备配置，但event模式收费项目不能发布或提交。重试GET无写入，PUT过期版本拒绝覆盖。

主键/租户及event_id关系由模型生成；settings的schemaVersion为1。渠道复制到应付quote_snapshot.paymentSettings，另保留amount、paymentMode和payInstruction；旧收费义务可从其不可变fee_policy补读旧二维码。新渠道不给公开页面/AI输入；图片通过业务授权接口返回。首次提交与配置共用PG赛事行锁；付款/凭证/实际收款仍按原独立状态。
