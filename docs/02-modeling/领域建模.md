## 独立状态

M1 最终流程 B：正式提交占名额/开立独立义务后即可付款，声明不等于实收；收费审核通过要求有效实收净额足额。无需审核免费提交成功，收费到账重验有效申请/规则/开赛窗口自动成功。审核配置与赛事字段首个正式提交后锁定；原通过/提交历史、撤回重提版本和旧资金分别保存。合法已通过整单撤回后重新占位/确认/付款，旧重试不复活。

取消以赛事状态终止新执行，名额停用、有效统计排除，保留历史占用；真实资金/通知收尾继续。冲正欠款报到限制和已有执行人工协调分开，不自动撤销资格历史或结果。注销保留稳定身份/历史操作者与当前唯一有效本人关联，关闭关系/会话并按必要期限清理；不以 del_flag 代替资金事实、访问隔离或资料删除。

状态存储使用有含义的字符串及 SQL CHECK；状态转换由有权限的应用服务完成，并记录业务依据。数据库能约束取值及部分结构，不能仅凭合法字符串证明专业规则或外部事实成立。

报名办理与名额、资格审核、费用义务、收款和退款分别记录。场次草案 / 发布 / 检录 / 进行 / 完成 / 异常，与成绩草稿 / 确认 / 申诉 / 发布 / 修订分开。荣誉待核验 / 有效 / 暂停 / 撤销独立于竞技结果。发送、送达、已读和确认不共用“通知成功”。

## 模型源与实现约定

模型源为 `database/model/catalog.py`；`scripts/generate-model.py` 输出完整表字段字典、JSON 目录、`database/schema/current.sql` 当前完整DDL和共享表租户排除配置片段。同一源生成，检查模式检测漂移。已落库V001为冻结初始化快照，生成器不覆盖；未来变更编写V002等增量迁移。

`asp_*` 名称用于区分上游 `sys_*`。应用分配 bigint 雪花 ID，避免依赖数据库序列；FK 不使用级联删除。业务时间采用 timestamptz，展示 Asia/Shanghai；生日是 date。审计字段兼容上游 BaseEntity，历史业务字段包含实际发生 / 生效时间。version 为乐观并发版本，del_flag 仅适用于允许逻辑删除的主数据；报名、资金、结果等账事实通过状态及追加记录保留。

共享表没有 tenant_id，租户表必填 tenant_id，并为同租户 FK 提供组合唯一键。共享表移出 MyBatis 租户过滤后仍必须由应用明确授权；参赛者只访问自己的档案，队内成员及赛事工作人员按各自授权查看。

核心金额、时段、人数范围、有效成员唯一性、请求幂等和版本编号通过约束与索引防守。资金累计分配 / 退款上限、容量计数、现实身份匹配、潜在晋级冲突和结果更正影响需应用事务及专业处理；在数据字典中标明责任。

JSONB 用于规则参数、属性取值、名单快照、可变成绩分项、变更影响与外部证据元数据。身份列、实际参赛人、金额、时间、状态和关键关联保留结构化列。属性取值必须对应目录中的类型，不能把参赛人改成一张自由 JSON 表。

## 变更与验收

初版 SQL 在新开发库执行。正式落地后冻结已应用迁移，模型变化新增迁移，先评估已有业务快照和版本引用。每个领域的实现需同时补充 API、事务、权限、状态转换、异常和验收证据。

首要不变量：总人数与项目名额守恒；重复请求不重建业务；付款和退款映射到实际付款人；同租户关联不串租户；历史快照不随现状改写；时间与资源真冲突不能绕过；已发生比赛及外部到账保留。对应验收场景记录于 `docs/04-verification/验收映射.md`。
