# 报名业务流程

日期：2026-10-06。状态：已开发，待业务验收。依据 ADR-007。提交时的收费版本和付款义务见 [收费业务流程](收费业务流程.md) 与 ADR-009。名额锁见 [技术规范](../03-architecture/技术规范.md)。赛事公开以 [赛事公开业务流程](赛事公开业务流程.md) 为准。

下列是最新目标规则，旧主链已有代码不表示本次变化已实现；最终决定见 [ADR-011](../03-architecture/ADR-011-一期业务收口与交付边界.md)，实际缺口见一期清单。

模型写入 `database/model/catalog.py`，并由 `scripts/generate-model.py` 同步。库结构用新迁移变更。已应用的更早迁移不改写。

## 1. 谁在用

| 角色 | 本期能做 |
| --- | --- |
| 参赛者 | 已登录的平台账号，并且本人档案已齐。为自己创建报名，邀请其他已注册账号，提交、撤回。当前队长还可以代表长期队伍报名，见 [长期队伍业务流程](长期队伍业务流程.md) |
| 被邀请成员 | 用自己的平台账号打开邀请链接，确认或拒绝。确认前档案必须已齐 |
| 组织管理员 | 已进入该组织的管理会话。为已有赛事建立竞赛单元，审核整单报名 |
| 超级管理员 | 不审核报名，也不能代替参赛者提交 |

报名属于赛事所在组织。页面不向参赛者展示租户。

## 2. 竞赛单元

承办方在自己的赛事下建立竞赛单元。单元记录玩法、人数上下限。名额上限写在该单元唯一的容量池上，单位是 `entry`。

| 玩法 | 人数 |
| --- | --- |
| 单打 `individual` | 1 |
| 双打 `pair` | 2 |
| 团体 `team` | 承办方填写下限和上限，下限至少 1，上限不小于下限 |

报名窗口在赛事上。单元不另记窗口，不建完整竞赛规则引擎；全赛事自定义字段配置、成员确认及快照版本必须实现。收费单独版本化，提交读取有效版本。项目有正式提交历史不可删除；容量调整不低于实际占用，和提交/释放共用并发保护，名称一般更正不改变含义。

已取消或已结束的赛事不能新建单元。

## 3. 报名状态

`draft` 草稿，不占名额。`submitted` 已提交，占名额。`approved` 已通过，继续占名额。`rejected` 已拒绝，释放名额。

```text
draft → submitted → approved
                 → rejected → submitted
submitted → draft
```

以上状态图仅描述旧实现，目标另需保留提交/撤回历史，不以复用当前行覆盖事实。已提交可合法整单撤回；已通过在报名截止前、全单无人报到且无场次关联时也可整单撤回并释放名额。重提使用新请求键、提交版本和独立付款义务，刷新资料/字段及本人确认、重新竞争名额和审核，不复用旧付款。

同一提交人在同一单元只有一条报名。

## 4. 成员确认

成员行按平台账号记录，不复用长期队伍邀请，也不在确认前写入名单快照。

创建草稿不替代最终本人资料确认。各成员填写/确认自己的资料和赛事字段，提交人本人也需覆盖当前配置版本，其他成员待确认。邀请仅对应账号本人，拒绝不占人数。草稿实质配置变更需相关人补填重确认，排序变化不重确认。

被邀请人在邀请人提交之前就能看到赛事、项目、整单状态和自己的确认状态，并可以确认或拒绝。邀请人提交之后、承办方通过或拒绝之后，被邀请人仍然能看到这条报名的状态，只是不能再改自己的确认。入口是邀请链接，以及「我的报名」里的收到邀请。

提交要求：人数合法、无人待确认、每人资料及字段值满足当前赛事配置并完成本人确认。组织维护本组织目录，赛事统一选择必填/选填；一期不分项目字段集，不复制其他赛事答案，不把组织字段写进共享个人档案。快照保留当时值、标签、类型及枚举含义；队长仅见完成情况，不取得全套敏感值。

## 5. 提交和名额

提交必须同时满足：

- 赛事已发布，组织仍是平台准入，举办状态不是已取消。
- 当前时间在报名窗口内。边界落在窗口之外：开始时刻可以提交，结束时刻不能提交。
- 容量池尚未用完。
- 该成员没有另一条已提交或已通过的同单元报名。

名额加减包在 `MutualLock` 里，键是 `capacity:{tenantId}:{unitId}`，PostgreSQL 权威约束/事务继续保留。`invite`、`addTeammate`、`removeMember`、`confirmInvite`、`decline` 和 `submit` 在锁内重读状态与成员版本后再写；代表队伍先取 `team:{teamId}`。撤回、通过和拒绝继续使用这把容量锁。名额调整以后共用它，调整功能尚未实现。已经完成提交的请求键记在 `asp_registration_submit_key`：旧键重放不新增占用、名单版本和义务，主动重提使用新键。2026-10-07 已用参赛者路径验证这两项。

提交成功后写入名单版本和名单成员。审核不另造名单。整单审核记录不指向单个名单成员。

通过保留名额，拒绝/合法撤回释放。默认人工整单审核，收费通过必须本次有效实际收款净额达到应付；声明不等于到账。赛事无需审核时免费提交检查通过即成功，收费到账后重新校验有效申请/规则/开赛窗口自动通过。首个正式提交锁定审核配置，全部撤回也不解锁。

提交后可立即付款，报名截止后已有提交仍可在开赛前审核/付款，开赛不新增通过。长期未付款由运营依政策人工拒绝，显示最新正式申请时间/等待时长及未声明/待核对/到账，不自动超时释放。开赛待审提示未取得资格，仍可人工拒绝和资金收尾。取消停止新业务、名额停用、保留历史；不伪造拒绝或自动迁移。

## 6. 写入租户

参赛者的登录租户是技术租户 `900001`。报名、成员、容量和名单写入赛事所属组织的租户。查询自己的报名时按平台账号过滤，不把 `900001` 当成报名数据范围。

## 7. 代表长期队伍

`team_id` 为空时，本节前面的个人报名和临时双打不变。

有 `team_id` 时，只有该队当前队长能创建、修改成员、提交和撤回。创建人字段只留审计。名单从当前有效成员里选，不自动写入队长。选中的非本人仍要本人确认。提交时重新核对队伍和成员仍然有效，成功后写入队名快照。退队和解散不改已提交或已通过的报名，也不自动删草稿里的人。

提交按当前有效收费版本产生独立义务，免费不制造付款。收费审核以有效实收为前置，无需审核分支到账后可自动通过；人工资金权限仍独立，详见 [收费业务流程](收费业务流程.md)。

「我的报名」目前不区分赛事仍在报名中，还是已经下架。下架不改报名数据。后续界面要么在同一列表上标出区别，要么拆成多个界面；具体效果在 UI 开发时再定。

## 8. 本期不做

- 付款和资格各有状态，收费通过必须有效实收，后续冲正不抹除旧审核，见 [收费业务流程](收费业务流程.md)。
- 候补、临时占位、未注册占位、阵容调整。
- 完整竞赛规则引擎；必要字段配置/确认/名单快照版本不后置，费用引用原收费版本。
- 跨单元禁止同一人重复报名。

TC21、TC22、TC23、TC25、TC27 仍待业务验收。

## 2026-10-08 参赛邀请与详情反馈实现

`POST /sports/c/registrations/{id}/members` 可选 requestSms，默认 false。新有效邀请自动持久站内信，重复同一邀请版本去重；邀请页面和成员本人确认接口继续验证目标账号。InviteView 增加 members，仅已确认的受邀本人可见当前伙伴姓名/确认状态；正式提交前提示名单仍可能调整，不额外开放敏感资料。MemberCard 增加可选 notice 渠道摘要。

收费详情足额后改为额外真实收款的补记入口，空金额、必填原因、二次核对；相同付款人/金额/时间提示核对。后端幂等与资金行锁继续承担事实保护。无需审核的有效收费申请到账重验后自动通过，页面重新查询并明确显示当前资格。不会根据界面意见删除已有实际款项。详见 ADR-014。

## 2026-10-09 质量检查：审核窗口与自动资格

ADR-011规则不变。本轮补齐服务端人工审核开赛时间校验，开赛及之后不新增资格；报名截止后、开赛前仍可处理存量报名。无需审核收费报名的每笔到账回调现在复核当前付款义务的足额状态，部分到账或失效义务不能自动通过。实际到账仍按资金服务记账与收尾，不因资格未通过伪造退款或回滚真实到账。源码及服务测试结果见[第二部分报告](../04-verification/全局质量检查-第二部分-20261009.md)，本轮未重启运行包，不当作普通角色验收。

## 2026-10-09 从未提交的草稿删除

见[ADR-023](../03-architecture/ADR-023-助手身份传递与报名草稿删除.md)。DELETE /sports/c/registrations/{registrationId}仅本人可办理者删除从未提交的draft，代表队看当前队长。团队→容量锁与事务内重验，拒绝正式提交/名单/资金/名额占用历史，清理成员采集值与邀请并留最小删除审计，版本冲突回滚；撤回后的draft仍保留。无退款、容量释放或管理员代删，前端按钮由Cursor按交互契约接续，真实普通角色并发验收继续保留。


## 2026-10-12 提交资料和费用展示修复

公开费用以有效策略为准，event为有效赛事统一收款模式。草稿展示当前预计费用，正式提交冻结本次应付。组织审核 GET /sports/b/registrations/{id}/submitted-roster 读取当前正式名单修订的姓名、性别、出生日期、电话和采集项标签/答案，不把当前个人资料替换历史。新采集项快照写入原名单JSON，无新增迁移；旧版未保存的项明确提示。普通队友/公开接口不新增私人联系方式或出生日期。决定与实际25项验证见ADR-038和报名与录分修复验证-20261012。

## 2026-10-12 队伍报名一次选人与确认

见 ADR-040。报名弹窗直接选队伍和实际上场成员，自动带入已有本人基础资料；核对完整名单与费用后一次准备草稿和站内邀请。全员本人确认、必要采集项与声明仍是正式提交条件，队长可只代办不参赛。正式提交再次展示名单与费用，不再要求从空名单逐人添加。老空草稿可一次补齐，已有名单不被创建请求替换。

当前登录人不在名单时不读取本人赛事字段或声明；selfMember 回显按当前账号判断。准备名单是 team → capacity 锁与完整事务，重复请求返回现状、不恢复已移除成员。实际普通账号及并发证据见[本轮报告](../04-verification/奖项材料与队伍报名修复验证-20261012.md)，不是正式用户验收。
