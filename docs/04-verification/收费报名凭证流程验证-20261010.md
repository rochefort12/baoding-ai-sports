# 收费报名与可选凭证流程验证

日期：2026-10-10。本地真实接口、数据库及存储流程；外部资金全部模拟。用户授权创建收费赛事、报名、上传凭证、核对收款、审批、排查并修复明确问题。不是管理员演示，也没有直接改数据库业务状态。

## 结果

正式 Vue 页面与真实 API 完整流程最终 **46 项断言通过**。普通承办人创建人工审核的 198 元单打赛事，普通用户正式报名，从手机页面上传合成回执；承办人从报名详情看到凭证，填写付款人、98 元实际到账测试值、时间、SIMULATED 备注；补记 100 元后，在页面审批通过。参赛端刷新可见已通过。另一个普通用户不上传、不声明，也能在模拟足额收款后通过。

管理员仅用于准备两个合成测试组织的准入，后续赛事、报名、收款、审批、退款和冲正全部使用普通组织/参赛会话。测试账号及所有材料均为本地合成数据，无真实转账、对外发布或短信。用真实存储和事务验证模拟账目，不表示银行/支付供应商到账或正式资金业务验收。

## 实际修复

1. 原项目没有付款凭证上传功能。新增 V027、报名关联、私有图片存储与两端查看入口，明确推荐但非强制。
2. 旧收费页“确认有误”缺少 paymentId，后端正确拒绝；改为选择具体原收款。
3. 旧退款按钮缺少金额、时间、接收人和原因；改为实际退款表单并保留稳定请求键、防重复。
4. 旧收费页部分收款后默认再次填写全额；改为根据实际净额默认剩余金额，补齐金额和时间校验。
5. 手机长付款弹窗加入高度限制、正文滚动；通过后仍可查看本次凭证，上传期间切换报名避免旧响应覆盖。

未发现本轮必须由用户另行决定的业务冲突。赛事级微信/支付宝/银行/线下统一配置仍是原待办，本次验证现有线下人工收款；真实支付渠道、真实退款、PDF 回执/OCR及只具备 organize 的工作人员完整权限切片未在本轮验收。历史义务的材料保留，不新增完整财务/对账/审批平台。
