# 全局质量检查第三部分：测试有效性与校准

日期：2026-10-09。依据 ADR-011、ADR-019 和用户逐部分执行决定。本轮完成第三部分，不提前宣称第四部分或一期业务验收完成。

## 当前结论

正式前端测试已能覆盖新版页面和自然语言助手，但原先未登记的接口被成功空数据掩盖，AI 创建终态及失败恢复也有缺口。本轮改为未知请求必失败，补具体接口响应与关键反例。校准过程中发现一个实际缺陷：带项目编号进入 C 端报名页会自动准备草稿，创建失败未捕获，产生浏览器未处理异常；已修复为留在项目页显示失败，保留手动操作，不自动重复请求。

现有单测调用实际业务函数或服务，依赖隔离的测试仍不能证明真实数据库事务、并发或普通角色全链路。旧静态原型测试继续只作设计检查，未并入正式页面验收。

## 校准内容

| 检查 | 本轮调整与保护 | 证据边界 |
| --- | --- | --- |
| 六组正式页面脚本 | 统一 UiFixtureAudit，隔离上下文所有 XHR/fetch 截获；未知读请求返回失败并在结束断言，未知写请求拒绝。明确补验证码、租户、菜单、组织申请、报名字段/项目、问答列表及读回响应 | 未登记请求不能继续以成功空数组蒙混；具体夹具仍需维护，不是自动生成的完整接口契约测试 |
| B 端 AI | 失败确认后重新读取任务，不自动重发；再次明确确认返回 CREATED 编号，不能自动发布/跳路由/保留重复保存按钮；恢复问答采用服务端消息且不调用模型 | 模拟任务及问答响应，不是真实建赛、Redis 写入或模型质量验证；同日并行新增反馈检查保留 |
| C 端 AI | 插画等待实际加载，登录页和最终项目页等待加载就绪；保留脚本异常断言。分别测试无预选项目只读上下文及预选项目自动创建失败 | 后者仅在本地返回失败的 POST，未发往后端；不以添加虚构队伍或放松异常断言规避失败 |
| AI 确认服务 | 新增 AiTaskConfirmationTest，实际调用 confirm：CREATED 重放、加锁后重读终态、跨组织在锁前拒绝、FAILED 拒绝；核验不再创建或更新任务 | Mockito 依赖与锁调用顺序；不代表真实 PostgreSQL 并发及首次成功创建事务已验收 |
| 既有单测 | 对照实际前端工具、赛事/助手/资料策略与网关调用；复跑相关测试。新运营会话数量规则纳入入口 | 组织准入、身份服务覆盖仍不均衡；段数规则不等于真实第九段删除或 Redis 失效验收 |
| 集中入口 | 新增 Test-FrontendRegression.ps1 串行运行认证、普通 B/C、关键交互、AI B/C；Test-CriticalRisks 增补审核/实收/结束保护、AI 服务、会话规则、网关及两端 AI | 任一步失败非零退出；本轮未整套执行包含数据库创建的 CriticalRisks；第四部分再做分层全量 |

C 端修复文件：plus-ui/src/views/sports/registration/enter.vue。仅接住自动准备草稿失败，保留既有带项目深链自动准备草稿的业务行为，不扩大为本轮报名流程重设计。
