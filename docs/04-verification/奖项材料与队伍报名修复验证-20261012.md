## 当前结果

| 问题 | 原因及修复后的行为 |
| --- | --- |
| 同一人的多个获奖修改项，新旧证明同时有效 | 原逻辑按奖项名称和单次签发分组。现在同一报名的最终名次作为一个连续奖项办理，多次改名、连续纠错只显示一个当前复核项；同一奖项每位获奖人只保留当前有效证明。专项奖与其他项目独立。暂停、撤销和被替代的证明进入历史，不能导出成有效证明。 |
| 修改不同场次后证明依据不一致 | 最终名次采用本项目完整当前正式赛果；专项奖采用明确选择的本报名场次。新增正式赛果和受控纠错使相关当前证明待复核，重试不重复暂停。签发时检查读取的版本和赛果摘要，失效、撤销或期间变化则拒绝；负责人手工核实，不自动推算名次。 |
| 材料直接显示 Markdown 原文 | 已保存、模板及生成内容默认进入阅读预览，可切回原文编辑。标题、表格、列表、引用和代码块共用安全渲染器；材料字体统一，标题保留层级，不执行原文 HTML、脚本或危险链接。保存仍是草稿。 |
| 队伍报名要先建空草稿，再逐个加人 | 选择项目后直接选队伍，展示当前全部成员；按项目人数自动预选可用成员，超人数时明确选择。第二步核对完整名单及费用，一次带入草稿；正式提交再次核对完整名单。其他成员仍须本人确认，队长不能代签。 |
| 不参赛的队长出现“你不在这条报名里” | 回显按当前登录者标记本人。未参赛的队长可管理名单并完成整单提交，不请求仅参赛成员可访问的本人字段和声明。已提交快照、名额、资金和资格仍由服务端判断。 |
| 同一人的其他项目也显示已报到 | 新增项目编号，报到状态及有效记录按组织、赛事、项目、人员区分；请求摘要、锁、冻结名单和收款复核采用同一范围。已在甲项目到场不误阻止未到场乙项目合法撤回；同运动多个项目不重复生成赛事成长报到。 |
| 悬浮助手文字占据页面 | 办赛端与参赛端入口仅显示原静态图标，去掉“赛事助手／体育助手”和办理中的文字标签。保留点击打开、拖动、键盘及辅助名称；窗口内标题保留。手机项目报到使用参赛人卡片，按钮和状态可直接查看。 |

## 保留的失败与修正

中间测试的名单四个新增用例遗漏本地标签，最初构建仅执行 454 项，不能声称执行 458 项；补标签后重建，最终实际执行 467 项。另有前端类型、错误的界面元素计数及构建期间源码变化的失败，原回执保留。

项目报到演练首次漏取人员编号，未写入报到，修正测试读取后在同一已建合成赛事复现。修复流程已完成乙项目撤回后，测试误按 `withdrawn` 状态判断；实际业务返回草稿、旧提交名单失效、释放一单名额。后续只观察同一已撤回报名，并引用之前 11 项成功观察，没有重做撤回。最后名单只读检查误把有效名单状态写成 `current`，原失败保留，改按实际当前名单版本和未失效状态只读核对。

## 历史数据与未完成事项

旧赛事级报到没有项目证据。V040 保留原记录的全部字段和发生时间，项目为空；界面显示“待项目核对”，负责人核对真实到场后办理项目报到。不能按现在报名情况推测当时在哪个项目到场，也不能复制成全部项目已报到。未知项目历史到场保守阻止整单撤回；历史正式纠正和原用户逐项目核查仍待真实办理。

本轮证明连续关系优先使用明确奖项类型和前次引用，旧名次名称用有限规则识别；没有可靠依据的旧专项名称仍需要人工核实。不同项目／不同专项合法多个奖项不合并，暂停或撤销的旧版本不再作为当前有效证明出现。

本轮队伍演练人员、场次、资料和费用均为合成。没有代成员确认，没有真实银行收款，也没有通过改库伪造业务状态。实际赛事排位、外部短信、真实手机设备、跨组织全量及负载验收未因此接受；一期 21 项功能、17 项使用缺口、7 个普通角色切片保持原清单管理。
