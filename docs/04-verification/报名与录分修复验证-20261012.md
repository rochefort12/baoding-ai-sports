# 报名与录分修复验证

日期：2026-10-12。结论：用户提出的四项缺陷已实现，在同一个本地隔离库用普通办赛方与普通参赛者会话完成 25 项接口和网页检查。已更新本地试用服务，用户亲试与正式业务验收仍待进行。机器证据见 [验证索引](报名与录分修复验证-20261012.json)，决定见 [ADR-038](../03-architecture/ADR-038-报名费用提交资料与手动录分交互.md)。

| 用户问题 | 原因 | 修复后的行为及实际验证 |
| --- | --- | --- |
| 已设置报名费仍显示待公布 | 公开页面只识别旧收费模式，遗漏赛事统一收款 `event`，因此禁用了报名入口 | 两处公开页复用费用判断；桌面和手机普通参赛者看到 100.00 元/单并能选择该项目。免费仍须明确零金额 |
| 报名页面文字、头像与侧栏粗糙 | 页内重复的小字号样式和共用主题相互覆盖 | 报名共用样式集中在 styles，删除重复局部样式。头像 40px、正文 14px，右侧卡片统一间距、手机单列；真实页面无横向溢出。资料保存按钮独立于字段网格 |
| 审核只有姓名 | 已有个人快照只投影姓名，页面未呈现必要资料；赛事采集答案没有随名单版本完整冻结 | 独立的组织授权接口读取提交版本，显示姓名、性别、出生日期、电话与采集项。新提交冻结标签/答案；参赛者调用审核接口被拒绝。提交后改写采集项被拒绝且快照不变 |
| 单侧批量录分失败，胜负交互不方便 | 导入强制 A、B 两行，B 行比分也没有核对；录入默认 A 胜并依赖下拉框 | 原样 01–06 六行及行尾反斜线实际导入为六场草稿，自动补齐对方胜负。重复请求幂等，冲突和未知后续场次整批回滚，不能跨项目或用参赛者身份导入。胜方改为点击卡片，本局比分可加减/直接填，手动结束本局和比赛后核对保存 |

录分提示分默认 21、可修改，只是辅助提醒，未引入羽毛球或其他项目的专项规则引擎。达到提示分不会自动结束或发布；当前局未结束会禁止静默保存，避免丢失点按的分数。正式结果确认仍独立，并展示对阵和比分供人工核对；未来赛事的正式确认实际被拒绝，草稿没有进入参赛者正式赛果列表。更正正式赛果沿用已有修订流程。

导入仍是五列 `场次编号,A或B,win/loss/draw,总比分,分局比分`，比分均为 A:B。例：`01,A,win,2:1,21:18|18:21|21:17`。单 B 行也按 A:B 填分数。兼容旧双行的相同或镜像比分；重复同侧、双方胜负或比分冲突、额外列等会拒绝。导入仅保存草稿，没有绕过原事务、赛事和请求键边界。

旧报名的个人快照可以读取既有信息；未保存赛事采集项历史的旧版本明确提示缺失，不用当前资料回填成历史。没有增加公开或队友接口中的联系方式、出生日期。

本轮没有修改用户原赛事、原报名或原成绩。当前授权组织的原赛事同名匹配未形成这轮直接验收证据，因此公开费用与点击报名用新建的模拟收费赛事验证，不能将其表述为原赛事已逐项验收。上一轮强 Agent 资料测试没有将 `event` 收费模式的公开报名点击及单侧 CSV 作为专门验收场景；后端编译和材料解析成功不足以发现这两处页面/输入契约缺口，本轮增加普通角色的实际覆盖。
