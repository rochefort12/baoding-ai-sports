## 已实现的交互与业务行为

1. 悬浮助手与通用助手的文件窗口支持拖拽。文件先成为可移除附件，用户发送后才处理；文件类型、数量、大小、同意状态和当前任务限制与选择文件一致。无效拖入不清空已选文件，文件拖入不会触发浏览器跳转。未登录参赛者会提示登录。
2. 文档识别结果直接形成可填写表单，包括运动项目说明、时间、地点、联系和退费说明，以及各项目报名上限和整单价格。缺项在表单内标识；桌面内部采用两列，手机采用单列，外层表单保持一个连续区域。材料引用和处理记录可展开核对。
3. “全部项目100元”按每个项目的整单报名价格写入候选，不按成员人数再乘算。保存／创建后价格实际写入费用配置。按人、附加费用和条件收费仍需明确含义，不能猜成整单价格；已写入的明确整单价格不再循环追问。
4. 创建按钮使用当前表单与版本，成功显示实际赛事编号，失败保留输入并显示原因。CREATED 任务继续关联原赛事和项目 ID；聊天与表单修改保存到该草稿，刷新后仍可接续。发送新问题前会先保存未提交的表单输入。
5. 其他工作区修改导致版本冲突时，拒绝覆盖并保留本地输入。“读取赛事当前内容”明确读取真实草稿，保留刷新前填写供核对或回填；重复读取不丢掉已有备份。历史任务缺少安全基线时要求先实际读取。当前流程支持原项目的修改，不自动增删原项目。
6. 对话发送“发布赛事”显示实际赛事、项目整单价格、时间、地点、联系人及退费规则的核对卡。收费赛事缺收款方式时，可在同一窗口保存线下收款说明，再核对并发送“确认发布”。保存收款说明不会自动发布，也不记录实际到账。正式发布核验权限、版本和实际预览哈希；项目价格、收款配置版本等变化后，旧核对不能直接发布。“确认发布？”等询问不作为确认。
7. 已发布赛事显示实际状态和编号，草稿编辑入口收起；发布后继续执行管理赛事的正式流程。关闭再打开助手会定位当前行动卡，继续聊天不强制跳转，手动读历史不被抢回。
8. 多选建议累积到输入框并保留手工文字，取消一个选项只移除该项。删除重复“下一步”面板，完成的处理阶段折叠为一行，额外工具和材料说明可展开；增加聊天留白、轻量动画及减少动态效果适配。
9. 本轮受影响的审核赛事选择和赛事列表按创建时间倒序，同时间按 ID 倒序。未发布、未实际使用的收费配置草稿可删除，连同其未使用的现行／历史价格配置和收款设置清理；真实报名、收付款或历史使用继续阻止删除，操作在赛事锁与事务内完成。

依据与接口： [ADR-045](../03-architecture/ADR-045-悬浮办赛表单与收费草稿删除.md)、[赛事资料建赛接口](../02-modeling/赛事资料建赛接口.md)、[赛事公开业务流程](../02-modeling/赛事公开业务流程.md)。不开放通用 Agent 未核验写渠道，不改变真实资金确认权限。
