## 发现与修复

1. 参赛邀请页接受/拒绝没有忙碌状态。等待服务返回时仍可点击相反操作；现两操作互斥、接受显示忙碌、拒绝禁用，服务失败后恢复。最终手机交互用例验证失败重试、处理期间两按钮禁用、成功后展示最小伙伴名单。
2. 登记收款接口失败虽由共用请求层提示，页面异步事件仍抛未处理异常。现本页消费已提示的错误，保留表单与请求键供核对重试；入队邀请页同样处理失败。最终错误模拟后浏览器未处理脚本异常为0，资金重试不换请求键。

测试工具自身的首轮问题也已纠正：临时库恢复保留PostgreSQL默认public schema；关闭对话框等待动画结束；Element Plus短信复选框通过可见标签操作。首轮集中执行在短信控件定位处退出非零，没有当作整套通过；修正后前端交互28项独立复跑通过。后端37项、前端单测17项及HTTP6项在集中执行已通过；数据库最终独立复跑9项通过。没有为了绿色结果删业务断言。

## 数据隔离与证据

开发库只导出schema-only，不拷贝或修改用户数据。测试在aisports-dev-postgres内本轮创建、受控前缀且随机名称的独立库执行，全部数据虚构；finally关闭测试进程并删除该库和结构临时文件。最终查询临时测试库遗留数为0。

Playwright使用独立浏览器会话，模拟token不发送真实业务接口，所有业务XHR/fetch包括GET都截获；意外写请求0、最终脚本错误0。实际HTTP只访问公开接口或不带会话的受保护接口，未执行真实收款、退款、发邀请、报名或注册，没有真实短信调用。正在人工测试的赛事、报名和资金保留；没有改TC01—TC80验收状态。

本机忽略目录.local/critical-tests保存database-results.json、http-results.json、ui-results.json、suite.log及手机截图；最终数据库/交互JSON的completed=true。后端JUnit详细结果在各模块target/surefire-reports中。suite.log保留首次集中执行的定位失败，不能只看它最后一行判断最终独立复跑结果。

## 如何再次运行

在项目根目录，用PowerShell 7执行：

```powershell
pwsh -NoProfile -File scripts/Test-CriticalRisks.ps1
```

需要现有前端5173、后端8080、aisports-dev-postgres正常启动，本机.env已配置，Java/Maven、Node与项目依赖可用，Edge已安装。集中入口刷新API契约缓存，依次运行相关后端单测、Vitest、临时库集成、匿名HTTP与模拟前端交互，任一步失败即非零退出。它不会启动或清空业务环境。

已有不同端口或Playwright安装位置时：

```powershell
pwsh -NoProfile -File scripts/Test-CriticalRisks.ps1 -BaseUrl 'http://127.0.0.1:5173' -NodeModulesRoot '本机Playwright所在node_modules绝对目录'
```

定位失败可单独执行Test-CriticalDatabase.ps1或Test-CriticalHttp.ps1；交互入口为node scripts/Test-CriticalUi.mjs后跟实际node_modules目录及可选站点地址。
