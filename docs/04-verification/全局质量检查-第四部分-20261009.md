# 全局质量检查第四部分：分层回归与收口

日期：2026-10-09。依据 ADR-011、ADR-019 和四部分检查方案。本轮检查与工程回归不等于一期交付或普通角色全链路验收。

## 发现及修复

1. 数据库结构测试基线仍为 V020 的 84 表/1292 列，实际迁移账本已到 V024。逐项校验 V001—V024 SHA256 通过；V021—V024 增加 7 表/111 列，更新 preparation.sql 为 91 表/1403 列，继续检查注释、租户外键、版本/状态/唯一性/配额。未修改迁移或实际结构。
2. AI 对话候选写回 Q2-07 存在晚到模型回复覆盖其他窗口候选、终态静默不写却返回成功、忽略更新失败的问题。saveProposal 在短事务内先核验归属，再行锁重读；只有仍待确认且候选等于模型读取的依据时更新，并校验影响行数。锁不跨模型调用；冲突明确拒绝，页面既有失败处理重新读取任务。失败补充回复也校验相应依据。新增 4 项实际写回方法测试，与 4 项确认保护测试共 8 项通过；依赖隔离，不冒充真实 HTTP/数据库服务并发。
3. 全后端反应堆直接开启测试，在无测试引擎的纯契约/Redis 基础模块遇到父级 Tag 过滤错误。尝试仅覆盖契约模块配置无法解决所有基础模块，已撤回该尝试，没有引入额外运行依赖或全局关闭测试。模块测试正常，整反应堆测试入口仍有工程缺口；合包使用既有跳测入口，不能算全模块测试通过。
4. 六组正式前端顺序运行中，B 端 AI 默认右侧位置再次超时；同一严格断言单独复验通过，增加超时位置诊断和截图，未降低位置断言。原因尚未确定，保留稳定性缺口，不归因于 Cursor 重启。共享工作区有并行反馈/上传状态检查，本轮 B 端 AI 当前执行 58 项。

## 剩余事项与优先顺序

- Q2-05：赛事联系人发布确认/冻结快照未闭合，当前公开费用仍读取组织当前联系人；先补冻结与历史读取，不能改几句界面文字关闭。
- Q2-06：AI 草稿目前以免费项目创建，候选费用说明不能替代真实收费版本；沿现有人工收费确认链衔接。当前必须人工核对，不宣称任意文本可直接正确建收费赛。
- Q2-07：本轮候选写回源码保护与针对性测试完成；真实多窗口/模型晚到/保存确认竞争仍待受控普通角色验收，不以行锁单测关闭全部AI并发问题。
- Q2-08：上传限制按现行6份/15MB/40MB；模型告知固定名称与可配置提供商口径仍需统一。
- Q2-09：Redis问答期限、数量及恢复已有规则/隔离交互证据；真实第九段删除、过期、不可用及跨账号/组织隔离仍未本轮执行。
- Q2-10：本轮迁移/实际结构及运行合包检查补证据；7个普通角色切片、真实资金/名额服务并发、短信/验证码服务端验签、模型质量仍待执行。现有用户业务数据未清理，未用直接改库/管理员演示替代真实角色链。
- Q4-01：B端助手初始位置偶发超时仍待定位，后续利用新诊断重现；单独通过不等于稳定性修复。
- Q4-02：全反应堆测试需解决无引擎基础模块的Tag过滤继承；目前用模块入口，不能把打包跳测说成全面单测。

身份与组织服务测试覆盖仍不均匀，短信资质/模板、人机验证、真实模型评测和普通角色完整路径未具备本轮可直接完成的验收证据。未启用MCP/关闭验证码、伪造实际到账、写真实报名或清除现有数据来制造通过。TC01—TC80、21项功能、17项使用缺口与7角色切片不批量改变状态。下一步优先联系人/收费衔接与真实角色资金流程，再处理测试稳定性和外部接入；本轮四部分工程检查已形成可复验记录，尚不能认定一期可交付。
