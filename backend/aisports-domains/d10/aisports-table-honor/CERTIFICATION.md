# 外部荣誉认证

复用 `asp_honor`，新迁移 V038 追加外部认证状态、本人账号、申请、审核事实、历史及佩戴/公开开关。旧赛事证明和成长称号不迁入认证流程，历史主键不变。认证不写 `asp_growth_*`、比赛结果或组织资质。`title_code` 保持为空，与成长称号的 `asp_title_equipment` 独立。

个人仅可保存及提交本人申请。支持世界级赛事的个人冠军、亚军、季军；申请和审核输入必须明确 `level=world`，真实年份不晚于北京时间当前年份。资料保存后上传私有 `honor-proof`（图片/PDF，5MB、最多8份）。提交经过统一动作确认和幂等回执；提交后禁止直接改写，补正或不通过后可重新保存、提交。

平台负责人使用既有 superadmin 身份核实，不扩政府或普通组织管理权限。审核前显示当前账号绑定的本人档案姓名、出生年份、证件资料是否已填写和实际档案核验状态；不输出证件散列、加密值、完整号码或手机号。昵称不能证明归属。通过须独立填入年份、完整赛事名、项目、世界级名次、正式公布单位及 HTTPS 结果依据，确认卡包含这些事实及本人档案版本。服务端再次锁定申请、账号和本人档案，拒绝版本变化，并生成含年份、赛事、项目和名次的准确称号。审核人负责核实外部事实；系统不会自动联网验证结果，也不把审核勾选冒充外部机构认证。

申请状态为 `draft → submitted → approved/correction/rejected`，补正/不通过可回到草稿重提。已通过可由平台负责人撤销。申请、提交和决定历史追加保存。撤销同时关闭佩戴与公开；每人每运动最多佩戴一个有效认证荣誉，数据库部分唯一索引和事务锁共同保护。本人公开同意与运动名片公开同意同时具备才返回匿名投影。公开 DTO 只含准确标题、年份、赛事、项目、名次及佩戴状态，证明、实名和审核说明不公开。

证明的专用读取只允许申请本人或平台负责人且必须被当前申请/历史引用。读写经执行器兼容事务留访问审计，通用媒体、头像及普通材料入口拒绝该用途。夜间未引用文件清理包含当前与所有历史证明，拒绝/撤销不清除历史依据。

`awarded_at` 是既有非空字段，外部申请初始化为申请记录时间；外部实际获奖事实仅按已核实的 `eventYear` 展示，来源注明 `awardDatePrecision=year`，不推定具体日期。

新能力全部 `agent=false`。保存、提交、审核、佩戴和公开走注册执行器；multipart 上传用兼容执行器事务并额外核验当前本人可用的 `honor.certification.proof.upload` UI 开放状态。登记不表示开放，迁移不自动发布渠道。本模块不调用模型、不重放报名或资金。
