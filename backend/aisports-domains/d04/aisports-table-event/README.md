# aisports-table-event

本模块是 `asp_event` 的手写业务入口，属于 D04。生成对象说明保留在 [MODULE.md](MODULE.md)；本说明不由表工程生成器覆盖。

赛事查询、发布、材料识别与确认、宣传、工作文稿和展示封面沿用当前组织授权。表工程仅直接依赖 `aisports-platform-core`；跨表事实使用动作私有投影及纯契约，不引用其他表工程的 Mapper、实体或实现。

## 赛事材料与封面

- `EventMaterialController` 读取当前赛事事实、事实摘要、赛事版本和私有工作文稿。
- `EventMaterialActionProvider` 登记 `event.material.save`、`event.material.generate`、`event.cover.save`。写入经过统一执行器，按角色、组织、开放渠道、版本和幂等键检查。三项能力的 Agent 渠道默认关闭。
- `EventMaterialService` 在 `asp_event.operations_materials` 保存策划、脚本、公告和宣传的独立版本，分别记录人工或 AI 来源，保留最多 10 条旧版本。标题最多 200 字，正文最多 10000 字，与页面、统一执行器及模型输出一致。V034 增加该 JSONB 对象列；原赛事数据和其他规则快照保留。
- 生成先检查当前版本及事实摘要，真实模型成功后再锁定赛事并重复核对。模型故障、事实变化或并发改稿不能覆盖原稿。没有模型配置时仍可编辑、使用明确标记的基础模板、保存及下载。
- 封面关联只修改展示媒体。保存必须使用当前赛事版本，并验证同租户、有效的 `event-banner` 图片用途；已取消赛事禁止继续调整封面。已发布赛事更换封面不改变报名规则、名单或收费快照。

模型通过既有私有 AI Gateway 调用；浏览器不持有模型密钥。草稿保存不发送公告、短信，不登记资金、政府审核、正式赛果或荣誉。接口约定见 [赛事材料与封面接口](../../../../docs/02-modeling/赛事材料与封面接口.md)，产品决定见 [ADR-031](../../../../docs/03-architecture/ADR-031-独立视觉落地与办赛材料工作室.md)。

## 当前验证边界（2026-10-11）

`EventMaterialServiceTest` 的 7 项模拟单测覆盖组织拒绝、过期版本、事实变化、AI 失败保护、历史来源、封面约束和正文 10000/10001 字边界。Gateway 材料测试的 5 项模拟单测覆盖凭据缺失、资料指令边界、非法输出、额度失败和相同长度边界；它们只证明各自模拟边界。总控当前 Gateway 全套 40 项通过。

`scripts/Test-ProductMaterials.mjs` 在隔离 8082 环境完成 28 项真实 HTTP 检查，包括普通主办方读写、参赛者拒绝、手稿与历史、四类 DeepSeek 草稿落库、重复请求回执、事实及版本冲突、真实封面上传/保存/匿名读取、错误用途拒绝，以及 10000 字实存、10001 字拒绝与恢复原稿为新人工版本。测试使用合成赛事与人物；证据保存在未跟踪的 `.local/product-release-20261011/`，不记录凭据或生成正文。脚本可沿原检查点恢复，不重复成功生成；两次恢复复核通过。后续 UI 合法更换封面曾使旧检查点的文件编号断言失效，失败证据保留；脚本修正为按当前版本重新办理测试封面后通过。

隔离环境缺少第二组织赛事，实际跨组织 HTTP 检查仍未观察，仅有单测拒绝证据；图片供应商未配置，未宣称真实 AI 生图成功。隔离候选开放不代表主环境开放或最终业务验收；普通角色桌面/手机完整操作、真实收退款、短信与现场赛事另行验收。

## 材料识别到人工确认建赛（2026-10-11 本轮追加）

`SportsEventRunAiTaskService` 使用原私有任务与文件渠道。上传及粘贴的任务/源文件在独立短事务中先提交，随后模型才能通过受控回调读取；回调固定使用当前实例 `server.port` 的 loopback 地址，不允许客户端选择地址。确认创建赛事、项目、收费政策和任务回执仍在同一业务事务内，不拆成多个页面 CRUD 写入。

候选草稿保留联系人、联系方式、退改原文、独立参赛声明，以及每个项目的人数、名额、拟议价格和报价依据。费用提议由 `AiFeeProposalPlan` 核验：缺价不是免费，明确零元才是免费；按人报价、额外费用、冲突价格或不明计价单位保留补问，不擅自换算。有效每单报价在普通主办方确认具体版本后通过 `FeeApi` 初始化政策。`CompetitionTypeApi` 将支持的人数/比赛形式绑定到项目，未开放组合拒绝创建。上述操作不登记真实到账、退款或支付凭证。

原文声明只有在来源确实存在时保留，模型不得新增条款。主办方在确认卡明确决定是否要求逐人确认；文本、开关、名单项目和价格绑定草稿版本，过期版本或静默改价被拒绝。`CREATED` 任务重复确认返回原赛事，不创建第二场。接口详见 [赛事资料建赛接口](../../../../docs/02-modeling/赛事资料建赛接口.md)。

本轮真实隔离验证使用合成规程，未改主站业务事实：原 Word、文本 PDF、无文本层扫描 PDF 和 PNG 经真实 DeepSeek 识别，费用/声明刷新 76 项检查通过；Word 普通主办方确认 15 项、人工补齐收款说明后发布 9 项通过。其他三个原任务各完成普通主办方页面确认 17 项检查，全部保持未发布草稿。原 Word 标准链的检查点及独立输入保持字节不变。扫描和图片的页面来源展示是视觉识别引文，不称为 PDF 文本层提取。

发布告知全文换行的真实桌面/手机只读检查 10 项通过。原冲突任务仍未确认，草稿可读区在桌面及两种手机高度下真实只读检查 15 项通过，内部滚动、收起恢复对话、无写请求。API 会在 GET 时刷新 `readiness.checkedAt`；不将这个派生时间误判为草稿事实变化。首次小屏窗口溢出、视觉任务脚本错误期待文本层、关闭按钮定位及比较派生时间的失败均保留独立证据，没有覆盖失败历史。

证据目录为未跟踪的 `.local/business-regression-20261011/`。Java/Gateway 本轮来源为 root 统一 r4 构建；有关 Java 单测和 Gateway 53 项通过是对应代码边界，不能代替真实业务检查。本节不代表通用 Agent 写渠道开放、图片供应商生图、真实收退款、短信或现场全流程已经完成。
